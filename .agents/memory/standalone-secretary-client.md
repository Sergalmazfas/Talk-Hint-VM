name: Standalone Secretary client boundary
description: Owner's scope for the separate Expo client and prohibition on migrating the laboratory.
---

The owner rejected restructuring/migrating the existing TalkHint project for the
mobile client. A separate runnable Expo project inside the workspace is acceptable.
The existing Swift app, administrator interface and labs remain the owner's
independent laboratory. Do not make their migration a dependency of client work.

**Why:** The owner explicitly clarified that “перенести” means reproduce the
existing Secretary workflow in a new design, not move the server or old app.

**How to apply:** Reuse the same accounts, existing cards, phone-profile meanings,
tasks and results through compatible backend APIs. The first separate client is
Secretary-only, with the selected direct OpenAI chain, no telephone session on
the device and no clone/provider selectors. Provided iOS screenshots are the
visual reference, not permission to add the other laboratory tabs. Test actions
must remain distinct from real calls until separately authorized.

The owner subsequently authorized a permanent connection to the published
backend and real outgoing Secretary calls after explicit in-app confirmation,
not TEST-only production access.

**Why:** Existing ChatGPT Secretary calling is already in active use; the mobile
client should reuse that engine rather than restart the product validation.

**How to apply:** Preserve explicit exact-assignment approval and no-redial
recovery. Keep old TEST requests test-only. Do not make calls as the agent or
change provider/recording/number settings just to verify the integration.

The owner approved preparing the already-built client for a **separate Replit
mobile project**, without migrating the existing project.

**Why:** The existing web project's Deploy does not produce a native install or
provide the mobile Apple/Expo signing flow.

**How to apply:** Keep the backend/laboratory intact. Treat a downloadable client
export as preparation for import, never as proof that a separate project was
created or a native build succeeded.
