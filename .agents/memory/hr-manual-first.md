Нина Кадрова — P.ORG, существующий ID не менять; подчиняется владельцу,
статус «описана, не подключена». Сначала отработать процесс вручную,
подключение агентом — потом, не в рамках описания анкеты.

**Why:** прямое решение владельца: сначала процесс, потом автоматизация.

**How to apply:** анкету брать из предоставленного владельцем JSON v2;
не восстанавливать недостающие поля по догадке. Книжки знаний Замира,
Фомы, Кати и Тихона заполнять только подтверждёнными фактами с датой
и источником. Действующие промпты разложить на личность / знания / задачи
без изменения смысла, показать diff; это не разрешение переключать
рабочих агентов. Отложенные предложения R1–R5 прохода rev904 оформить
как proposed, не включать. Записи — через production MCP; один ZIP
анкет, знаний, слоёв и предложений в конце на сверку Claude.

Будущая память сотрудников — три вида: существующая книжка знаний, журнал
работы и заметки опыта. Для опыта: агент предлагает → проверяющий отдела →
еженедельно через Нину в книжку, с сохранением действующего принятия уроков.
Память не меняет характер и не отменяет жёсткие правила. У секретарей —
без чужих личных данных из звонков.

**Why:** решение владельца о будущих этапах, не разрешение реализации.

**How to apply:** сначала карточки целиком, дальше поиск по меткам; RAG позже
для меню компаний, журнала звонков и материалов конкурентов. Искать только
в принятых материалах. Не выдавать план за включённую память, индекс или расписание.

## Обновление вместе с методом

Правило владельца для AI Crew: «поменялся метод или инструмент — обязанности
и книжки затронутых сотрудников обновляются в тот же день».

**Why:** владелец связал полигон Hint с цепочкой Замир → Фома → Паша →
Мария → владелец и потребовал не оставлять знания и обязанности позади метода.

**How to apply:** при изменении метода отметить затронутые роли, обновить
описательные обязанности и предложить уроки со ссылкой на факт/версию.
Предложенный урок не считать принятым; личность, рабочие промпты и продукт
не менять этим правилом. Если MCP умеет только создавать связанные дополнения,
прямо отличать их от изменения исходной книжки или канонического документа правил.
