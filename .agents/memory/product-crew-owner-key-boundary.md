description: Owner-approved header authentication fallback, permissions and release boundary.

Владелец одобрил резервный вход в production Product Crew MCP по ключу в заголовке, не замену OAuth.

**Why:** после успешного consent redirect Replit не запросил обмен кода; причина callback не установлена, повторные попытки владельца не дали рабочего подключения.

**How to apply:** оба входа обязаны использовать одну проверку владельца, service/repository и блокировку записи production new-country. Ключ не даёт приёмку за владельца или внешние действия. Не обходить недоступное MCP прямой записью в модель.

Ключ создаёт только владелец в своей браузерной сессии, видит один раз и сам вставляет в custom header Replit. Агент никогда не получает реальный ключ; тесты — только с изолированными фикстурами.

**Why:** решение владельца: 90 дней, hash-only, одна активная версия, ручной отзыв, last-used; безопасность требует отдельной сверки Claude до Publish.

**How to apply:** ротация отзывает предыдущий ключ, но не OAuth. Не объявлять живое подключение работающим по одному зелёному тесту или сборке: после Publish нужны ready-интеграция и фактическое read-only чтение.
