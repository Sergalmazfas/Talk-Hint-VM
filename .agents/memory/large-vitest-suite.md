---
name: Large Vitest suite verification
description: Complete the normal test gate within shell time limits using sequential shards, without hiding skips or changing tested source.
---

Если монолитный Vitest не укладывается в лимит команды, полный штатный набор
проверять четырьмя последовательными шардами с одним worker; при необходимости — шестью.

**Why:** монолитный прогон повторно превышал лимит, а последовательные шарды
завершились без отключения проверок и без изменения исходников.

**How to apply:** `npx vitest run --shard=i/4 --maxWorkers=1`.
Сохранить снимок кода и JSON-отчёты, сверить объединение файлов с
`vitest list --filesOnly`, исключить повторный учёт и пропуски.
Указывать файлы, всего тестов, passed, failed и штатные skip отдельно.
Нулевой exit code не превращает opt-in интеграционные skip в пройденные тесты.
Правка исходников требует новой проверки затронутого объёма; нельзя смешивать
результаты несовместимых снимков и объявлять их одним полным прогоном.

Лимит времени ShellExec относится ко всему shell-циклу, а не к каждому шарду.
Даже зелёные отдельные шарды могут суммарно превысить 300 секунд.

**Why:** последовательный цикл завершился по общему тайм-ауту после двух
зелёных частей, хотя каждая укладывалась в свой лимит.

**How to apply:** длинный цикл запускать background-задачей либо отдельными
вызовами по шарду; после тайм-аута без правки исходников достаточно закончить
непроверенные части. Не перезапускать уже зелёные части того же снимка.
