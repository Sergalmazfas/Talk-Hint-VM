## Evidence and strategic review

Navigation is not a causal dependency. A changed competitor fact may require a
related conclusion to be reviewed, but must never automatically replace the
mission, differentiation, budget, people or plan. Public claims, private
observations, external estimates and accepted decisions stay distinct.

**Why:** The owner explicitly wants to understand why a decision follows from
data, while retaining control of strategic choices; a competitor's new feature
is not itself an instruction to copy it or start an action.

**How to apply:** Propagate review only through explained dependencies, preserve
the old meaning and review rationale, and keep quarterly data and map methods
historical. Deterministic recalculation is not an accepted strategy decision.
Do not label a map as recalculated unless a fresh calculation actually exists;
archive captures must stay frozen while a newer calculation is shown as current.

## CrewAI checkpoint boundary

Never silently create a new research run when a requested checkpoint is missing.
Keep facts, history and authoritative checkpoints in the existing owner-scoped
TalkHint model; do not adopt CrewAI's default SQLite as a competing card store.

**Why:** CrewAI Flows documentation permits a missing restore ID to fall back to
new state. That could repeat paid collection or writes while appearing to resume.

**How to apply:** A future worker must verify owner, hypothesis, run identity,
approved inputs and persisted version before continuation; reject unknown IDs
and use atomic revision checks and stable operation identities for writes.

## History-format rollback boundary

Do not downgrade to a binary that assumes inline history while archived heads
remain in current owner rows. Preserve both current model and archive together
in backups; never delete archive blocks to make a rollback pass.

**Why:** Historical compatibility was deliberately kept at the repository
boundary, so older direct-SQL consumers cannot distinguish a retained history
tail from the complete array. A blind code downgrade can silently lose history
on its next write even though the archive itself still exists.

**How to apply:** Before an explicitly approved legacy-code rollback, stop
writers, materialize and verify the full current model under each owner lock
without changing CAS revision, and retain its archive. This is not permission
to alter production. Operational details are in `docs/project-model-history.md`.
