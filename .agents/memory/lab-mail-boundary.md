---
name: Gmail лаборатории
description: Границы подключения Gmail для отчётов владельцу и отличия от будущей почты внутри продукта.
---

Подключение Gmail через workspace OAuth выбрано для отправки лабораторных
отчётов владельцу самому себе вместо регистрации SendGrid. Это не внедрение
почтового чата TalkHint и не выдача клиентам доступа к почте владельца.

**Why:** владелец попросил минимальную авторизацию существующего аккаунта для
получения собственных отчётов. Такое подключение принадлежит проекту, а не
каждому пользователю приложения; широкие OAuth scopes не расширяют поручение.

**How to apply:** не считать этот ресурс готовой пользовательской email-функцией
в книге продукта. Новая работа с почтой клиентов требует отдельного решения и
их собственных разрешений. Не открывать mail transport через публичный Product Crew.

Владелец подтвердил получение тестового self-mail через это подключение.

При проверенном self-send через Gmail/Replit SDK предложенный RFC Message-ID
был заменён; поиск по исходному идентификатору не находил уже доставленное письмо.

**Why:** после успешной отправки это давало ложную неопределённость outbox.
**How to apply:** подтверждать известный provider ID через metadata и SENT,
проверяя получателя. Если ответ с provider ID потерян, не считать пустой поиск
доказательством неотправки и не разрешать слепой повтор.

Успешный Gmail-профиль и self-mail из Dev не подтверждают готовность того же
транспорта в опубликованном процессе.

**Why:** перед первым контрольным звонком production оказался без записи
управления лабораторией, хотя подключение Gmail в Dev читалось успешно.
Точная причина отказа production тогда оставалась неизвестной.

**How to apply:** до приглашения владельца на звонок проверить инициализацию,
настройки окружения, выключатель и свежий статус контроля именно в production.
Наличие OAuth, таблиц и успешной сборки не заменяет эту проверку.
