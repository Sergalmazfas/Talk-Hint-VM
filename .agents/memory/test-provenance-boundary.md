---
name: Test provenance I/O boundary
description: Keep DB-error unit tests independent of real source-tree and Git work
---

В unit-тесте учёта ошибок записи в БД источник версии звонка должен быть
контролируемой фикстурой; настоящий расчёт версии проверяется отдельно.
Unit-тест самой семантики stamp также контролирует и Git, и файловую систему,
включая обход дерева, а не только дочерний процесс Git.

**Why:** первый фиктивный createCall вызывал синхронный обход исходников и Git.
Полный шард получил тайм-аут в проверке ошибки БД, хотя отдельный прогон проходил.
Это ненужная внешняя зависимость теста, а не повод увеличить тайм-аут или убрать
проверки записи.
Позже один только замоканный Git не устранил зависимость от размера дерева:
обход файлов в тесте stamp тоже превысил его тайм-аут.

**How to apply:** отделять проверяемую семантику от файловой системы, Git и
сети. Сохранять самостоятельные проверки настоящего stamp/provenance; сбой
таймера без измерений не объявлять доказанным сбоем конкретной команды Git.

В герметичном routing-тесте отдельно контролировать лениво импортируемые
смежные runtime-зависимости, даже когда основной объект БД уже подменён.

**Why:** первый исходящий запрос в проверке владения cold-import'ил runtime
планов и клиентские singleton-зависимости уже внутри HTTP-таймера. Поэтому
тайм-аут воспроизводился и отдельно, а не только при загрузке полного шарда.

**How to apply:** если тест проверяет маршрутизацию, дать ему управляемую
фикстуру привязки плана; настоящую привязку проверять собственными тестами.
Не увеличивать тайм-аут и не считать мок БД полной изоляцией от смежного I/O.
