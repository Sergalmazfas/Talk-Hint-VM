# Общая модель: рост и неизменяемая история

## Причина и граница исправления

Прежний guard считал весь JSON: актуальные данные, все старые ревизии,
before/after аудита и накопленные квитанции crew. Повторные правки увеличивали
историю и могли остановить небольшую новую запись на 5M символов. Это ограничение
payload, не измеренная нехватка CPU/RAM. Покупка мощностей его не устраняет.

Теперь guard считает рабочее состояние: последние версии записей и паспортов,
актуальные документы, связи и остальные действующие данные. Аудит исключён,
исторические массивы учитываются последней записью. Граница отдельной гипотезы
остаётся 5M символов, общего конверта с альтернативами — 8M. Действительно
переполненный рабочий набор по-прежнему получает явный 413 с объяснением;
архивирование истории не обещает бесконечное количество действующих документов
или отсутствие ограничений PostgreSQL.

## Один источник данных

`talkhint_project_models` остаётся единственной актуальной owner-записью общей
модели. `talkhint_project_model_history` — её архив, не второй каталог карточек,
заданий или ролей. Ключ включает владельца:

- `h:<sha256>`: неизменяемый блок истории с ссылками на предыдущий блок и
  вложенные исторические блоки. Повторное сохранение не переписывает старый блок.
- `r:<revision>`: неизменяемый снимок опубликованной в owner-модели транзакции.

В актуальном JSON для исторических массивов остаётся хвост и внутренний
`__modelHistoryV1` с головой цепочки и количеством записей. Полные старые
organization/strategy/competitor/analyst revisions, аудит и квитанции операций
восстанавливаются без изменения публичной схемы. Порядок, версии, даты, источники,
before/after и неизвестные старые поля сохраняются. Хеши канонические:
перестановка ключей PostgreSQL JSONB не считается повреждением.

Чтение старого inline-формата не требует миграции. При первой успешной записи
сохраняется исходная owner-ревизия вместе со всей её прежней историей. Более
ранние целые owner-снимки, которых раньше не было, не синтезируются. Их
исходные предметные ревизии и аудит остаются доступны.

## Атомарность и чтение

В одной транзакции: owner `FOR UPDATE` → проверка общей CAS revision →
восстановление истории → все команды → архив исходной/новой ревизии →
обновление актуального JSON → commit. Сбой на любом шаге откатывает и архив,
и документы, и статусы. Альтернативы разделяют CAS владельца, но не данные.
Архив читается только с условием owner; отсутствующий блок, неверный hash или
неполная цепочка дают 503 и запрещают запись неполной модели.

`GET /api/admin/project-model?hypothesis=new-country&revision=N` возвращает
read-only снимок с `X-Model-Snapshot: read-only` и `Cache-Control: no-store`.
Сохраняются admin gate, owner из сессии, Dev-only граница альтернатив. POST с
параметром revision запрещён. Неизвестная ревизия — 404, не новая модель.
Изменения со старым CAS-токеном не затирают актуальную модель.

Существующие представления истории получают те же полные массивы; старые
ревизии не превращаются в пустые заглушки. Обычное чтение пока восстанавливает
полную историю для совместимости. Поэтому стоимость полного чтения/клонирования
растёт с архивом. Ограниченное чтение с постраничной историей и отдельным поиском
квитанций — самостоятельная оптимизация, не повод удалять историю.

Crew сохраняет прежние requestId/fingerprint и распознаёт повтор даже после
архивирования. Изменённое содержимое под прежним requestId — 409. Искусственный
лимит 100 переходов/версий паспорта снят; реальные проверки входов, полномочий,
состояний и текущего размера остаются.

## Откат и эксплуатация

- Транзакционный rollback проверен с ошибкой **после** записи архивных блоков:
  ни checkpoint, ни частичное изменение не остаются.
- Чтение прежней ревизии не восстанавливает её поверх текущей и не выдаёт
  разрешение на запуск worker.
- **Нельзя просто вернуть старый бинарник**, не понимающий архив: он увидит
  только хвосты массивов. Перед согласованным откатом кода остановить писателей,
  под owner-lock восстановить полный текущий JSON через `unpackModel`, записать
  его с прежней revision и проверить полное повторное чтение; архив не удалять.
  Этот inline round-trip проверен в изолированной Dev-схеме с сохранением
  архива и CAS. Старый size guard после отката снова имеет прежнее ограничение.
- Backup/restore должен включать обе таблицы из одного согласованного снимка.
  Нельзя отдельно очищать архив или переносить только актуальные owner-строки.
- Новая таблица объявлена и в Drizzle-схеме для сохранности при будущих миграциях.
  Эта работа не запускает Publish, production migration или смену ресурсов.

## Проверки

```sh
npm run check
npx vitest run server/projectModel server/productCrew server/__tests__/publishSchemaSafety.test.ts
RUN_MODEL_HISTORY_DB_TESTS=1 npx vitest run server/projectModel/history.integration.test.ts
```

Последняя команда требует внутреннюю Dev-базу (`helium`/`lithium`), создаёт
случайную отдельную схему и удаляет только её. Не импортирует bootstrap приложения
и не вызывает внешние API. Проверяет legacy-историю >5M, CAS-конкуренцию между
гипотезами, изоляцию владельцев, новые экземпляры repository, исторические снимки,
rollback после архивирования, повреждение блоков, 105 правок паспорта и повтор
самой первой операции, intake → работа → отчёт → приёмка.
