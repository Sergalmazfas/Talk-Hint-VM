### Сначала — разрешённый браузерный вход на Mac

1. Проверить чистоту worktree и правильный репозиторий, как описано ниже.
   Проверить `gh --version` и доступность `gh auth git-credential --help`.

   Не запускать `gh auth setup-git`, `git config --global` или `git config --system`.

   для push будет разовый helper только в одной Git-команде.
3. Запустить **интерактивный браузерный OAuth-вход**:

```bash
gh auth login --hostname github.com --git-protocol https --web
```

   Владелец сам открывает GitHub, выбирает свой аккаунт и подтверждает GitHub CLI.
   Если нужен device code — показать его только владельцу на Mac; не включать
   его в отчёт/логи/ZIP и не пересылать Replit. Страница:
   https://github.com/login/device .
   Не писать stdout авторизации в tee/файл, не вводить пароль/2FA за владельца.
4. Использовать системное защищённое хранилище macOS. Запрещены `--insecure-storage`,
   `--with-token`, `gh auth token`, `--show-token` и чтение credential-файлов.
   Если gh сообщает о plaintext/fallback-хранении — остановиться и доложить
   без чтения/печати токена, не продолжать push.
5. Проверить авторизацию без показа токена:

```bash
gh auth status --hostname github.com
gh api user --jq .login
gh api repos/Sergalmazfas/Talk-Hint-VM --jq .permissions.push
```

   В отчёт — только аккаунт и результат проверки права push, не полный auth-вывод.
   Неверный аккаунт/нет прав — остановиться; не делать logout/switch/refresh
   автоматически. Дополнительные OAuth scopes, в том числе workflow, отдельно
   не запрашивать без решения владельца.
6. Глобальные настройки Git должны остаться прежними. Дальше разрешён только
   повтор согласованной передачи исходного commit через разовый helper ниже.
   Никакой сборки, изменения кода, очистки диска или платных вызовов.

Это разрешение относится к GitHub CLI на Mac владельца, не к входу в приложение,
Apple Account, Keychain приложения TalkHint, Replit или каким-либо провайдерам голоса.
