# Единая iOS-дельта поверх принятого аудита 9c3341b

Владелец принял независимый аудит Claude Mac: 92/92 XCTest на прежней базе.
Настоящий отчёт относится к следующей дельте в постоянной ветке
`xcode-chat-voice-sarah-2026-11-11`, не к установленному бинарнику.

## Что изменено

1. Hint: индивидуальное декодирование планов; испорченный план не теряет
   остальные. Preflight ограничен 1 с, не бросает ошибку в обработчик неудачного
   звонка. При сетевой ошибке/пустом ответе — нейтральная первая фраза.
   Явная PREP-цель не заменяется профессией или чужим pending-планом.
   Обязательная авторизация/получение Twilio access token всё ещё могут честно
   остановить звонок: они не являются необязательным preflight.
2. HintGoal/Opening/Translation: UTF-8 пределы 160/100/80 байт и общий
   URL-encoded предел 800 байт с To и именами ключей. Для сохранённого плана
   только id/hash, полный текст остаётся на сервере. Удалён неиспользуемый
   `incall.opening.hide` во всех пяти языках.
3. Серверная защита: в `server/websocket.ts`, callback UtteranceGate,
   `speaker !== "GST" || !isOpeningGreeting(text)` вызывает
   `savedPlanOpening.invalidate()`. То есть речь владельца отменяет отложенную
   первую фразу, Guest greeting — нет. SavedPlanOpening проверяет инвалидность
   после async-операций. Проверено чтением кода и opening.test.ts; это защита
   от ПОЗДНЕЙ отправки, а не заявление об удалении уже сказанного текста.
   Новый серверный код для этого не понадобился.
4. Копирование: необязательный presentation, неизвестные kind пропускаются.
   Выделяемый UITextView, Markdown bold/italic/code вместо сырых маркеров,
   кнопка целого ответа и отдельные адрес/телефон/email/reference/code.
   Тап по обнаруженной ссылке копирует видимый текст, не звонит/не открывает Maps.
5. Озвучка: отдельный ChatReadAloudPlayer без микрофона. Manifest/UTF-16,
   последовательные платные сегменты только после Play, один playbackId;
   строгий POST без text/provider. PCM 24kHz mono заворачивается в WAV,
   JSON/redirect/нечётные данные не проигрываются. Stop/поздние ответы,
   уход со страницы/смена разговора/аккаунта, прерывание/фон защищены.
   ChatAudioOwnership определяет phone/Agata/readAloud; звонок/Агата
   прерывают плеер, чтение не начинает захват звука.
6. Табличник: XLSX/CSV в Files; свой предел из tables.limits.bytes до 10 МиБ
   в picker и API. PDF/PNG/TXT остаются до 2 МиБ. JSON без slash-escaping —
   даже худший base64 помещается в уже существующий серверный parser 14 МиБ.
   В меню чата «Таблицы»: список, поиск, ещё страница, async XLSX export,
   скачивание с Bearer только с того же origin, без redirect, системный Share.
   Стабильный requestId для повторного запроса экспорта; незавершённый job
   не объявляется готовым файлом. Пользователь сам выбирает Save to Files в Share.
   Подтверждения строк/автозапись документов груза НЕ добавлены.

- Новых изменений серверной схемы в этой дельте нет: SQL diff = пусто.
  Новые серверные endpoint/миграции/startup DDL не добавлялись.
  Сервер публикуется из основной Dev-ветки, НЕ из старой серверной базы
  native-ветки. Ожидаемая серверная Hint-дельта — 45d8b0f1 или потомок.

  Только затем одна итоговая обычная сборка TalkHint поверх приложения,
  без удаления данных, с прежним iOS 15.
- Риски: новый UITextView/layout; реальный iOS PCM/Bluetooth/аудиопрерывания;
  большие экспорты и время обработки job. Mock/static тест не доказывает звук.
  Плеер ожидает целый сегмент до 600 символов, не потоковый первый звук.
- Откат: отмена только коммита этой native-дельты поверх 9c3341b,
  без reset/удаления данных, без переключения Katya/Hint моделей/провайдеров.
  Серверный read-aloud отдельно можно отключить штатным флагом владельцем;
  эта работа флаг не меняет.
