Secretary: комплект для переноса на Mac и проверки через Xcode

24 октября 2026 · только Dev. Изменены существующий сервер и существующее UIKit-приложение TalkHint. Новый мобильный проект не создавался.

Код подготовлен, но реальные телефонные звонки и звук iPhone здесь не проверялись. В среде нет Xcode, Swift и XcodeGen. Публикации, GitHub push, изменения входящей маршрутизации и реальные внешние действия не выполнялись.

Основная связка и альтернативы

  • Retell + TalkHint Engine: Merritt, gpt-6.1-sol, reasoning medium, Custom LLM. Ориентир — успешный личный браузерный тест владельца с Катей v2. Личность выбирается из общего каталога; новой автоматической привязки Кати к номерам не создавалось.
  • OpenAI / GPT-Live 1 остаётся выбираемым старым вариантом: Marin, рассуждение через gpt-6.1-sol. Настройки личности, карточек и исходящего номера Retell не выдаются за применённые к этому альтернативному маршруту.
  • ElevenLabs и Cartesia не показаны как рабочие телефонные варианты Secretary: их браузерные возможности не означают готовой телефонии. Исторические данные не удалены.

Что изменено

  • Swift: проверка сохранённых настроек своего номера перед подтверждением; явные сведения об окружении, связке, личности/версии, голосе и модели. Переход в настройку, выбор каталога, сохранение и повторное чтение. Устаревшая/чужая/нечитаемая настройка блокирует новый Retell-звонок, а не заменяется другой линией.
  • Идентичность незавершённого запроса сохраняется до POST и изолирована владельцем и backend-origin. Восстановление задачи не создаёт новый вызов. Старые неподписанные областью черновики не приписываются новому аккаунту.
  • Катя представляется виртуальным секретарём с подтверждённым сервером именем владельца. Если подтверждённого имени нет, используется нейтральное представление без заимствований из поручения или карточек. Предусмотрены RU/EN/ES; запреты и полномочия выше характера.
  • Телефонный Engine не получает браузерные TEST-инструменты, вымышленные свободные слоты или TEST-бизнес — в том числе в диагностическом контексте отчёта. Используются подтверждённое поручение и только разрешённые выбранные карточки.
  • Завершение Retell: разрешён только инструмент подготовки окончания текущего звонка. После подтверждения итога собеседником Engine формирует прощание; только завершённый актуальный ответ получает end_call. Retell завершает после произнесения и отбрасывает сигнал при перебивании. Иное/незаконченное прощание, отменённый ответ и браузерная TEST-сессия не получают этот сигнал. Это нативный механизм Retell, не отдельный таймер воспроизведения GPT.
  • End: повтор для уже завершённой задачи не создаёт действий провайдера. При ошибке Twilio проверяется состояние того же SID; ошибка или 404 без доказательства не считаются завершением. Неопределённую задачу с известным собственным SID можно явно остановить, но не повторно набрать автоматически.
  • Ошибка остановки браузерного Retell HTTP 404 теперь проверяется чтением того же call ID. Только подтверждённое конечное состояние закрывает сессию; неизвестность остаётся видимой и повтор остановки доступен. Точную причину исторического 404 один JSON не устанавливает.
  • Мониторинг: Twilio both_tracks на PSTN-ноге → guest/secretary → авторизованный feed владельца → два независимых Swift playback-узла. Новые метаданные различают подключение источника, получение обоих треков и локальное воспроизведение. Устаревший источник не дублирует звук нового.
  • Переподписка на read-only feed не восстанавливает потерянный Twilio-источник. Экран может обновлять транскрипцию/статус даже без аудиоисточника, повторно открываться и обнаруживать позже подключившийся источник. End остаётся доступным. Наличие пакетов не выдаётся за доказанную слышимость.
  • Проверено включение ранее исправленного падения: карточка добавляется в общий родитель до активации межвидового ограничения ширины. Нативные регрессионные тесты и обязательный список XCTest включают live/recovered transcript rendering.

Перенос на Mac без отправки в GitHub

  1. В Replit откройте Files → меню с тремя точками над деревом файлов → Download as zip. Это ручной экспорт текущих файлов; агент ничего в GitHub не отправляет. Официальная инструкция.
  2. Распакуйте архив в новую папку на Mac. Для Xcode используйте всю актуальную папку ios, а не несколько отдельных Swift-файлов. В ней вместе нужны UI, Networking, SessionStore, пять локализаций, Tests, scripts и project.yml. Не смешивайте старый native-код с новым сервером. Серверные изменения уже находятся в этом Dev-проекте; переносить сервер на Mac и запускать второй сервер не нужно.
  3. Не переносите серверные ключи в приложение. Не добавляйте .env, токены Retell/OpenAI/Twilio и секреты в Xcode, plist, Swift или архив приложения. Run-переменная ниже — только несекретный HTTPS-адрес.
  4. Используются существующий проект ios/TalkHint.xcodeproj, генерируемый из ios/project.yml, и схема TalkHint / Debug. Сначала выполните:
cd /путь/к/распакованному/проекту/ios
xcodegen generate
open TalkHint.xcodeproj

В Xcode выберите свою команду Signing и подключённый iPhone, разрешите разрешение Swift Package Twilio. В Edit Scheme → Run → Arguments → Environment Variables задайте:

TALKHINT_API_BASE_URL=https://e62acc35-f5e5-43be-91ea-c3ad7b36be85-00-3l7jbsd7n4zci.janeway.replit.dev

Нужна именно Run-переменная схемы Debug. Оставьте Dev-сервер работающим. На экране подтверждения проверьте этот адрес и пометку окружения: Debug сам по себе не доказывает подключение к Dev. Войдите своей учётной записью в Dev; настройки и назначение номера production не копируются автоматически.

Обязательный Mac-gate до звонка

Выполните существующий скрипт из корня репозитория с установленным Xcode 16.4 (или укажите фактический путь к согласованному Xcode):

DEVELOPER_DIR=/Applications/Xcode_16.4.app/Contents/Developer \
  bash ios/scripts/validate-native.sh

Изолированная схема TalkHintValidation использует .invalid backend и фикстуры. Скрипт должен не только собрать приложение, но и выполнить требуемые XCTest: личности/настройки, live/recovered-карточки, аудиомаршрутизация и настоящее Keychain write/read/delete в тестовом scope. Логи и .xcresult сохраняются в generated-artifacts. Не считать build-only подтверждением исправленного падения. Ошибку Keychain entitlement не скрывать fallback-хранилищем.

Порядок первой проверки владельцем

  1. Запустить Debug на iPhone. Проверить Dev, вход, отсутствие старого неопределённого запроса из другой области аккаунта/сервера.
  2. Settings → Secretary: Retell + Engine → Personality & outgoing line. Выбрать свой исходящий номер и Катю v2, только явно разрешённые карточки, сохранить. Повторно открыть и сверить.
  3. Создать новое поручение текстом или диктовкой. Старое согласованное поручение не переоснащается новой личностью. Перед Start сверить номер собеседника, задачу, собственную линию, Катю v2, Merritt, gpt-6.1-sol, medium и Dev. На этом этапе ещё нет нового телефонного набора.
  4. Только владелец нажимает Start для заранее согласованного получателя. Проверить один входящий вызов у собеседника, приветствие виртуального секретаря с правильным владельцем и живую транскрипцию. Владелец слушает, его микрофон в разговор не отправляется.
  5. Критический критерий: услышать и собеседника, и Катю в наушниках, затем на динамике; сравнить с индикаторами прихода обоих треков. Если транскрипция идёт, а одного голоса нет — тест мониторинга не пройден, даже если собеседник доволен разговором.
  6. Проверить RU → EN → ES, имена/номера/адреса, паузы, уточнения, мягкий юмор и отказ от запрещённого действия. Перебить в начале/середине/конце ответа. Не требовать реальной отправки, записи в календарь или уведомления: эти действия не подключены.
  7. В отдельных новых поручениях проверить прощание после подтверждённого итога, отмену прощания новой репликой, End и завершение собеседником. Отдельный прогон — предел 5 минут. Не завершать за музыку ожидания, перевод или простую паузу.
  8. Во время согласованного разговора закрыть/открыть монитор, кратко потерять сеть. Проверить обновление transcript/status, корректную остановку локального playback и отсутствие нового набора. При потере Twilio-источника экран не должен обещать его создать заново. End остаётся доступен.
  9. После завершения открыть историю и ту же задачу повторно: итог и transcript доступны, повторного набора нет. Перезапуск Dev проверять отдельно: восстановление потерянного Custom LLM/Twilio-источника не гарантируется; автоматический новый звонок запрещён.

Выполненные проверки и остающиеся ограничения

591 автоматическая проверка прошла; 9 проверок выбранного набора пропущены их существующими условиями. TypeScript и git diff --check прошли. 36 Python-проверок инструментов native validation прошли. Пять локализаций имеют одинаковый набор ключей.

Блокеры подтверждения полной готовности: реальная сборка и XCTest на Mac; настоящий вход и своя линия в Dev; проверка доступа/конфигурации отдельного телефонного агента при человеческом запуске; физическая слышимость обоих участников и завершение на iPhone. Серверные моки не заменяют эти проверки. Закрытые экраны веб-интерфейса не проверены визуально после входа.

Телефонный агент изолирован от браузерного. При первом явном запуске сервер проверяет доступ и ищет/создаёт отдельную конфигурацию; это не перенастраивает входящий номер и не меняет браузерный агент. Личный входящий Secretary не обещается. Записи/уведомления/календарь не активированы.

Источники протокола: Retell Custom LLM WebSocket / end_call, Stop Call. Полная инструкция сборки остаётся в ios/README.md.
