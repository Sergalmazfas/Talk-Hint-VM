# AI Crew · задача 2 · пилот Hint (код, НЕ запуск)

## Граница этапа

Первый механизм принят владельцем. Read-only production-проверка подтвердила
probe `claude-haiku-5-5` (165 входных / 8 выходных токенов), OFF/0, запусков 0.
Это не проверка генерации Sonnet/Opus и не разрешение их запускать.
Этот пакет не делает production-записей, не создаёт назначений, не меняет Катю,
промпты продукта, штатные анкеты, звонки, полномочия или доступы. Publish — владельцем
после независимой проверки Клавдия.

## Данные: минимальная структурная выдержка

`GET /api/admin/ai-crew/hint-pilot` — существующая owner-only граница.
Только production. Три SELECT в одной read-only repeatable-read транзакции,
statement timeout 8 секунд, параметры ownerId, без динамического SQL:

- `calls`: только свой user_id + явный labHintSource Hint/production; последние 12.
  Числовые показатели Hint latency/SLA/usage и счётчики stale/cooldown/duplicate.
  **Подсказки представлены измерениями событий, не текстом реплик.**
- `call_lab_jobs`: свои production, mode=hint, synthetic=false, последние 12;
  только известные QA-статусы и категории выводов (до 100 на отчёт).
- журнал проблем дежурного `call_lab_controls.watchdog`: свои production,
  только код ANALYSIS_UNAVAILABLE и количество. Это НЕ весь журнал проблем компании.

Повторная проекция разрешает только перечисленные enum и конечные числа
0…100000000; неизвестное — null/unknown. Не копируются транскрипты, имена,
телефоны, тексты подсказок, цели звонка, контакты, URL, SID, произвольные ошибки.
Отчёты/сессии получают локальные ref; SHA-256 связывает весь снимок.
Никакого «удаления имён регуляркой», ненадёжного для свободного текста.
Книжки знаний и непринятые материалы автоматически не подмешиваются.

Цена приватности: нельзя проверить семантику подсказок/точность STT по таким данным.
Агенты обязаны назвать этот пробел; число совпадений реплик не равно удовлетворённости.
Старый сигнал дежурного не доказывает текущую поломку. Задержки от STT final,
не от физического конца речи. Сырые записи остаются в своей базе неизменными.

## Описания, ставки, резерв

| Сотрудник | agentId | model_id | $/1M input | $/1M output |
|---|---|---|---:|---:|
| Паша | product-manager-specialist | claude-sonnet-5-5 | 2 | 10 |
| Фома | Hint-lg-qa-role | claude-opus-5-5 | 4 | 20 |

Источник: https://platform.claude.com/docs/en/about-claude/pricing#model-pricing
(проверено при подготовке 2026-11-01).
Обычный синхронный Messages API, не Agents, без caching/fast/batch и geo-множителя.
USD за миллион = целые microUSD за токен.
Владелец подтвердил ставки Sonnet/Opus и выбрал latency после проверки Клавдия.
Кнопка подготовки записывает ratesConfirmed=true только после подтверждения владельца.
Подготовка
проверяет оба ID свежим GET /v1/models, но не делает платных inference.
Никакого автоматического fallback на другую модель.

Максимум ответа **2000 токенов каждому**. Резерв каждого запроса:
`(UTF8_bytes(input + fixed system) + 4096) × input_rate + 2000 × output_rate`.
Input ограничен 48 KB для пилота (с выдержкой и предложением Паши).
Каждый резерв/расход — в общем UTC-бюджете и журнале своего агента.
Нельзя использовать старый резерв на 256 токенов. Ожидание ответа до 120 секунд,
OFF проверяется перед запросом и до сохранения, transport прерывается.
Неизвестный платный исход сохраняет резерв; автоматического повтора нет.
Если денег хватает только Паше — Фома остаётся в очереди, разбор не закрывается.
Целиком бюджет пары заранее не резервируется — это явно видимое ограничение.

### Оценка одного прогона

**Сценарий, не измеренный расход:** Паша 3000 input + 2000 output,
Фома 5000 input (включая предложение) + 2000 output:

- Паша: 3000×2/1M + 2000×10/1M = **$0.026**.
- Фома: 5000×4/1M + 2000×20/1M = **$0.060**.
- Вместе: **$0.086**, ориентир **$0.08–0.10** при таком размере входа.

При максимальном допустимом input 48 KB консервативный суммарный резерв выше:
`6 × (48000 + bytes(system) + 4096) + 60000 microUSD`, около **$0.38**.
Это технический резерв, не прогноз счёта. Факт — usage × зафиксированные ставки;
без реального пилота входные токены/стоимость не измерены. Налоги и договорные
скидки не учитываются. Владелец отдельно выбирает лимит; сейчас он 0.

## Порядок одной настоящей задачи

1. Владелец выбирает одного кандидата и подтверждает ставки.
2. `hint_pilot_prepare`: только при OFF/0, свежие SELECT + модели + CAS revision.
   Создаёт одну задачу и описания двух агентов, фиксирует снимок/hash/ставки.
   Не создаёт очередь, расписание или запуск. Второй незакрытый пилот запрещён.
3. Только после отдельного «да»: владелец задаёт положительный бюджет и общий
   флаг, затем `hint_pilot_start` (ownerApproved=true, CAS, автор задачи).
   Эти команды **не выполняются в текущем этапе**.
4. Паша → отдельный документ `proposed`; только после успешного результата
   автоматически ставится Фома. Тот получает тот же снимок/hash и предложение,
   помеченное как недоверенный материал, а не инструкцию.
5. Фома → отдельный `proposed` документ + `confirmed` / `not_confirmed`.
   Неверный/обрезанный JSON = not_confirmed, без платного повтора.
   Это заключение о разборе, НЕ приёмка продукта. Всё остаётся для владельца.
   После завершения цепочки в той же транзакции включается OFF (epoch+1),
   дневной лимит сохраняется, результат и фактическая цена по usage видны на панели.
6. Задача остаётся в analysis, держатель — владелец. Только owner-команда
   может передать на owner_decision. Она требует фактические два документа,
   два done-запуска, точные разные agentId и разные модели. Одних введённых
   вручную имён больше недостаточно. «Подтверждено» не закрывает задачу само.

Описания/ставки/модели фиксируются до закрытия пилота. Общие enqueue/schedule
для этой задачи запрещены: иначе можно было бы обойти последовательность.
При расхождении модели ответ оплачивается по учтённому usage, но не используется
для следующего шага. Продукт, промпты, звонки и публикации не доступны как tools.
После отрицательного исхода полного цикла новый эксперимент — отдельное
решение владельца; автоматического повторного пилота нет.

## Кандидаты из production (не выбор за владельца)

1. **Задержки выше SLA.** Сессия 2026-10-28: 15 подсказок, e2e p95 4063 ms,
   SLA 1000 ms, withinSla 0%; 2026-10-27 p95 5136 ms.
   Разбор: где измеренное время, какие причины только гипотезы, что измерить ещё.
2. **Низкая доля использования.** Те же реальные серии: 20% при 15 доставленных
   и 21% при 14. Лаборатория содержит QA-расхождения.
   Разбор достоверности usage и границ выводов, не смена подсказок.
3. **Незавершённые разборы.** Два исторических ANALYSIS_UNAVAILABLE в watchdog;
   две Hint-записи с «НЕ ПРОВЕРЕНО QA». Проверить, что известно о полноте,
   отделить письмо/готовый файл от завершённого анализа.

Рекомендация на первый пилот: **1 — задержки**. Числа есть, задача укладывается
в обезличенную выдержку, не требует раскрывать чужие реплики. Выбор — владельцу.
Наличие этих записей не означает, что проблема воспроизводится на последней версии.

## Не проверено в этом этапе

- Реальный платный Паша→Фома и качество выводов: сознательно не запускались.
- Готовность Sonnet/Opus к inference под production-ключом: GET catalog не заменяет запрос.
- Все проблемы компании, содержание личных звонков, смысл подсказок — не входят в выдержку.
- Внешняя независимость/качество Клавдия — не самоприёмка.
- Авторизованный экран в браузере не обходили; проверяются API и тесты.
- Выбран latency, ставки подтверждены владельцем. Положительный лимит и фактический
  запуск остаются отдельными действиями владельца; значение $1 — только default поля.
