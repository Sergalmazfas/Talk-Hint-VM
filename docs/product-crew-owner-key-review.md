## Сделано

- Второй способ аутентификации **того же** production MCP: `X-API-Key`. OAuth не удалён, его выдача, PKCE, scopes и отзыв не изменены.
- Защищённая страница `/admin/product-crew-key`, ссылка из `/admin`.
- Создание и отзыв доступны только браузерной сессии фиксированного владельца, который также входит в действующий admin allowlist. OAuth bearer и API key не могут выпускать ключи.
- Для изменения: точный Origin `https://talkhint.app`, запрет `Sec-Fetch-Site: cross-site`, CSRF привязан к сессии, 10-минутный одноразовый маркер подтверждения, явное `{confirm:true}`.
- Секрет: 32 случайных байта, `thpk_` + base64url. Срок 90 суток, без автоматического продления. Показывается только в ответе на выпуск.
- На сервере хранится **только SHA-256** ключа, фиксированный владелец и временные метаданные. В статусе нет ни секрета, ни hash.
- Одновременно активен один ключ. Выпуск нового и отзыв прежних сериализованы PostgreSQL advisory lock в одной транзакции. Ошибка вставки откатывает отзыв прежнего ключа.
- Дата последнего успешного использования обновляется после проверки hash и срока, до обработки MCP-метода. Это использование ключа, не успешное изменение модели.
- Отзыв блокирует следующие проверки доступа; уже прошедшая проверку операция может закончиться. Это не отмена ранее записанных данных.
- Используется существующая таблица `sessions` как хранилище credential markers, аналогично OAuth. Новых таблиц, колонок, миграций или настроек среды нет.
- Два пространства маркеров: `productcrew:ownerkey:<hash>` (создание/срок) и `productcrew:ownerkey-use:<hash>` (последнее использование). Выпуск/отзыв меняют только эти пространства для владельца. OAuth grants, обычные сессии и документы не затрагиваются.
- Истёкшие/отозванные маркеры могут убираться существующей очисткой expired sessions; новая политика хранения данных модели не вводится.
- Право ключа: тот же авторизованный владелец, тот же `ProductCrewService`, только активный production `new-country`. Текущий gate `writes_open`, CAS/revision, requestId, разрешённые инструменты и запрет `review_result` сохранены.
- Нет звонков, денег, Publish, удаления, серверных секретов, произвольного выполнения кода или приёмки за владельца. Знание ключа даёт разрешённые права модели: хранить его нужно как пароль.
- Если одновременно присланы bearer и `X-API-Key`, запрос отвергается, а не выбирает более сильный вход. Ключ не принимается в URL, cookie или JSON.
- Экран держит секрет только в памяти React, без localStorage/sessionStorage/URL/query cache/телеметрии. Копирование — только нажатием владельца. Скрытие/переход очищают экран; запоздавший ответ после pagehide не показывает ключ.
- Ожидание API ограничено 15 секундами, включая чтение JSON. Неоднозначный результат блокирует последующие действия до явного чтения статуса, не повторяет выпуск.

## На что Claude обратить внимание

1. Проверить границу cookie-сессии владельца и allowlist на каждом management-запросе.
2. Проверить одноразовый CSRF, Origin и конкурентные повторные POST.
3. Проверить, что hash-only storage не смешивается с login sessions и OAuth markers.
4. Проверить атомарную ротацию, срок, отзыв, обновление last-used и отказ при сбое PostgreSQL.
5. Проверить, что ключ не расширяет права production repository и не разрешает запись при `writes_open=false`.
6. Проверить отсутствие утечек в response/status/error/log/UI storage. Глобальный request logger пишет только метод, путь, статус и длительность, без headers/bodies/query.
7. Проверить, что UI не перевыпускает секрет при сбое/перезагрузке/возврате назад.
8. Не считать локальные тесты приёмкой безопасности или доказательством, что Replit сохранил custom-header соединение.

## Проверки и ограничения

Точные результаты и команды — в `verification.md` ZIP.

Тест PostgreSQL поднимает отдельный временный кластер на loopback, создаёт только фикстурную `sessions`, не читает DATABASE_URL и не подключается к базе приложения. Кластер останавливается после теста. В модели Dev и production изменений нет.

Браузерная проверка использует **реальный компонент** с изолированным API-фикстурой и Chromium. Это не проверка входа владельца, реального ключа, iPhone Safari/Chrome либо сохранённого подключения Replit.

Реальный production-ключ **не создан**. Секреты не запрашивались и не читались. Реальный MCP вызов с owner key до Publish и ручного подключения владельцем невозможен. Независимая сверка Claude ещё не получена.

## Действия владельца — только после одобрения Claude и Publish

1. [Открыть ключ MCP в TalkHint](https://talkhint.app/admin/product-crew-key). Войти под владельцем, нажать «Создать ключ», подтвердить предупреждение. До Publish новой страницы в production может не быть.
2. Скопировать показанный секрет. Не присылать его в чат и не добавлять в документы, URL, Git или screenshots. Держать страницу открытой до сохранения заголовка в Replit; при утрате секрета можно лишь заменить ключ, старый станет недействителен.
3. [Открыть готовую форму custom MCP в Replit](https://replit.com/integrations?mcp=eyJkaXNwbGF5TmFtZSI6IlRhbGtIaW50IFByb2R1Y3QgQ3JldyIsImJhc2VVcmwiOiJodHRwczovL3RhbGtoaW50LmFwcC9hcGkvcHJvZHVjdC1jcmV3L21jcCJ9). Это форма добавления, **не поиск по каталогу**.
   - Display name: `TalkHint Product Crew`.
   - MCP Server URL: `https://talkhint.app/api/product-crew/mcp`.
   - Advanced settings → custom header: имя `X-API-Key`, значение — секрет из пункта 1.
   - Нажать **Test & save**.
   - При исправном ключе OAuth для этой проверки не нужен. Если снова предлагается OAuth, остановиться: проверить URL/заголовок и прислать только статус/скриншот **без значения ключа**, не повторять consent вслепую.
4. На странице TalkHint нажать «Я сохранил, скрыть». Отзыв при необходимости — там же, «Отозвать ключ». Ротация означает, что значение заголовка в Replit тоже нужно заменить.
5. Написать Replit «Проверь MCP read-only». Агент проверяет наличие ready-подключения, `get_roadmap`/`get_team`, production/new-country и актуальную revision, **без записи и без получения секрета**.
