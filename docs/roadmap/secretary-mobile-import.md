# TalkHint Secretary — отдельный мобильный проект

Это готовый существующий Expo SDK 54 / React Native клиент, извлечённый из
TalkHint без переноса сервера. Это не архив всего проекта и не новый backend.
Новый Replit-проект ещё нужно создать импортом; наличие этого архива не означает,
что проект уже создан или что появилась встроенная панель мобильной сборки.

## 1. Создать отдельный проект Replit

1. Откройте https://replit.com/import и выберите ZIP.
2. Загрузите `talkhint-secretary-mobile.zip` (файлы уже находятся в корне архива).
3. Назовите новый проект, например `TalkHint Secretary Mobile`.
4. Передайте Agent нового проекта текст ниже. Он должен настроить именно
   мобильный Expo preview/build, а не ещё одну веб-страницу. Если импорт
   определился как веб-проект, это нужно исправлять в НОВОМ проекте.
   Старый TalkHint не нужно мигрировать.

> Это отдельный мобильный Expo / React Native проект iOS и Android. Здесь уже
> находится готовый клиент Secretary. Прочитай AGENTS.md и README.md. Настрой
> мобильный preview и доступный в этом новом проекте процесс нативной сборки
> Replit, используя существующий код. Установи зависимости из package-lock.json,
> скопируй .env.example в .env: там только публичный URL существующего Dev backend.
> Не переноси backend, не создавай новую базу или аккаунты, не переделывай дизайн.
> Не запускай платные EAS builds, публикацию, звонки, SMS/push или запись в
> календарь. Покажи, доступен ли настоящий мобильный экран сборки, а не только web
> preview. Если недоступен — сообщи конкретный блокер, не называй настройку завершённой.

Официальные инструкции:
- ZIP import: https://docs.replit.com/build/import-from-providers
- Native Mobile Apps: https://docs.replit.com/features/artifact-types/building-mobile-apps
- Apple account: https://docs.replit.com/build/mobile-apple-account
- iOS upload: https://docs.replit.com/build/mobile-upload-ios

## 2. Что уже есть

- Secretary: текстовое/голосовое поручение, уточнение, review номера/цели/карточек.
- Явное подтверждение, только TEST-задачи и восстановление той же задачи.
- Существующие карточки, профили номеров, история, итоги и транскрипты.
- Существующие персональные Google Calendar API, без фиктивного бронирования.
- Авторизация через существующий TalkHint Dev backend.
- Независимые iOS bundle ID и Android package:
  `com.talkhint.secretaryclient.dev`; scheme `talkhintsecretaryclient`.
- EAS development/preview-конфигурации; credentials и EAS project ID не созданы.

Код интерфейса в `src/` сохранён без изменений. Из конфигурации web-экспорта
удалён только старый префикс `/secretary-preview`, поскольку новый проект
запускается в корне. `EXPORT-MANIFEST.json` содержит контрольные суммы файлов.

## 3. Подключение к старому Dev backend

Старый TalkHint Dev-сервер должен быть запущен. URL указан в `.env.example`;
это публичный адрес, не секрет. При смене Dev URL измените эту настройку и
перезапустите Metro. В установленном приложении URL также можно задать
на экране входа/в Settings. Используются прежние аккаунты, новая регистрация
или копия базы не нужна.

**Не использовать production `talkhint.app`: клиент его запрещает, а
`/api/mobile-secretary/*` намеренно регистрируется только в Dev.**

Нативное приложение обращается к Dev API напрямую. Браузер нового проекта
имеет другой origin: текущий backend намеренно запрещает такой cross-origin
доступ. Поэтому отдельный web preview может показать интерфейс, но его вход/API
не следует считать проверенным. Не отключайте CORS ради демонстрации.
Рабочий same-origin web preview остаётся на старом Dev backend по адресу
`/secretary-preview/`. Это не замена нативной проверке.

В браузерном Google-входе подтверждается передача доступа к этому клиенту.
Авторизация фактическим аккаунтом и сохранение сессии в SecureStore требуют
проверки на iPhone/Android.

## 4. Команды

После установки зависимостей в новом проекте:

```sh
npm run typecheck
npm run start -- --dev-client
```

`.env.example` нужно скопировать в `.env` ДО запуска. Для отдельного отображения
web-интерфейса: `npm run web -- --port 5000` (ограничение CORS описано выше).
Не использовать web Deploy как способ установки на iPhone.

Нативная локальная сборка возможна при наличии соответствующих инструментов:

```sh
# macOS + Xcode + настройка подписи
npx expo run:ios
# Android SDK/JDK + emulator/device
npx expo run:android
```

Встроенный процесс Replit / Expo EAS потребует связать собственный Expo-проект
и Apple-аккаунт для подписи. Apple Developer Program нужен для TestFlight/App
Store. Не отправляйте пароль Apple, токены Expo или сертификаты в чат.
Никакая облачная сборка или загрузка в магазин этим архивом не запускается.
Expo Go не является обещанной целью проверки; для этого клиента предусмотрен
development build.

## 5. Перед тем как считать приложение собранным

- Есть устанавливаемый native build, а не только успешный export JS.
- На реальном iPhone и Android проверены вход/выход/refresh и восстановление.
- Проверены микрофон, остановка записи, возврат из Google и копирование.
- Review и повторное подтверждение создают одну TEST-задачу без звонка.
- Не открыты чужие данные; не включены SMS, push, запись звонков или Calendar writes.
- Неподготовленные Terms/Privacy не заменены фиктивным принятием.

История/транскрипт/итог доступны; новая аудиозапись звонков не включена.
Сроки хранения, релиз и реальные звонки требуют отдельных решений владельца.

## Проверка подготовленного архива

Проверены целостность ZIP, контрольные суммы, отсутствие backend/секретов/
node_modules и совпадение исходников клиента с существующим приложением.
Извлечённая в отдельный временный каталог копия прошла TypeScript и
`expo export --platform all`: пакеты iOS, Android и web сформированы.
Для проверки использовалась копия уже установленных зависимостей; чистая
установка в новом Replit-проекте ещё не проверена.

**Это проверка JS/Hermes-пакетов, не Xcode/Gradle/EAS-сборка.** Новый Replit-проект,
его мобильная панель, подпись Apple и работа на физическом устройстве ещё
не проверены. До импорта никакого нового проекта в аккаунте не создано.
