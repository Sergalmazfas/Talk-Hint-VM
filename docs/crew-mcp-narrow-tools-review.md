# Шесть узких инструментов production MCP, включая Марию — на сверку Claude

Вход: переданное владельцем заключение по этапу r970. Это не приёмка нового кода.
Добавление Марии: существующий опубликованный update_role_passport сохранил
полный должностной паспорт HEAD.06 в production, r971, с повторным чтением.
Это одна запись описания, не запуск и не приёмка. Шесть новых инструментов
ещё не применялись в production; Publish не выполнялся.

Источники этого дополнения: production get_team/get_roadmap r970,
DOC-TEAM-HEAD06 v1 и текущая инструкция владельца. Запись паспорта подтверждена
повторным get_team r971. Запрос get_product_chapter не вернул подтверждённого
результата — актуальная глава не объявляется прочитанной.
Maria_only.diff — добавление Марии поверх предыдущего набора;
diff.patch — общий diff шести инструментов от исходной базы.
TypeScript и 129 целевых тестов прошли; полный прогон приложен отдельным логом.
Закрытая UI проверена fixture-тестом; браузер без входа показывает только
авторизацию. Подписанная UI визуально не проверена.

## Мария — добавление к исходному пакету

Файлы Maria_Sobol_HEAD06.json и P_BENCH_Maria_Project_leads.json содержат
фактическую запись r971 и карту передач, будущие должности не выданы за существующие.
Формулировки триггеров/результатов и назначение владельца принимающим пяти
собственных обязанностей Марии — конкретизация HEAD.07 на сверку, не самоприёмка.
Мария принимает вход P-BENCH, не собственный результат.

Новый инструмент не принимает свободный JSON: берёт существующий role_passport
Марии указанной версии, проверяет пять разных обязанностей, реальные ID и
текущую согласованную структуру. Переносит только productResponsibilities и
ссылку на источник, повышая версию анкеты; остальные поля сохраняются.
Текущий показ команды после такого переноса читает именно пять обязанностей,
входы/клиентов, запреты и неизвестные метрики. Исторические нативные действия
не удаляются и не переименовываются.

В основной visual-анкете эта часть пока не внесена. Список 24 нативных действий
P-BENCH с прежними/требуемыми acceptorId находится в карте связей. Граф пока не
менялся. Прежние принимающие ACQ.CA.05 (регион) и MKT.2.25 (финансы) выделены
для явной проверки: продуктовая приёмка Марии не даёт финансовых полномочий
и не должна молча уничтожать смежное согласование.
После независимой сверки можно выполнить эти адресные изменения существующим
update_structure с повторным чтением; отдельного универсального patch не добавлено.

Анкета Нины переносит исходный v2 целиком в `sourceProfile`; отдельные визуальные
поля — для существующего читателя команды. `promptDraft` не превращается в
рабочий `prompt`. Неизвестный портрет остаётся пустым, имя сохраняет статус источника.
Перед заменой обязательны SHA-256 полного источника и старой основной анкеты.
Старый Markdown остаётся в обычной истории модели; документы/роли не удаляются.

Новые инструменты работают только в production. Dev не рекламирует их и
отказывает при прямом вызове. OAuth требует product:write; ключи проходят прежние
проверки владельца/отзыва/срока. Хранилище остаётся прежним production new-country,
с writes_open, CAS и атомарным updateMany. Схема БД, ключи и их права не менялись.

Каждая операция — одна атомарная группа команд с общей квитанцией. Внутри могут
появиться несколько последовательных ревизий, как в существующих операциях.
Идентичный requestId возвращает квитанцию; изменённый payload с тем же ID —
конфликт. Прежний requestId после потери ответа сначала сверяют чтением.

`ownerDecisionRef` — ссылка на входящее решение, не криптографическое доказательство
личной приёмки. Квитанции имеют state=received, не accepted. Приёмка через MCP
по-прежнему запрещена.

## Чтение и показ

- get_team возвращает IDs/версии/режимы анкет и руководителя проекции Кати.
- get_roadmap возвращает настоящий competitorDirectory для повторного чтения.
- Старая пустая карточка режима скрывается, когда создана его пустая должность.
- Живая Катя остаётся одной; изменяется только видимая связь подчинения.
- Без нового документа связи действует прежняя связь с владельцем.
  Если документ повреждён или руководитель исчез, ошибка, не молчаливая подстановка.

Старый валидатор URL каталога выбрасывал TypeError на пустом appStore ещё до
разбора разрешённого варианта "". Исправлено: невалидный URL даёт false,
пустое значение корректно проверяется прежней union-схемой.

## Что проверить независимо

1. Все шесть операций write-scoped и production-only; запреты доступа действуют
   до разбора аргументов: без входа, read-only OAuth, другой владелец, отозванный ключ.
2. Закрытая запись, устаревшая revision, конфликт requestId, отсутствие атомарного
   updateMany не дают частичных изменений.
3. Пустая должность не включает агентов; параметры executor/permissions/prompt и
   неизвестные поля отвергаются strict-схемами.
4. Смена названия сохраняет личность/промпт/полномочия. Нельзя убрать secretary
   у уже назначенного руководителя Кати.
5. Нина берётся только из сохранённого v2 с совпадающими hash; draft не исполняется.
6. Каталог конкурентов сохраняет прежние записи и историю, а переданные сведения
   не становятся проверкой живым сценарием.
7. Нет секретов в diff, архиве и диагностике. Провайдерские ответы не журналируются.

Команды: `npm run check`; `npm test -- --maxWorkers=1`.
В архиве отдельные логи полного и целевого прогонов, SHA-256 файлов.
Проверен неподписанный /admin: доступна только страница входа, auth не обходился.
Подписанный экран команды и новые операции на production до Publish не проверялись.

## Катя — отдельное read-only ограничение

`script/crew-katya-readonly-snapshot.ts` вызывает только список и чтение агента,
не readiness/create-agent/create-call. Сырые ответы, задания владельца и ключи
не сохраняются. В доступном Retell-аккаунте найдено **0** агентов с ожидаемым
production-именем для talkhint.app. Другой агент не выбран.

Это НЕ доказательство поломки Кати, неверного ключа или отсутствия рабочего
агента вообще: привязка действующего production-агента пока не установлена.
Полный действующий Engine-промпт также не получен; по памяти не восстановлен.
Разложение этого промпта по трём слоям остаётся открытым.

## После сверки

Publish выполняет только владелец. Затем: tools/list → get_team/get_roadmap,
актуальная ревизия → по одной согласованной записи из structure-pending,
Нина в P.ORG, Otter в каталог → повторное чтение каждой записи.

Этот пакет не даёт произвольной замены паспорта компании; дополнение AI Crew
в основной книге не считать автоматически внесённым. Обязанности Паши вне Hint
не удалены переименованием. 44 прочих случая самоприёмки не менялись.
Книжки знаний и R1–R5 остаются proposed. Активация, вызовы, деньги, удаление,
самоприёмка, Archive/TestFlight в этот пакет не входят.
