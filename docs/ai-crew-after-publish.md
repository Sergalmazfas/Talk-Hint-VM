# AI Crew · порядок после независимой проверки

До положительной сверки Клавдия — не публиковать.
Publish делает только владелец, **без Copy development database to production**.
Агентов/модели и после Publish не включать.

1. После Publish открыть [закрытую панель AI Crew](https://talkhint.app/admin/ai-crew)
   под владельцем. Если показан вход — войти прежним аккаунтом владельца.
   Это новый адрес: до Publish старый сервер его не обслуживает.
2. Кнопкой «Обновить» проверить среду `production`, наличие ключа,
   `enabled=false`, лимит `0`, срок `24`, пустые agents/runs/schedules.
   Метаданные ключа — только true/false; значение нигде не вводить.
3. «Инициализировать» — **один явный технический шаг**: новая отдельная таблица
   runtime, если миграция Publish её ещё не создала, и отдельная строка
   начального состояния. Существующая строка не перезаписывается.
   Модель `new-country` и анкеты не редактируются.
   Затем повторное чтение: OFF/0, запись публикации с commit/sourceHash/taskRef.
4. «Получить модели»: получить actual IDs уже с production-сервера.
   Зафиксировать возвращённые Opus/Sonnet/Haiku ID, не заменять их догадками.
5. Выбрать один ID из этого списка и выполнить **один** короткий probe.
   Это разрешённая владельцем диагностическая генерация, не агент.
   Зафиксировать `environment=production`, model, usage, status.
   Timeout/unknown — стоп: не нажимать повторно и не очищать slot.
6. Повторно прочитать состояние: агенты OFF, бюджет 0, назначений нет.
   Проверить кнопку общего отключения (она не включает ничего).
   Сохранить подтверждение этой проверки отдельным отчётом, не выдавать
   текущий Dev-прогон за production-доказательство.
7. По отдельному будущему решению — установить реальные ставки, бюджет,
   назначить конкретных сотрудников и сценарий запуска. Этот план их не включает.

Дополнительно:
- Никаких новых звонков, подключений агентов или изменения настроек Кати.
- Имена Севы/Лёвы/Томы этим пакетом не записывать: нет разрешённого узкого способа.
- Следующий реальный звонок получит codeVersion при старте. Старую историю
  не переименовывать и не переписывать текущей версией.
- Если production не содержит новую таблицу и создание не разрешено
  результатом независимой проверки — остановиться, не обходить.
- Закрытый интерфейс владельца без входа не проверен визуально; проверены
  маршрут отказа, его API-контракты и безопасный скрипт страницы.
