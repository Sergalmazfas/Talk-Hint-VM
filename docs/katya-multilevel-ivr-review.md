## Изменение

1. Граница услышанного фиксируется при каждой отправке цифры. Следующий уровень
   собирается только из речи ПОСЛЕ этой границы, в том числе при дополнении одного
   ASR-turn. Старая цитата не подходит для нового уровня.
2. Явные варианты текущего меню сопоставляются с целью: парковка/бронирование →
   точный пункт, иначе general manager/manager; шинный сервис → service advisor,
   parts/in-shop/truck service; затем доступный человек/повтор.
   Метка связывается со своей цифрой, включая меню без точек, с запятыми.
3. Для распознанных вариантов не нужен дополнительный медленный вызов модели:
   существующий Engine отправляет существующую Retell DTMF-команду. В остальных
   случаях прежние IVR tools остаются; необъявленные цифры/приватный ввод запрещены.
4. Уведомление помощи имеет предел ожидания 2500 ms. Даже provider_accepted
   не доказывает доставку владельцу: доступный безопасный пункт выбирается самостоятельно.
   При отсутствии подходящего пункта используется объявленный повтор; если и его
   нет — немедленный audible fallback `representative`, без выдуманной цифры.
   Поздний результат уведомления не восстанавливает ожидание; слепого повтора push нет.
5. Сохраняются write-ahead audit, проверка текущего меню, abort и защита от
   повторной/неопределённой отправки. Лимит 5 цифр без ДРУГОГО меню не сбрасывается
   из-за промежуточных ASR-фрагментов.
6. Событие содержит текущую цитату, menuHash, выбранную цифру, reason,
   время события, sentAt и привязку к turn. Новые снимки вставляют нажатие после
   соответствующего меню, не после всех будущих реплик/Goodbye.

## Replay и проверки

Исходные цитаты: `server/secretary/fixtures/ivr-replays.json`, только меню без
имён владельца, телефонных номеров и остального содержимого звонка.

- TA: **8 → 7**.
- Love's: **1 → 2**.
- Реальные SecretaryConversationEngine и RetellEngineRegistry; локальный fake
  WebSocket, перехват `digit_to_press`, ноль вызовов модели в этих двух replay.
- Обновления частичной ASR сами цифры не отправляют; семь уровней, дополнение
  одного turn, stale/abort, sensitive input, повтор одного меню/лимит пяти цифр.
- Отсутствующий/зависший help-push, поздний результат, самостоятельный general
  manager/повтор, audible fallback без второго вызова модели.
- Проверка порядка menu → digit → next menu → digit → Goodbye.

Это **текстовый replay с подставленным транспортом**, не аудио-replay, не оценка
реального STT/LLM/Retell/PSTN и не доказательство слышимого DTMF на телефоне.
2500 ms — предел ожидания уведомлений на сервере; физическая слышимость и
задержки БД/сети не доказываются локальным тестом и требуют контрольного звонка.

## Что проверить Claude

- Нет склейки уровней и повторной отправки по старому снимку/после human answer.
- Из пункта «fuel — 1» не получается «general manager — 1» из-за соседнего текста.
- Private input, abort, неизвестный исход отправки и лимит пяти цифр не ослаблены.
- Help-push не оставляет бесконечного ожидания, в том числе при зависании.
- Журнал честно различает отправку команды и принятие DTMF адресатом.
- JSON-метаданные совместимы с прежними записями, старым событиям не придумано время.
- Изменения ограничены меню, личность/разговорный характер не затронуты.
