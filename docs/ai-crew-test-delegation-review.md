# Самостоятельные проверки Replit · пакет Клавдию

## Решение владельца и границы

Отдельный scope `crew-test`, отдельный Secret `CREW_TEST_KEY` (не менее
32 случайных байт в base64url/hex), отдельный production endpoint
`https://talkhint.app/api/crew-test/mcp`, заголовок `X-API-Key`.
Обычный PRODUCT_CREW_KEY, OAuth и cookie владельца доступа сюда не дают.
Значение ключа не сохраняется в модели, файлах, журнале или ответах.
Сравнение SHA-256, constant time. Ключ не создаётся при запуске приложения.
Без Secret — отказ. Браузерные Origin-запросы на этот endpoint запрещены.

Первый успешный аутентифицированный запрос фиксирует в существующей строке
CrewStore одну серию на 7 дней, $5 = 5 000 000 microUSD. Это **не** запуск
агентов: для этого нужны отдельные prepare/enable/start. При Publish ничего
не включается. Срок и бюджет не обновляются при последующем обращении,
смене ключа, новом дне или рестарте. Самообновления разрешения нет.
Отзыв до первого использования оставляет tombstone: ключ не создаст новую серию.
Смена ключа после начала требует нового решения/механизма выдачи, не обходит отзыв.

## Узкие команды

`crew_test_state`, `crew_structure_check` — чтение. Результат проверки структуры
не исправляет модель. Аутентифицированные обращения обновляют только lastUsedAt/
revision в runtime-журнале, не new-country.

`crew_test_prepare` (только latency), `crew_test_enable`, `crew_test_start`,
`crew_test_off`, `crew_test_close_stalled`. Каждая запись: свежая revision,
новый requestId; изменение атомарно через CrewStore, ответ/reread. Повторный
UUID/конфликт — STOP, а не повтор paid generation.
Нет произвольных промптов, выбора моделей/тарифов, enqueue, schedule, advance,
приёмки, изменения продукта, звонков, Кати, Publish или чтения Secrets.
Фиксированные, ранее утверждённые модели Паши/Фомы не меняют рекомендации
в анкетах. Паша предлагает, Фома проверяет, приёмка остаётся владельцу.

При delegated ON диспетчер не запускает чужие задачи/очереди/расписания.
Новая подготовка после завершённой цепочки оставляет прошлую задачу ожидающей
владельца, не принимает и не закрывает её за него.
Для старого latency-пилота разрешено только безопасное закрытие уже согласованным
helper: OFF, queued, без running/unknown/резервов/расходов/документов.
Владелец и история старой задачи не переписываются. Автоматического закрытия нет.

## Бюджет и безопасность

Счётчик серии — отдельный от UTC-суточного, в той же заблокированной строке:
`spent + reserved + maximum_request_reserve <= 5_000_000`.
Резерв — консервативная UTF-8 верхняя оценка входа с запасом + 2000 токенов
выхода по фиксированным тарифам. Перед каждым запросом проверяются ОБА лимита.
Успех заменяет резерв фактической ценой usage; unknown переносит весь резерв
в spent серии навсегда. Суточный unknown-резерв не освобождается.
Запросы после unknown автоматически не повторяются.
Это учёт по токенам и принятым ставкам, не сверенный счёт провайдера.
Если провайдер вернёт расход выше резерва, OFF и discarded, расход не скрывается.

Независимый maintenance-таймер (не зависимый от busy dispatcher):
- проверяет expiry/revocation и выключает делегированный ON;
- спустя 5 минут queued/running — OFF; running становится unknown, резерв
  серии считается потраченным; после crash/restart это тоже работает;
- выключение/истечение проверяются также перед отправкой и во время запроса;
- поздний ответ после unknown не принимается и не освобождает расход.
После штатной цепочки — автоматический OFF, без сброса расходов серии.
В action-журнале actor `replit-test`; agentId отдельно сохраняет Пашу/Фому.

Панель `/admin/ai-crew`: срок, остаточный учёт/последнее использование,
кнопка окончательного отзыва с подтверждением, owner auth, Origin, CSRF,
revision и reread. Без обхода сессии владельца. Независимый OFF сохраняется.

## Бесплатная проверка структуры

Один production new-country источник, только read. По команде или ежедневно
UTC (опрос раз в минуту). Результат ежедневно append-only в runtime-state,
не в модель компании. Никаких моделей, расходов или автоисправлений.
Сбой чтения не выдаётся за «ок».

Мария, Hint, штатные роли Секретаря: поля обязанностей, рабочее место,
disabled/proposed рекомендация, запрет продукта; manager-chain до Марии/owner,
циклы/сироты/depth >3; все действия на самоприёмку, включая общего исполнителя.
Отсутствующие/непонятные поля и неустановленная идентичность исполнителя —
проблема, не предположение. Отдельно часы/держатель зависших runtime-задач.
Катя и будущие каталожные слоты не синтезируются как роли: каталожные ссылки и
runtime-настройки не записываются. Проверка не доказывает выполнение обязанностей.
Вывод: ID, check, ok/problem; без текста звонков/номеров/посторонних имён.

## После независимой сверки и Publish владельцем

1. Без Copy development database to production. Новых SQL-таблиц/DDL нет.
2. Защищённо добавить отдельный CREW_TEST_KEY в shared/production Secrets;
   ключ не передавать в чат. Пока его нет — запуск заблокирован.
3. Replit: `npx tsx scripts/crew-test.ts state`, затем `structure`, затем `latency`.
   Скрипт не входит в startup/build и не запускается при Publish.
4. При ошибке/unknown — не повторять запись; свежий статус, OFF/watchdog,
   отчёт. Владелец может отозвать доступ на панели.
5. Проверить OFF, общий spent/reserved серии, usage каждого исполнителя.
   Фактический результат сохранить в generated-artifacts, ZIP Клавдию.
6. Отдельная ручная оценка Replit по документам: факты/гипотезы/пробелы
   в разборе Паши; конкретная сверка Фомы с данными/расхождениями.
   Разные модели сами по себе не доказывают независимости проверки.
   Числовой privacy-excerpt не доказывает качество текста/голоса подсказок.

## Что пока не проверено

Настоящий production запуск, наличие нового Secret в production, расход провайдера,
реальные роли/пробелы модели, production daily-report и настоящий expiry через 7 дней.
Это проверяется только после Publish. В текущем пакете — воспроизведения на fixture,
поддельном provider и временной таблице Dev PostgreSQL, не платные запросы.
Полный тестовый отчёт и снимок исходников приложены отдельно в ZIP.
