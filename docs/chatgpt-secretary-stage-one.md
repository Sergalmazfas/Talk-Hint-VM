# TalkHint Secretary → официальный ChatGPT: первый этап

Дата проверки документации OpenAI: **19 октября 2026 года**.

## Что сделано, а что не включено

Доработан существующий серверный адаптер, без нового чата, web-экрана или iOS UI.
Обычные звонки, Twilio dialer, голос, входящие webhooks и база не заменены.
Настройки production не изменены, публикации и настоящего набора не было.

Сам адаптер требует явного включения и корректной конфигурации. Даже после
включения режим по умолчанию — только чтение:

| Разрешение | Данные |
|---|---|
| `calls:read` | Только свои звонки, статусы и результаты Secretary |
| `calls:transcript` | Дополнительное разрешение на полный текст транскрипции |
| `offline_access` | Обновление доступа с ротацией refresh token |

Доступные инструменты: `get_profile`, `list_calls`, `get_call`, `list_tasks`,
`get_task`. Нет инструментов изменения настроек, SMS, переадресации, входящего
AI-ответа, записи или отправки сообщений в ChatGPT.

`secretary:start` и `incoming:read` не выдаются в этом режиме. Исходящие
инструменты не только скрыты из списка, но и запрещены на сервере. Ранее
выпущенный токен с правами записи не обходит этот запрет.

## Как проверялось

Команда: `npm run test:chatgpt-secretary`.

Результат проверки 19.10.2026: **36 изолированных тестов прошли**.
Полный существующий workflow `npm test`: **104 файла, 1304 теста прошли**,
включая существующие development PostgreSQL integration tests с тестовыми
записями и их cleanup. Это не production DB проверка. TypeScript
(`npm run check`) и `git diff --check` также прошли.

Это отдельное тестовое окружение Vitest + Express/Supertest:

- без подключения к development/production PostgreSQL;
- без наследования телефонных и AI-ключей;
- с вымышленными аккаунтами, хранилищем разрешений и dialer;
- с запрещённым `fetch` в HTTP OAuth/MCP-тестах;
- без импорта production Twilio dialer или запуска телефонного сервера.

Проверяется реальный HTTP-контракт OAuth/MCP, но пользователь, БД и телефония
имитируются. Это **не** проверка подключения из аккаунта OpenAI и **не** MCP
Inspector. Существующие проверки нативного lease/idempotency находятся отдельно
в `server/secretary/__tests__/liveTask.integration.test.ts`; они используют
PostgreSQL и не входят в изолированную команду выше.

Покрыто:

1. Discovery, authorization code + S256 PKCE, точные client/resource/redirect,
   возврат state/iss, одноразовый code.
2. Чтение звонков/результатов владельца, изоляция двух аккаунтов,
   запрет подставленного user ID, отдельное разрешение на транскрипцию.
3. Короткий access token, ротация refresh, отзыв подключения,
   запрет обмена после отзыва; повтор использованного refresh отзывает семью.
4. OAuth-коды ошибок, MCP auth challenges, инициализация, JSON-RPC ошибки,
   GET 405 для сервера без SSE.
5. Отсутствие write-инструментов в read-only режиме и запрет скрытого вызова.
6. Отдельный mock-сценарий исходящего через настоящий адаптер Secretary:
   OAuth → точные номер/задание → owner approval → параллельные повторные
   start → один fake dial → одинаковый task_id → чтение результата.
7. Legacy `POST /start-call`: 401 без авторизации, 410 для владельца,
   без обращения к телефонному провайдеру.

## Соответствие официальному контракту

| Требование | Состояние |
|---|---|
| Remote MCP, JSON Streamable HTTP | Реализован stateless POST, без SSE |
| OAuth discovery и protected resource | Реализованы, scopes зависят от режима |
| PKCE S256, resource binding, issuer, точный callback | Реализованы; проверены имитациями |
| Predefined OAuth client | `talkhint-chatgpt`, public client, token auth `none` |
| DCR/CIMD | Не реализованы; predefined client допустим по документации OpenAI |
| Персональные разрешения и отзыв | Реализованы; проверяются при чтении |
| Profile tool | Стабильный непрозрачный ID, без email и секретов |
| OAuth onboarding в браузере | Только существующая owner auth и заранее одобренный grant |
| Реальный OpenAI account / Inspector | Не проверены |
| Каталог опубликованных Plugins | TalkHint не публиковался |
| Официальный ChatGPT на iPhone | Не подтверждён |

Указание соответствия выше относится к реализованным элементам контракта,
не к сертификации OpenAI или полной проверке всей OAuth-спецификации.

## Как будет подключаться пользователь в ChatGPT web

Это инструкция для **отдельного согласованного тестового HTTPS окружения**,
не инструкция включать production.

1. Подготовить защищённый тестовый HTTPS endpoint с тем же адаптером.
   Не подключать его к настоящему dialer. Не использовать fake owner headers
   из unit-тестов в публичном сервисе.
2. Открыть [официальный раздел Plugins](https://chatgpt.com/plugins).
   Если аккаунт/workspace позволяет, добавить custom remote MCP:
   `https://<тестовый-домен>/api/chatgpt/mcp`.
3. Выбрать OAuth с predefined public client `talkhint-chatgpt`;
   client secret этому flow не нужен. Точный callback скопировать из OpenAI.
   Нельзя самостоятельно угадывать или расширять redirect allowlist.
4. Согласовать конфигурацию тестового origin/callback и существующего
   подписывающего сервиса. Секреты остаются на сервере; не отправлять их в чат.
5. Из отдельного авторизованного owner API-клиента создать grant с
   `calls:read calls:transcript offline_access` либо без transcript, если
   нужен только статус/summary. Полную owner-сессию нельзя отдавать ChatGPT.
6. OAuth authorization должен выполняться в браузере с действующей
   авторизацией владельца. Нативный iOS Bearer token не появляется в браузере
   автоматически. Не передавать его в URL или через чат.
7. Выполнить Scan Tools и безопасный запрос:
   «Покажи мои последние звонки и результат последней завершённой задачи.
   Ничего не набирай и не меняй».
8. Отозвать подключение через owner API и проверить, что старые access/refresh
   больше не работают. Затем при необходимости авторизоваться заново.

**Текущий блокер пользовательского onboarding:** адаптер не создаёт браузерную
login/consent-сессию и не рисует страницу согласия. API-only grant проверен,
но сам по себе не обеспечивает установку из ChatGPT в несколько нажатий.
Нужна проверка существующей браузерной owner auth на выбранном тестовом домене.
Если она отсутствует, безопасная минимальная web-страница входа/согласия
потребует отдельного разрешения пользователя. Она в этом этапе не создана.

## iPhone: что можно и чего нельзя обещать

Документация custom MCP указывает **web-only**. Документация опубликованных
Plugins описывает каталог на mobile, но доступность зависит от конкретного
плагина, аккаунта, региона и workspace.

Следовательно:

- web MCP не доказывает совместимость с iPhone;
- наличие ClawCall в каталоге доказывает существование такого пути у другого
  поставщика, но не доступность TalkHint;
- установка и чтение результата должны быть реально проверены в официальном
  приложении ChatGPT на целевом iPhone;
- TalkHint пока не опубликован, проверка на iPhone не выполнялась.

## Исходящий сценарий: пока только имитация

В отдельном тестовом экземпляре адаптера разрешён mock outbound режим.
Рабочая серверная композиция его не включает.

1. `prepare_call` получает точный US +1 номер, задание, UUID `clientRequestId`,
   существующие provider/language параметры Secretary.
2. Сервер возвращает подписанное ограниченное по времени подтверждение.
   Звонка ещё нет.
3. Владелец отдельно подтверждает его через
   `POST /api/chatgpt/confirmations/approve`, с обычной owner auth.
4. `start_call` принимает только это подтверждение. Подмена номера, другой
   владелец/подключение, просрочка и `confirmed:true` отклоняются.
5. Нативный persistent lease допускает один запуск. Повтор возвращает прежнюю
   задачу, в ответе есть `task_id`.
6. `get_task` читает результат. `finalizing` и `unknown` не означают успех.

«Allow all tools» и подтверждение модели не заменяют пункт 3.

**Для обычного пользователя отдельное подтверждение в браузере сейчас не
оформлено.** Если существующие средства его не обеспечат, минимальный экран
должен показать номер, задание, срок, кнопки подтвердить/отклонить, привязать
решение к owner session и быть защищён от CSRF. Не давать MCP-токену право
подтверждать себя. Такой экран сначала нужно согласовать.

## Асинхронность и отключённые функции

Baseline: вернуть task_id, затем прочитать статус/отчёт по запросу пользователя.
Нет обещания фонового polling, доставки в исходный разговор или уведомления
после закрытия ChatGPT.

Входящие AI, переадресация, SMS, автоматическая запись, новые голоса и
chat subscriptions в этот этап не входят. Отзыв доступа не завершает уже
принятый нативный звонок и не удаляет историю.

## Следующий шаг для реального подключения

Согласовать отдельный HTTPS test endpoint и проверить браузерную авторизацию
владельца. При необходимости отдельно согласовать минимальное web consent,
затем выполнить read-only OpenAI linking + revoke на целевом аккаунте.
Только после этого можно обсуждать публикацию и проверку iPhone; настоящие
исходящие звонки требуют нового явного разрешения.
