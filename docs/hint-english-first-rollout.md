# Hint В: подготовка включения, а не включение production

## Сделано

- Английская часть и последующий перевод используют OpenAI strict JSON Schema
  (`additionalProperties:false`, все поля обязательны) и дополнительную проверку
  результата. CHOICE собирается сервером в каноническую строку.
- SSE обрабатывается на сервере. На устройство отправляется **вся проверенная
  английская карточка**, не фрагменты JSON. Это первая совместимая версия, а не
  показ слов потоком на iPhone.
- Полный live-контекст, grounding, стратегия, фильтры, дедупликация и библиотечный
  fast path сохранены. Короткий экспериментальный промпт в live не переносится.
- Перевод приходит вторым сообщением и обновляет ту же карточку. Для web это
  updateOnly; существующий iPhone заменяет pinned banner. Нет второй hint-cycle
  или повторного ACK web-карточки.
- Перевод не ждёт перед показом английского. Перед запросом перевода повторно
  проверяются настройки, режим и состояние звонка. Перед доставкой —
  актуальность реплики, карточки, revision и переключателей.
- Translation OFF не вызывает вторую модель; Hints OFF сохраняет ранний запрет
  генерации. Ошибка/отказ/обрезанный JSON не выдаётся за подсказку, скрытого
  переключения провайдера и автоматических повторов нет.

## Управление и откат

После Publish: https://talkhint.app/admin/hint-mode — вход владельца.

Настройка относится к **своему пользователю**, не ко всем клиентам. Исходное
значение `legacy`, revision `0`. PUT защищён owner-admin доступом, Origin,
отдельным CSRF, явным подтверждением и CAS revision. Перед записью и после неё
страница перечитывает состояние. Неясный ответ — остановка, не повтор записи.

В — схема English-first. Она сохраняет явно заданный candidate Brain override;
при его отсутствии используется `gpt-5.6-terra`. Контроль strict-контракта
выполнен именно на Terra. Провайдер указан в серверной диагностике.

Откат — кнопка «Старый». Нового Publish для отката не нужно.

## База

В Dev выполнены только добавления к `users`:

```sql
hint_response_mode text NOT NULL DEFAULT 'legacy'
hint_mode_revision integer NOT NULL DEFAULT 0
```

Это **не инструкция выполнить SQL в production**: production-схему применяет
штатный Publish владельца. В production выполнено только чтение списка колонок.
Production-only таблиц/колонок по этой проверке нет; Dev-only — ровно два поля
выше. Типы, nullability и defaults новых Dev-полей приложены.

Проверка имён колонок не является полной сверкой всех индексов/ограничений БД.
На экране Publish ожидаются два добавления. Любой DROP — стоп. Не включать
«Copy development database to production». Production-значение режима не менялось.

## Проверки и ограничения доказательства

В ZIP: полный Vitest по четырём шардам, сверка покрытия файлов и исходников,
TypeScript, проверка синтаксиса classic web script, offline release build,
результат синтетического запроса, ожидаемая схема.

Синтетический контрактный контроль — два HTTP 200 (EN/SSE + перевод), обе схемы
strict. Оценка расхода $0.012035 по usage; это не счёт провайдера. Списано в
остаток **старой** серии до $15, с резервом до запросов. Новая серия $15 не начата.
Это не замер задержек на реальном звонке и не проверка качества на полном корпусе.

При полном прогоне один тест учёта ошибок БД попутно запускал source/Git I/O и
вышел за таймер. Зависимость изолирована только в этом unit-тесте; проверки
реального provenance сохранены. После этого весь набор повторяется заново.
Исходный неуспех не скрыт в отчёте.

Также один старый тест большого паспорта модели превысил стандартные 5 секунд.
Ему дан тот же предел 15 секунд, который уже используют соседние проверки того
же полного снимка. Проверки данных сохранены; это не тест пятисекундного SLA.
Окончательный полный набор запускается на одном снимке уже с обеими правками
тестов. Частичные предыдущие результаты не выдаются за финальный прогон.

Не проверено: интерфейс новой страницы в реальной сессии владельца, физический
iPhone, реальный входящий/исходящий звонок с новым режимом, время до первого
слова именно этой strict-реализации. Доступ, Origin, CSRF, CAS и разметка
страницы проверяются автоматическими тестами, а не обходом входа.

## Порядок выпуска

1. Сверка ZIP Клавдием: затронуты БД и защита настройки.
2. Publish делает владелец; приложение остаётся на старом режиме.
3. После отдельного «да» владельца — включение В и пробный звонок владельца.
   Если хуже — откат той же настройкой.
4. Затем отдельный native-стенд Gemini Live / GPT Realtime по
   `docs/hint-native-models-next-stage.md`, новая серия до $15. Сейчас это план:
   новые native-адаптеры не реализованы и платные прогоны не начаты.

Swift не менялся: новая сборка iPhone для этой первой версии не требуется.
Publish сайта сам по себе не обновляет iPhone-приложение.
