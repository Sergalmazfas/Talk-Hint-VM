# TalkHint Secretary: восстановить инструменты ChatGPT

> Для подготовленной версии **0.3.1 / MCP 1.2.1** актуальна
> [инструкция подтверждения прямо в чате](talkhint-chatgpt-inline-confirmation.md).
> Ниже — предыдущая диагностика опубликованного сервера. Новая версия добавляет
> UI-only инструмент и не требует перехода на сайт перед каждым MCP-звонком;
> её ещё нужно отдельно опубликовать и проверить в реальном ChatGPT.

## Что установлено проверкой

Production `https://talkhint.app/api/chatgpt/mcp` уже отдаёт Streamable HTTP,
настроенный OAuth callback и семь инструментов, включая `prepare_call` и
`start_call`. Это проверка сервера, а не установленной копии плагина.
Открытие `/api/chatgpt/secretary` показывает сохранённую историю, не набирает
номер и не доказывает выполнение сегодняшнего поручения.

Сервер и установленный пакет обновляются независимо. Старые инструкции в
выбранном плагине не доказывают, что работающий сервер остался read-only.
Replit не может прочитать или заменить локальный кэш ChatGPT пользователя.
Содержимое конкретной установленной копии здесь не проверено.

## Самый короткий путь в ChatGPT

1. Открыть [ChatGPT Plugins](https://chatgpt.com/plugins).
2. Найти именно подключение сервера TalkHint Secretary, адрес которого
   `https://talkhint.app/api/chatgpt/mcp`. Выбрать **Refresh**.
3. Проверить список: `get_profile`, `list_calls`, `get_call`, `list_tasks`,
   `get_task`, `prepare_call`, `start_call`.
4. Если подключения сервера ещё нет, добавить **custom MCP server** с этим
   адресом и **Create as a plugin**. Не создавать второй телефонный backend.
5. Пройти OAuth: provided client `talkhint-chatgpt`, token auth `none`,
   callback `https://chatgpt.com/connector_platform_oauth_redirect`.
   Начальные права: `calls:read offline_access`. Входить в свой аккаунт TalkHint.
   `secretary:start` запрашивается отдельно для подготовки исходящего.
6. Открыть новый чат с обновлённым подключением и сначала проверить `get_profile`.
   Отсутствие инструментов и ошибка авторизации — разные проблемы.

Семь инструментов уже доступны в production; для их появления в ChatGPT
не обязательно ещё раз публиковать TalkHint. Новая публикация нужна для
обновлённых серверных инструкций, версии, подсказок и публичных skill-файлов.
После неё всё равно требуется обновление метаданных на стороне ChatGPT.

## Если выбран отдельный локально установленный пакет

**Refresh сервера не заменяет инструкции и связи локального пакета.**
Обновить исходный пакет в его marketplace, привязать реальное зарегистрированное
подключение TalkHint, обновить установленную копию и начать новый чат.
Для локальной схемы OpenAI требует `.app.json` с фактическим
`plugin_asdk_app...` ID и ссылку `extensions.com.openai.apps` на этот файл.
ID установленного пакета вида `plugins_...` не подходит для этой привязки.
Не придумывать ID, не использовать другой продукт и не заменять OAuth на noauth.

Короткое поручение для `@plugin-creator` в ChatGPT Work:

> Обнови существующий частный TalkHint Secretary, не создавая новый backend.
> Привяжи его к существующему зарегистрированному MCP-серверу
> https://talkhint.app/api/chatgpt/mcp через реальный plugin_asdk_app ID.
> Проверь .app.json и extensions.com.openai.apps, добавь актуальные
> skills/setup/SKILL.md и skills/secretary/SKILL.md из подготовленного пакета.
> Обнови установленную копию, а не только исходную папку.
> Должны быть семь tools, включая prepare_call и start_call.
> Не звони, не меняй OAuth-защиту и не открывай историю вместо запуска.

## Подготовленный пакет

```sh
npm run chatgpt:package -- --private-config docs/chatgpt-private-plugin.example.json
```

Создаёт offline source ZIP с настоящим endpoint и новыми skills. Если реальная
привязка не передана, имя **NEEDS-MCP-BINDING**, receipt говорит
`structurallyComplete: false`: это исходники для обновления, не готовое подключение.
Старый `talkhint-NOT-FOR-UPLOAD.zip` с `.invalid` использовать нельзя.

Чтобы получить структурно полный private candidate, в отдельный non-secret
конфиг передать `registeredApps` — фактическое содержимое `.app.json`,
созданное plugin-creator для единственного TalkHint connection. Не передавать
токены, пароли, cookies, authorization URL или client secret. Сборщик сохраняет
реальную привязку без изменения и никогда её не генерирует из догадки.
Даже candidate требует проверки в реальном ChatGPT, не доказывает OAuth или звонок.

## Один будущий тест, только по явному запросу владельца

1. Ввести точный номер и цель. `prepare_call` возвращает preview и
   защищённую `approval_url`; звонка ещё нет.
2. Открыть эту ссылку, войти в TalkHint, проверить номер/цель и подтвердить.
3. Вернуться в чат. `start_call` использует ту же confirmation и возвращает
   один `task_id`. Повтор запроса не должен создавать новый набор.
4. `get_task` читает только этот `task_id`. Пока статус не завершён, не
   объявлять успешный звонок. Старый FAILED не является результатом нового теста.
5. Если звонок ещё идёт, попросить позднее проверить результат этого поручения.
   Автоматического фонового сообщения в исходный чат нет.

В этой работе настоящих звонков нет. Прямой MCP write-доступ и возможность
использования в официальном iPhone-приложении зависят от клиента и правил
OpenAI; успешный серверный тест не является подтверждением этой совместимости.
Официальная справка сейчас ограничивает custom MCP на личном Pro правами
read/fetch, а полный MCP — Business и Enterprise/Edu; подключение на mobile
указано как web-only. Обновлённый пакет не отменяет этих ограничений. Если
после Refresh доступны read-инструменты, но недоступен `start_call`, отдельно
проверить политику фактического аккаунта, не ослаблять серверную авторизацию
и не объявлять сценарий звонка рабочим.
