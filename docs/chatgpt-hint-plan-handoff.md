# ChatGPT → подготовка Hint и существующий Секретарь

## Границы

Изменение только в Dev. Ничего не публиковалось, production-данные не менялись.
Нет новых секретов, OAuth scope, агентов, звонков или изменений личности/голоса Кати.
Новые операции доступны personal GPT Actions и существующему ChatGPT MCP,
с тем же OAuth и существующим `secretary:start`. В Actions владелец закреплён
текущим конфигом; в ChatGPT MCP дополнительно проверяется уже подтверждённый
company/lab owner. Если привязка владельца ещё неизвестна — отказ, не обход.
MCP Product Crew не расширялся.
Старые `prepare_call` / `start_call` и независимое подтверждение звонка сохранены.

## Общий JSON плана

```json
{
  "goal": "Узнать наличие и полную цену новой шины 295/75 R22.5",
  "ownerFacts": ["Нужна новая шина 295/75 R22.5"],
  "sayAsk": ["Уточнить наличие", "Уточнить цену с монтажом и налогом"],
  "expectedQuestions": [
    {"q": "Для какой оси нужна шина?", "answer": null}
  ],
  "unknowns": ["Ось", "Количество", "Бюджет"],
  "disclosurePolicy": {
    "allowed": ["Требования к шине"],
    "forbidden": ["Платёжные данные"]
  },
  "language": "en",
  "executor": "hint"
}
```

`targetPhone` — необязательный E.164. У Secretary обязателен; существующий телефонный
путь по-прежнему принимает только номера +1. `disclosurePolicy` намеренно
структурирован: `allowed` / `forbidden`, без расплывчатого свободного текста.
`null`/пустой answer означает «ответ неизвестен», не разрешение выдумать.
До 20 ожидаемых вопросов, общий план до 12000 символов.
У Secretary сохраняется старый предел instruction 2000 символов **вместе с JSON
и предостережением**: большой план явно отклоняется, не обрезается.

## Что вставить в существующий GPT

После Publish владельцем обновить Actions schema содержимым
`talkhint-actions.openapi.json` из пакета или импортировать URL
`https://talkhint.app/api/chatgpt-actions/openapi.json`.
OAuth **не перенастраивать**, ключи/secret в инструкции не вставлять.
Если существующий ChatGPT подключён через MCP `/api/chatgpt/mcp`, менять транспорт
не нужно: обновить метаданные подключения, чтобы получить два новых инструмента.
Подтверждение Secretary остаётся внутри существующей защищённой inline-карточки.

Добавить в инструкции GPT:

> Ты готовишь звонки владельца TalkHint. Сначала собери цель и 3–5 существенных
> уточнений. ownerFacts — только подтверждённые владельцем факты; неизвестное
> записывай в unknowns. В expectedQuestions укажи ожидаемые вопросы собеседника и
> подтверждённые готовые ответы; неизвестный ответ — null. Согласуй, что можно и
> нельзя раскрывать, заполни disclosurePolicy. Не выдумывай карточку владельца.
> Для «план для Hint» вызови save_hint_plan с executor=hint и новым UUID
> clientRequestId. Без номера план относится к следующему исходящему Hint-звонку;
> с targetPhone — к следующему подходящему звонку на этот номер. Срок 24 часа.
> Это НЕ звонок: сообщи результат сохранения и срок. При неоднозначном ответе
> повторяй только тот же UUID и тот же план; не создавай замену вслепую.
> Для «задание Кате» используй prepare_secretary_plan с тем же форматом,
> executor=secretary и точным номером. Дальше следуй существующему подтверждению
> точного номера/задачи и start_call. Никогда не обходи независимое подтверждение
> и не создавай второй звонок для получения результата.
> После Hint-звонка найди запись через list_calls и, по явному запросу владельца
> на разбор с расшифровкой, get_call с includeTranscript=true. Для этого уже
> нужен calls:transcript. Поле preparation содержит сохранённые признаки
> подготовки; итог лаборатории также приходит обычным письмом, если лаборатория
> включена владельцем. Не называй совпадение слов полезностью или 99% успеха.
> Новые действия не дают доступа к произвольным документам/модели компании.

## Поведение

- Сохранение Hint-плана не набирает номер. UUID идемпотентен, другой payload с тем же UUID — 409.
- Новый UUID заменяет только pending-план для того же номера/общего слота.
- TTL от создания — 24 ч, повтор UUID срок не продлевает.
- Привязка сериализована advisory transaction lock по владельцу; сначала точный
  номер, затем общий план. План должен существовать до начала звонка.
- Звонок получает неизменяемый snapshot и hash. Повторный webhook не потребляет
  следующий план. Никаких удалений строк и автостарта.
- Входящий звонок, Translator, Copilot и Secretary Hint-план не потребляют.
- Legacy и English-first получают один контекст плана. Универсальная библиотека
  ответов не обходит его; выбор готового ответа делает текущий grounded Brain,
  без дополнительного модельного запроса. Формат подсказки/iOS не менялся.
- План не отменяет вопросы текущей беседы или исправления владельца, запреты
  disclosurePolicy и неизвестность. Само сохранение плана не ускорение, доказанное замером.
- Рекомендации языка не переключают системный язык приложения или голос Кати.

## После звонка

Существующая разрешённая лаборатория получает snapshot и отдельную инструкцию
описательной работы P.PREP: фактический вопрос → пункт плана → готовый ответ →
фактическая реплика → совпало/частично/нет/неизвестно. Независимый QA проверяет
те же основания; дополнительных платных проходов и нового агента нет.
Раздел входит в штатное письмо. Без успешной лаборатории семантическая оценка
не измерена; локальный бесплатный отчёт отмечает только точные текстовые совпадения.
Новая автономная роль P.PREP не включается, старый production STOP по её записи не обходится.

## База и Publish

Новая **пустая Dev**-таблица `hint_call_plans`, индексы и FK присутствуют в
`shared/schema.ts` и созданы в Dev. Production DDL не выполнялся.
В Publish ожидаются только CREATE этой таблицы/индексов/FK. При DROP/DELETE/ALTER
существующих таблиц остановиться и сверить экран, не подтверждать удаление.
«Copy development database to production» **не ставить**.
Вопрос согласованного срока хранения исторических snapshot отдельно от TTL
активного плана остаётся открытым: сейчас историю не удаляем.

## Проверить после Publish (без реального звонка)

1. Импорт OpenAPI в существующий GPT без смены OAuth.
2. Сохранить синтетический план Hint; проверить hash и expiresAt, затем тот же UUID.
3. Убедиться, что звонок не создан. Удаление/очистку production не выполнять.
4. Реальный звонок владельца — только по отдельному решению владельца.
5. Проверить использование snapshot, качество подсказок и письмо по реальным
   данным. До этого внешний GPT и пользовательский опыт не объявлять проверенными.

## Дальнейшие шаги к цели качества

1. Одна настоящая подготовка в ChatGPT → звонок владельца → независимый разбор
   P.PREP в существующей лаборатории: покрытие вопросов, готовность и совпадение
   ответов, промахи, полезность по отзыву владельца.
2. На фиксированном корпусе сравнить без плана / с планом при одной версии Hint:
   первое слово p50/p95, качество, доля реально применённых ответов, цена.
3. Только по данным предложить изменение PREP_PROMPT/ускорение прямого
   выбора готового ответа. Рабочее внедрение — отдельное «да» владельца.
4. Произвольные документы и дополнительные задачи через ChatGPT — отдельный
   явно согласованный контракт, без смешивания с Product Crew и без новых прав здесь.
