# Claude на Mac: все накопленные iOS-изменения — один итоговый TalkHint

Это ЕДИНСТВЕННОЕ актуальное задание на этот заход. Старые handoff по документам,
памяти, голосу и предыдущий черновик Hint — справка, не отдельные очереди сборок.
Аудит Claude Mac на `9c3341b`, 92/92 XCTest, принят владельцем.
Владелец принял независимый Mac-аудит всех 10 исправлений по `b4c79935`.
Текущая узкая дельта: очистка цели в CallManager на всех терминальных путях,
защита от позднего callback старого звонка и видимая причина readAloud.available=false.
Сначала новые целевые XCTest; затем одна итоговая сборка. Подробности:
`docs/ios-chat-audit-fixes.md` (новый первый раздел).
Replit добавил исправления Hint и native B–D; новые XCTest написаны, но
НЕ исполнены в Linux. Сейчас Claude независимо проверяет дельту и выполняет
целевые XCTest, включая три новых набора и ChatApprovedScreenTests.
Код продукта исправляет Replit, не проверяющий. ОДНА конечная сборка всего списка —
после успешных проверок и повторной read-only проверки уже опубликованного сервера.

### A. Готовый Hint

- Перед `TwilioVoiceSDK.connect` существующий API списка Hint-планов даёт
  план/хэш и утверждённую первую фразу. PREP не подменяется другим pending-планом.
- В Twilio передаются `HintPrepared`, выбранные `HintPlanId`/`HintPlanHash`;
  для PREP без сохранённого плана — `HintGoal`/opening. Сервер проверяет владельца,
  номер, срок и хэш. Испорченные планы пропускаются по одному. Preflight имеет
  timeout 1 с; ошибка/пустой ответ не приводит к `.failed`: сохраняется уже
  отфильтрованная по цели localOpening PREP, и только без неё — нейтральная фраза.
  Явная PREP-цель сохраняется, чужой план не присваивается.
- HintGoal/Opening/Translation ограничены по UTF-8 и общему URL-encoded бюджету
  800 байт вместе с To и именами параметров. Тексты карточек/сохранённый план
  не переписываются. Длинные id/hash не обрезаются: испорченная пара не отправляется.
  Twilio 31103 документирует 800 байт для JS, iOS API отдельный предел не называет:
  используем консервативное ограничение, не выдаём его за опубликованный iOS-лимит.
  https://www.twilio.com/docs/api/errors/31103
  https://twilio.github.io/twilio-voice-ios/docs/latest/Classes/TVOConnectOptions.html
- Без цели — нейтральное начало. Профессия/карточки не становятся причиной звонка.
- Первая фраза и новые подсказки — один нижний баннер, не второй блок сверху.
  Быстрые фразы тоже обновляют его, а не засоряют транскрипции.
- Проверить не только чистый selector, но и цепочку preflight → stage opening →
  реальный показ экрана/подключение: фраза должна попасть на экран до ответа
  собеседника, даже если экран был создан до завершения preflight.
- Приветствие Guest не отменяет подготовленную фразу; содержательное продолжение
  и речь Owner сохраняют защиту от устаревания.
- Свернуть перевод → смена подсказки сохраняет этот выбор в пределах звонка.
  Саму английскую фразу/точные числа не обрезать.
- Короткость/ответ одним известным фактом обеспечиваются сервером. Не дублировать
  модель в iOS и не выдумывать локальную тему.

### B. Копирование и читабельность — проверка реализованной дельты

- Внизу каждого ответа ассистента кнопка «Копировать»; копирует весь читаемый
  ответ, не служебные статусы, скрытые tool-сообщения или чужой контекст.
- Текст можно выделить. Адрес, телефон, email, номер документа и code-блок
  копируются отдельно, точным значением, без `**`, подписей и лишнего объяснения.
- Новое необязательное поле сообщения:
  `presentation = {revision:1, format:"markdown", copyItems:[{kind,value}], documentIds:[...]}`.
  `kind`: address / phone / email / reference / code. Будущие неизвестные kind
  не должны ломать декодирование всей переписки.
- Для старых сообщений без presentation оставить целое копирование и выделение.
  Не требовать повторного ответа модели или повторного распознавания документа.
- Markdown отображать читабельно, без видимых служебных `**`. Производное
  оформление не переписывает сохранённый текст. Числа, ведущие нули, переносы,
  адреса и содержимое code-блоков не «исправлять».
- Markdown только у ассистента. Fenced code проходит вне Markdown-парсера:
  переносы/отступы сохраняются в показе и целом копировании. Первые два copyItems
  имеют короткие подписи, остальные доступны через «ещё N»; код не дублируется
  полной строкой кнопки. Tap-тест использует подменный writer, НЕ general pasteboard.
- Только осознанный tap пишет в UIPasteboard; не читать буфер при открытии.
  Копирование не запускает звонок, письмо, навигацию, инструмент или платный запрос.
- UIKit/iOS 15: не использовать iOS 16+ edit-menu API без совместимого пути.
  Не добавлять новые экраны ради этих кнопок.

### C. Прослушивание — проверка реализованной дельты, не путать с Агатой

- Кнопки «Прослушать весь ответ» / «Стоп», один активный плеер.
  Никакого autoplay, чтения «по ходу» незавершённой генерации или автоматического
  возобновления после ошибки/прерывания.
- Это существующий ElevenLabs read-aloud (серверный голос Sarah,
  `eleven_flash_v2_5`), НЕ Retell/Merritt. Агату и её шар не переключать обратно
  на старую связку transcribe + ElevenLabs.
- Читать `GET /api/chat-v1/capabilities`, отдельное поле `readAloud.available/reason`.
  Показать честную недоступность. Не использовать `voiceMode.speech` как разрешение
  read-aloud: там другая функция. Ограничение owner/флаг/ключ не обходить.
- Только сохранённый собственный assistant-ответ `complete`:
  `GET /api/chat-v1/conversations/:id/messages/:messageId/read-aloud`
  возвращает `{revision:1,offsetEncoding:"utf-16",textHash,segments:[{offset,length}]}`.
  GET не генерирует аудио. Не пытаться озвучить failed/interrupted/hidden сообщение.
- На явный Play: один `playbackId` UUID на всё прослушивание; последовательные
  POST на тот же путь, тело СТРОГО
  `{requestId:UUID, playbackId:UUID, offset:Int, length:Int}`.
  `requestId` отдельный на сегмент; `offset/length` из manifest, максимум 600.
  Не добавлять text/language/provider/textHash: серверная схема strict.
- Offset — UTF-16 сохранённого исходного текста, не позиции в отрисованном
  Markdown и не Swift Character.count. Не пересекать surrogate pair.
  Сервер сам убирает Markdown и нормализует текст для речи.
- Ответ — **PCM s16le 24000 Hz mono, не MP3**. Переиспользовать безопасный
  нативный PCM-плеер/аудиополитику, не кормить эти байты MP3-декодеру.
  Проверять HTTP-статус/тип ответа; JSON ошибки не проигрывать как PCM.
  Эта версия получает целый ограниченный сегмент и заворачивает PCM в WAV для
  AVAudioPlayer: HTTP-чанки не режутся/не теряют нечётный остаток; итоговый
  нечётный размер отклоняется. Для чтения текста не включать микрофон/старый capture.
  Не смешивать аудио двух ответов; generation/token защищает от поздних callback.
- Стоп отменяет HTTP и очищает очередь/плеер. При звонке, запуске Агаты или
  аудиопрерывании уступить существующему владельцу аудиосессии; не деактивировать
  чужую CallKit/Retell-сессию. Bluetooth/наушники и speaker не ломать.
- Ошибки 409/429/503, READ_ALOUD_BUSY и неизвестный результат платного запроса
  объяснять, не повторять автоматически. Смена сообщения/аккаунта не продолжает
  старую озвучку. Не уходить самовольно на системный TTS.
- chatBinary сохраняет серверный error/code. UI выводит локализованное объяснение,
  не технический код; добавлены тесты ru/es/en (ключи есть также в kk/uk).
- Ключ ElevenLabs только на сервере. Дневной предел берётся из capabilities
  (сейчас сервер сообщает $5), не повышать. Автоматические проверки — $0,
  реальный Play проверяет сам владелец отдельно.

### D. Табличник — проверка реализованного native-минимума

- Выбор XLSX/CSV в существующих Files, до 10 МиБ. MIME/расширение и size-check
  должны работать также в upload/API, а не только в picker.
  API повторно читает capabilities; JSON без escaping слешей гарантирует, что
  даже base64 из 10 МиБ байтов FF помещается в выделенный серверный parser 14 МиБ.
  **Не поднимать** существующие фото/PDF-лимиты вместе с табличным лимитом:
  камера/HEIC→JPEG по-прежнему до 2 МиБ и примерно 2000 px.
- На сервере: максимум 20 листов, 100 колонок, 50 000 строк. Не ставить тяжёлый
  Excel-парсер/SDK в iOS; структурированную ошибку сервера показывать понятно.
- Список/поиск таблиц; экспорт XLSX и системное «Поделиться» через скачанный
  собственный временный файл. Не менять пользовательские колонки/формулы клиентом.
- Имя скачанного файла — безопасное название таблицы.xlsx; UUID только у
  временной папки. Подтверждённый failed/purged сбрасывает export attempt,
  явный Retry создаёт новый. Сетевая неизвестность сохраняет requestId/job.
  Ошибки показываются понятным текстом.
- Эндпоинты ниже относительно `/api/chat-v1`, все под обычным Bearer:
  - `GET /tables?search=...&offset=...&hidden=0`;
  - `GET /tables/:bookId`, `GET /tables/jobs/:jobId`;
  - `POST /tables/:bookId/export`:
    `{conversationId:UUID,revision:Int,requestId:UUID}` → 202 job;
  - `GET /tables/exports/:jobId/download` → XLSX;
  - `GET /tables/:bookId/export`: готовый текущий экспорт → 303 на download,
    иначе 409 `TABLE_EXPORT_REQUIRED` с `createExportUrl`; GET не создаёт задание.
- Для DTO списка/job проверить фактическую схему перед реализацией, неизвестные
  поля не ломают старый клиент. Не выдумывать result/download URL.
  Точный contract-snapshot лежит рядом: `ios-chat-server-contract-reference.md`.
- Redirect/скачивание только на доверенный origin; Bearer не отправлять
  произвольному сайту. Async job не объявлять завершённым до результата.
  Повтор запроса не плодит экспорт: сохранить requestId и учитывать revision.
- Строки и исправления — сразу по ясной команде в чате/Агате, ответ «Записал: …».
  **Без карточек, Save/Cancel и кнопок подтверждения таблиц.**
  Неоднозначность — короткий вопрос. Откат словами; журнал внутри.
- «Удалить таблицу» — сначала скрыть; окончательно стереть только по отдельной
  явной команде. Никакого автоудаления.
- Документ груза → строка таблицы НЕ включать: cargoRowContract остаётся контрактом.
  UI не делает суммы или выводы моделью — вычисляет серверный код.

### E. Сохранить уже работающие память/документы/Агату

- Память человека: отдельная карточка «было → станет», Save/Cancel,
  expired после 24 часов, stale при смене исходной записи; голосовое «да» не Save.
- Грузовые и прочие документы: сервер сохраняет в архив без Save; ответ
  «Сохранил: …» + короткая сводка. Это не профиль, не контекст звонка и не строка.
  Не ограничивать неизвестные типы enum из четырёх документов.
- Камера/Фото активны; HEIC→JPEG/ориентация/лимит сохранены. Поля документа
  редактируются в существующем разрешённом потоке, без переписывания оригинала.
- Исправление EXIF absent=up в ChatAttachmentImageTests уже в базе; не терять.
- Не включать старый голос вместо Агаты, не менять агента Кати, номера, маршруты,
  модели, Push, фоновые исполнения или структуру органов AI Crew.
- Не обещать push-напоминание: существующие напоминания документов доставляются
  в чате при открытии, не на закрытый телефон.
