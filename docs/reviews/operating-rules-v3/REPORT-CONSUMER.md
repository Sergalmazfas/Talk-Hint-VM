# Офлайн-проверка потребителя P.OPS

Это проверка вычислений, **не утверждение схем**, не наблюдение production
и не запуск дежурства. `manualPass`, `trialProtocol`, доступы, crew, расписания
и рассылки не меняются.

## Воспроизведение

```sh
npx vitest run server/projectModel/oncallRole.test.ts
```

Тест создаёт документы существующим `prepareOncallRole`, передаёт их и структуру
в `scripts/test_ops_report.py`. Python применяет **те же функции diff**, которые
использует `scripts/operating_rules_review.py`: `report_form_patch` и
`report_packet_patch`. Проверяются сохранённая форма v1/пакет v2 и кандидат
формы v2/пакет v3. Внешний снимок модели, БД и секреты не нужны.

Потребитель: `scripts/ops_report.py`. Он не подключён к серверу/агентам.
Для ручного расчёта из локального экспорта:

```sh
python3 scripts/ops_report.py --input /path/to/local-envelope.json
```

Входной JSON: `{ "packet": <рабочий пакет>, "form": <форма>, "inputs": <факты> }`.
Здесь только описание конверта, не новая копия канонических бланков.
Результат — JSON в stdout; ошибка схемы/периода — ненулевой exit code.
Никаких отправок, записей в модель и повторов доставки.

## Факты и границы расчёта

- `inputs`: явные `periodStart`, `periodEnd`, `asOf` с часовым смещением,
  `timezone`, `environment`, `period` (`day`, `week`, `month`).
  Период закрытый для расчёта, интервал наблюдений `[start, end)`.
- `freshnessSeconds` задаёт вызывающий код как проверяемую политику;
  это **не утверждённый SLA**. Без порога свежесть неизвестна.
- `observations`: ключ `domain:<supplierActionId>` либо `system:<system>`,
  окружение, `source`, `sourceConnected: true`, `observedAt`, `evidenceUrl`,
  фактический `status`. Код watchdog в карте не считается runtime-наблюдением.
  Отсутствующие и неоднозначные входы остаются отдельными строками с поставщиком.
  Для кандидата v2 карта обязательна: все десять поставщиков сверяются с пакетом,
  все десять систем — с тем же каноническим предложением генератора diff.
  Удалённые, подменённые и дублированные элементы схемы приводят к отказу расчёта,
  а не к сокращению знаменателя или подстановке формы v1.
- Намеренная пауза: `pause.intentional: true`, `start`, `end`, `evidence`;
  для статуса всего периода пауза должна покрывать его целиком.
  Частичная пауза не скрывает остальной непроверенный период.
- `results`: исходные строки с `resultId`, `version`, `environment`,
  `observedAt`, `supplier`, `evidenceUrl`, числовыми `expected`/`actual`,
  явной `acceptance` (`accepted`, `returned` или неизвестно).
  `dailyReports[].results` содержит **те же первичные строки**, не дневные суммы.
  Дедупликация — по ID+версии+окружению; разные версии остаются разными результатами.
  Противоречивый дубль остаётся неизвестным с причиной.
- План-факт: сумма исходных числителей / сумма знаменателей.
  Пропуск, неизвестное число, пустой период и нулевой знаменатель не дают процент.
  Известные подытоги показываются отдельно и не объявляются полным итогом.
  Дневные проценты не используются; сводка без исходных строк отмечает пробел.
  Если хотя бы один ожидаемый источник неизвестен, полные итоги также `null`:
  известные результаты остаются подытогами, а не «100% всей системы».
- `systemSummary` описывает **только наблюдаемые системы**, не приёмку работ
  и не готовность дежурства. Неизвестное покрытие показано отдельно даже при сбое.
  `coverage` — доля подтверждённых наблюдений относительно предоставленной карты,
  не утверждение полноты всей компании. Норматив KPI не назначается.
- `delivery` использует прежние `savedVersion`, `providerId`, `sentConfirmed`,
  `ownerRead`, `acceptedBy`. SENT подтверждает только транспорт.
  Строки без приёмки остаются в `pendingAcceptance`.

Фикстуры покрывают отсутствие источника, устаревание, паузу, неизвестный
знаменатель/числитель, разные веса процентов, недельные/месячные дубли,
разные окружения/версии, конфликт дублей, отсутствие исходных дневных строк,
SENT без приёмки, несовместимость схем, неизменность исходников.

Подключение к реальным источникам и сверка с утверждёнными в модели версиями
требуют отдельного этапа после согласования схем. Эти тесты его не имитируют.
