# Отдельный плагин TalkHint для официального ChatGPT

**Актуальный путь для Plus/iPhone — опубликованный каталог, не ручной custom MCP.**
См. [пакет подготовки к публичному review и действия владельца](talkhint-plugin-public-review.md).
Раздел custom MCP ниже — только техническая developer-инструкция для
поддерживающих её аккаунтов, не инструкция установки для владельца на Plus.

Проверено **19.10.2026**. Это продолжение существующего OAuth/MCP-адаптера,
не новый чат и не отдельное iOS-приложение. Route Leader — только пример
подключаемого UX. Его данные, серверы и разрешения не используются.

## Что готово в коде

- Отдельная идентичность **TalkHint**, функции Secretary.
- Тот же защищённый remote MCP `/api/chatgpt/mcp`: `get_profile`,
  `list_calls`, `get_call`, `list_tasks`, `get_task`.
- Прежний OAuth authorization code + PKCE S256, точные client/redirect/resource,
  персональные разрешения, refresh rotation и отзыв доступа.
- Дополнительное разрешение `calls:transcript` для текста разговора.
  Первичное подключение запрашивает минимум `calls:read offline_access`.
- Метаданные переносимого remote-MCP плагина:
  `/api/chatgpt/plugin.json` и `/api/chatgpt/mcp.json`.
  В них нет ключей, owner session или фиксированного bearer token.
- Защищённый отдельный раздел **Secretary**:
  `/api/chatgpt/secretary`, со списком до 50 последних задач и звонков,
  итогами, статусами и ссылками на подробности.
- Детали `/api/chatgpt/secretary/tasks/:id` и
  `/api/chatgpt/secretary/calls/:id`. Транскрипция не загружается автоматически:
  для неё есть отдельная ссылка. Текст экранируется, скрипты не исполняются.

Метаданные **не регистрируют** приложение в аккаунте OpenAI или публичном
каталоге. Название при создании отдельного подключения следует выбрать TalkHint.

## Где остаются события и отчёты

Источником истины остаётся существующий backend TalkHint и его PostgreSQL,
не переписка ChatGPT и не временный WebSocket:

- задача, request ID, номер, задание и текущий статус — `secretary_tasks`;
- native call ID/provider status, попытки и сохранённые временные отметки —
  существующие поля задачи и `calls`;
- summary, outcome, verified facts, next step, transcript/turns —
  существующая запись отчёта Secretary.

`get_task` дополнительно возвращает `events` с
`eventCoverage: "saved_checkpoints"`: создание задачи, сохранённые попытки,
окончание потока и снимок текущего состояния. Это проекция **реальных
сохранённых полей**, а не выдуманный полный журнал всех переходов.
Полный неизменяемый аудит всех OAuth/HTTP-событий не добавлялся.

Итог звонка показывается только из связанного **собственного** отчёта
Secretary. Если сохранённого итога нет, это указано явно; новый AI-summary
при чтении не генерируется. Новые таблицы и миграции не требуются.

## Исходящее поручение — подготовлено, но реальные вызовы не включены

1. По явной команде текущего пользователя `prepare_call` принимает точный US
   +1 номер, задание и UUID `clientRequestId`.
2. Возвращает ограниченное по времени `confirmation` и зашифрованную
   `approval_url`. Набора нет, queued job не создаётся.
3. По ссылке владелец отдельно входит в TalkHint, проверяет **номер и
   задание**, нажимает подтверждение или отказ.
4. Страница сама не набирает номер. После подтверждения пользователь
   возвращается в ChatGPT, который может вызвать `start_call`.
5. Сервер проверяет владельца/подключение/expiry/отказ/approval и использует
   существующий persistent idempotency/lease Secretary.
6. Возвращается `task_id`. Повтор того же request ID возвращает ту же
   задачу, а не новый звонок; результат читается через `get_task`.

`confirmed:true`, настройка Allow all tools, инструкции из транскрипции или
заявление модели «пользователь подтвердил» не заменяют пункт 3.
Отказ не обходится старым owner API. Изменённые номер/задание не могут
использовать прежнее подтверждение.

Честная гарантия при сетевых сбоях — один выигравший запуск без автоматического
повторного набора. Если неизвестно, принял ли провайдер запрос, задача остаётся
unknown/starting до reconciliation; нельзя обещать математическое exactly-once
внешнего телефонного эффекта и повторять звонок ради получения ответа.

**Рабочая композиция по умолчанию остаётся read-only.**
Исходящие инструменты включаются только отдельным явным режимом. В этом этапе
они проверялись исключительно с mock dialer, не с настоящей телефонией.
Автоматического отчёта обратно в исходный чат нет: task_id + последующее чтение.

## Как подключить отдельно в официальном ChatGPT web

Открыть [Plugins в ChatGPT](https://chatgpt.com/plugins).

1. Убедиться, что аккаунт/workspace разрешает custom MCP.
   По текущей документации полный MCP/write — Business/Enterprise/Edu с
   соответствующими правами; Pro допускает read/fetch. Политику конкретного
   аккаунта нужно проверить в его интерфейсе.
2. **+ → Add custom MCP server**. Имя — **TalkHint**.
3. Указать **активный тестовый HTTPS endpoint**:
   `https://<согласованный-тестовый-домен>/api/chatgpt/mcp`.
   Это шаблон, не действующий адрес. Нельзя подставлять production без
   отдельного разрешения. Тестовый сервер должен работать, а интеграция —
   быть явно включена оператором.
4. Выбрать OAuth, predefined/provided public client:
   client ID `talkhint-chatgpt`, token endpoint auth `none`.
   Client secret в этом flow отсутствует. Не передавать ChatGPT собственную
   сессию TalkHint, пароль или API-ключи телефонии.
5. После создания/сканирования скопировать **точный OAuth callback**,
   показанный OpenAI, в allowlist конфигурации тестового TalkHint.
   Не угадывать callback и не разрешать wildcard.
6. Для первоначального scan предусмотрен безопасный bootstrap: до настройки
   callback доступны только discovery, plugin metadata и initialize/tools-list.
   Чтение данных, выдача grant, login и звонки в этой фазе запрещены.
7. Пройти OAuth в браузере TalkHint: существующий аккаунт, проверка своего
   аккаунта и scopes, явное «Разрешить». Для Google/Apple можно использовать
   существующий web-вход и явный same-origin session bridge; отдельная
   проверка реального браузера ещё требуется.
8. Подтвердить предупреждение доверия и выбрать **Create as a plugin**.
   Проверить обнаруженные инструменты и установить отдельный TalkHint.
   Порядок OAuth/scan в конкретном интерфейсе OpenAI может отличаться.
9. В новом разговоре выбрать `@TalkHint` и попросить:
   «Покажи мои последние задачи Secretary и сохранённый итог завершённой».
10. Проверить отзыв в `/api/chatgpt/connections/manage`: старый доступ
    должен перестать работать. Обновление tool metadata требует Refresh.

Это документально подтверждённый путь интерфейса, **не свидетельство
выполненной установки в вашем аккаунте**. В текущем этапе не создавались
реальное подключение OpenAI, публичный listing или production deployment.
Пока тестовый HTTPS-стенд не активирован и callback не настроен, подключение
из ChatGPT остаётся заблокированным.

Переносимые JSON-файлы пакета не являются универсальной кнопкой установки
на iPhone. Для публичной подачи OpenAI требует remote HTTPS MCP endpoint,
review и отдельные сведения, включая privacy/terms/брендовые материалы.
Такая подача не выполнялась.

## iPhone — отдельное ограничение

Официальная справка custom MCP прямо говорит: **web-only**.
Каталог опубликованных Plugins доступен на mobile, но не все действия и
плагины доступны на каждом клиенте/плане/workspace.

Следовательно, отдельный плагин TalkHint — правильная структура продукта,
но наличие manifest/OAuth и успешные mock-тесты **не доказывают работу
в официальном ChatGPT на iPhone**. Нужна реальная проверка допустимого пути
распространения и конкретного аккаунта. Публикация — только после согласования.

## Проверки и исключения

- Изолированные HTTP OAuth/MCP/browser тесты без настоящей БД/провайдеров:
  `npm run test:chatgpt-secretary`.
- Полный существующий набор: `npm test`.
- TypeScript: `npm run check`.
- Вёрстка — отдельный render-only fixture; это не тест внутри ChatGPT/iPhone.
- Нативный iOS, обычные телефонные маршруты, голос и входящие webhooks
  не изменялись. Нет SMS, покупки номеров, реальных звонков или публикации.

Результат текущей проверки: **62 изолированных теста прошли**;
полный набор — **1330 тестов в 106 файлах прошли**.
TypeScript и `git diff --check` прошли. В полном наборе есть существующие
development PostgreSQL-тесты с синтетическими записями и cleanup; это не
проверка production. Проверены и прежний legacy `/start-call`, и mock-сценарий
OAuth → отдельное подтверждение → один выигравший dialer → task_id → результат.
Дополнительно проверены изоляция истории, запрет auto-transcript, чужие
task/call ID, безопасный bootstrap до callback и собственные summary-связи.
