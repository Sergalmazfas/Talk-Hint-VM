# Пилот Hint · после сверки и Publish

**Сейчас этот план не выполнялся. OFF/0 сохраняются.**

1. Клавдий проверяет ZIP: код, приватность SELECT/проекции, бюджет 2000 токенов,
   фактическую цепочку разных исполнителей и тесты. Publish делает владелец,
   без Copy development database to production.
2. [Открыть панель владельца](https://talkhint.app/admin/ai-crew).
   «Обновить», проверить OFF/0 и отсутствие запусков/расписаний.
   Новая схема БД для пилота не требуется; прежний probe не повторять.
3. [Посмотреть обезличенную выдержку и предложенные ставки](https://talkhint.app/api/admin/ai-crew/hint-pilot).
   Это GET, никакого запуска. При ошибке ничего не подставлять вместо данных.
4. Владелец выбирает одного из трёх кандидатов и подтверждает
   [официальные цены](https://platform.claude.com/docs/en/about-claude/pricing#model-pricing).
   До подтверждения не писать даже подготовку пилота в production.
5. В существующем JSON-редакторе «Команда» на панели (либо через защищённый owner API,
   тот же Origin+CSRF и свежая revision) подготовить:

   `{"kind":"hint_pilot_prepare","candidate":"latency","ratesConfirmed":true}`

   Другие кандидаты: usefulness / unavailable. Ответ → повторное чтение состояния:
   одна задача analysis, hintPilot.status=prepared, SHA снимка, два описания,
   control OFF/0, runs=[], schedules=[]. При расхождении/неясном ответе — STOP,
   не повторять запись вслепую. Это НЕ смена штатных промптов сотрудников.
6. Передать результат владельцу. **Остановиться до отдельного «да» на запуск.**

## Только после отдельного разрешения запуска (не часть текущего этапа)

Owner-only API `/api/admin/ai-crew/command` принимает `{revision,command}`,
CSRF из GET `/api/admin/ai-crew`, same Origin; перед каждым POST — свежее чтение,
после — повторное чтение. Прямая активация в JSON-редакторе панели намеренно
заблокирована прежней защитой: нужен отдельный согласованный owner API шаг,
а не обход панели или выдача её ограничений за отсутствие API.

- владелец задаёт `control` enabled=true, согласованный дневной лимит microUSD;
  код сам лимит не выбирает, 0 запрещает запуск;
- `{"kind":"hint_pilot_start","taskId":"<UUID из чтения>","ownerApproved":true}`;
- проверить Пашу done/proposed → Фому done/proposed → verdict для владельца;
  задача analysis не закрывается автоматически;
- общий «Отключить» останавливает цепочку. После опыта вернуть OFF/0,
  прочитать usage, фактическую цену, резервы unknown и ограничения.

Не добавлять расписания, не запускать другие задачи. Не повторять unknown.
