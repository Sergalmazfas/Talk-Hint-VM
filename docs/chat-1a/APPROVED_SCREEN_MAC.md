# Утверждённый экран Chat — изолированная проверка на Mac

## Важно

Это **нативный UIKit-экран в существующем проекте**, не HTML и не новый
дизайн-макет. В этой среде нет macOS/Xcode: **Swift ещё не собран и реальных
скриншотов этой реализации пока нет**. Статические проверки не заменяют
сборку/просмотр на Mac. Не считать экран визуально принятым до решения владельца.

Основа — именно отдельный крупный
`0_IMG_4200_1793933763767.jpeg`, 960×1517, присланный владельцем после уточнения.
Общий рисунок с четырьмя телефонами — только контекст. Последние мелкие
технические концепты не использованы.

## Что сделано

- Добавлен явный вариант `.approvedReference` существующего ChatViewController.
  Он использует прежние обработчики сообщений, ошибок, загрузки, диктовки,
  отмены, проверки текста и отправки. Сервер/API не переписаны.
- Крупные сообщения, зелёный/светло-фиолетовый фон, нормальная плотность.
- Шапка: круглая стрелка назад, folder + TalkHint Chat, многоточие.
  **Многоточие отключено, бокового меню в этом варианте нет.**
- Капсула ввода: плюс, текст, микрофон, отправка при наличии текста.
  Отдельная чёрная кнопка справа — неактивный Voice Orb, без обработчиков.
  Мелкая подпись под Orb в новом варианте убрана, как в образце.
- Нижних вкладок внутри экрана нет; поле привязано к keyboardLayoutGuide.
- Используются системные шрифты/Dynamic Type, светлая/тёмная тема,
  локализации EN/ES/RU/KK/UK. Текст UI не зафиксирован на русском.
- Новый вариант **не подключён к центральной вкладке**. Существующая функция
  `makeMainTabController()` и ChatNavigation не изменены. Предыдущая Dev-
  навигация остаётся как была; это не её повторное внедрение или одобрение.
- Для просмотра добавлена отдельная build configuration/scheme в том же
  iOS target: `ChatPreview` / **TalkHintChatPreview**.
  При её запуске пропускаются обычные auth/телефонные/push стартовые пути.
  Обычная и Release-схемы новый предпросмотр не запускают.

## Конкретные UI-параметры

Это стартовые UIKit-параметры, **оценённые по пропорциям рисунка**, а не
доказанные исходные значения дизайнера. Нормализация ширины экрана к 390 pt —
допущение. Шрифт по JPEG точно определить невозможно.

| Элемент | В реализации при обычном размере текста | Статус |
|---|---:|---|
| Сообщения | SF system regular 20 pt + UIFontMetrics | Оценка по образцу; проверить переносы на Mac |
| Заголовок | System bold 20 pt + UIFontMetrics | Оценка |
| Поле ввода | System regular 19 pt + UIFontMetrics | Оценка |
| Дата | 13 pt + UIFontMetrics, локальный формат | Оценка |
| Боковые поля переписки | 16 pt от safe area | Из пропорций, округлено |
| Между сообщениями | 14 pt | Из пропорций, округлено |
| Внутри пузыря | 16 pt по горизонтали, 12 pt по вертикали | Из пропорций |
| Радиус пузыря | 22 pt, continuous | Оценка |
| Максимальная ширина | user 80%; assistant 85%; конечный ответ 96% ширины переписки | По разным пузырям образца |
| Кнопки back / more / plus / mic / send | hit target не меньше 44×44 pt | Явный UIKit-параметр |
| Иконки plus / mic | 24 pt, не только увеличенная область нажатия | Оценка |
| Orb | 48×48 pt; waveform 24 pt, белый | Явный параметр |
| Зазор капсула → Orb | 10 pt | Оценка |
| Капсула | одна строка 56 pt; grows до редактора 120 pt + insets | Проверить на маленьком экране |
| Радиус капсулы | 28 pt | Оценка |
| Keyboard / safe areas | реальные системные guides, без нарисованной клавиатуры | Требует UIKit runtime |
| Фоны пузырей | примерно #ECFAE0 / #F3EFFF | JPEG-сэмплы, не исходные цвета дизайнера |

В таблице измерений `APPROVED_SCREEN_MEASUREMENTS.md` координаты приведены
от края JPEG. Для положения относительно экрана нужно вычесть левую границу
дисплея ≈50 px, затем делить на ≈2.28 px/pt. Например, левое поле пузыря:
(89−50)/2.28 ≈17 pt → в коде 16 pt. Верх исходного телефона обрезан:
высоту status bar / notch / safe area по нему не выдумываем.

Это сопоставление параметров, **не подтверждение пиксельного совпадения**.
Примерный рисунок не позволяет доказать точный шрифт и межстрочный интервал;
в реализации оставлен системный line height. Проверить переносы, последний
пузырь, баланс шапки и контраст на настоящем Simulator до принятия.
Стандартный copy-glyph из рисунка не добавлялся как новая функция сообщения.

## Как открыть на Mac

ZIP содержит **полный текущий ios/**, а не только отдельные Swift-файлы.
Распаковать **в новую папку**, не поверх рабочей копии Mac.
`BASE_REVISION.txt` и patch нужны лишь для сверки/переноса в основной репозиторий.
Не применять patch без проверки базовой версии.

Из распакованной папки:

```sh
cd ios
xcodegen generate --spec project.yml
open TalkHint.xcodeproj
```

В Xcode:

1. Scheme → **TalkHintChatPreview** (не обычная TalkHint).
2. Destination → **iPhone Simulator**, не настоящий телефон.
3. Product → Run (⌘R).
4. На служебном экране прочитать предупреждение и нажать
   «Открыть пример переписки» / Open sample conversation.
5. Стрелка назад возвращает на служебный экран предпросмотра.

Для языка: Edit Scheme → Run → Options → App/Application Language:
Russian / English / Spanish. Это системный механизм Xcode; новый переключатель
языка в приложении не добавлен. Для темы — Simulator → Features → Toggle Appearance.
Если программная клавиатура не показывается, отключить Connect Hardware Keyboard
или включить Toggle Software Keyboard в меню Simulator.

### Что означает локальный предпросмотр

Это **демонстрационные данные без сервера**, не «работающий AI».
В отдельном экране явно указано: AI, STT и загрузки отключены; соответствующие
capabilities false. При попытке отправки fixture transport возвращает ошибку,
а не выдумывает ответ модели. URLSession/провайдер не вызываются.
Текст можно набрать/исправить. Реальная запись с микрофона в этой fixture-
схеме недоступна; «Запись» и «Распознавание» — явно именованные UI-состояния,
без записи аудио и запросов распознавания. Волна в fixture — фиксированный
уровень для визуальной проверки. В настоящем обработчике она по-прежнему
питается AVAudioRecorder.averagePower, без синтетической замены.
Сохранение sample-черновиков изолировано от реального пользователя/истории.

Прежние Dev-обработчики сохранены, но настоящее STT/AI на этом шаге не проверялось.
Не изменять API-сервер на production для проверки. Подключение нового вида
к обычному чату — только после отдельного согласования.

## Реальные скриншоты и одинаковый масштаб

На Mac открыть нужное состояние. В Simulator **File → Save Screen** / ⌘S
сохраняет настоящий экран вместе с системной клавиатурой.
Либо из корня распакованной папки:

```sh
bash ios/scripts/capture-chat-approved-preview.sh
```

Нужен ровно один booted Simulator; при нескольких передать его UDID первым
аргументом. Скрипт **только снимает уже открытый экран**, не запускает
приложение, тестовый разговор, AI или STT.
Он сохраняет оригинальный native PNG и два отдельных крупных изображения
одинаковой ширины 1170 px: утверждённый оригинал и реальный native screenshot.
Не микроскопический коллаж. Верх рисунка обрезан, поэтому автоматический
pixel-diff не считается приёмкой.

## Проверки

В Replit:
- 31 Python source-contract test — пройдено; это не исполнение Swift.
- `git diff --check`, синтаксис Python verifier и shell scripts — проверены.
- Попытка `validate-native.sh` честно остановилась: требуется macOS/Xcode.
- Сервер, Retell, телефонные обработчики и штатная сборка вкладок не менялись.

На Mac:

```sh
bash ios/scripts/validate-native.sh
```

В полный набор включены 6 новых `ChatApprovedScreenTests`; обязательность
проверяет verify-xcresult. Это пока **не выполненные** здесь XCTest.
Они проверяют opt-in стиль, отсутствие меню/вкладок, hit targets на 320 pt,
неактивный Orb, отмену UI-записи, editing/keyboard guide, и сохраняют
крупные UIKit attachments в xcresult.
UIView attachments **не включают отдельное системное окно клавиатуры** —
для полной картинки нужна ⌘S/simctl screenshot. Микрофон/разрешения/STT
не тестируются этими screenshot-fixtures.

Не выполнять Archive/TestFlight/Publish. После просмотра владельцем —
**остановиться и ждать отдельного «добро»**.
