# TalkHint Chat 1A — реализация и границы проверки

## Что сделано

| Область | Реализация |
|---|---|
| iPhone | Chat между Translator и Secretary; существующие Hint, Translator, Secretary и History сохранены. Copilot не возвращён. |
| Интерфейс | Светлый чат по макетам владельца, зелёные/фиолетовые акценты, новый разговор, недавние разговоры в боковом меню, сообщения, текстовый ввод. |
| Будущие разделы | Календарь, записная книжка, задачи, файлы, почта, карточка, подключения и тариф обозначены как недоступные на этом этапе. Projects нет. |
| История | PostgreSQL: `chat_conversations`, `chat_messages`, `chat_attachments`. Сохранение только в настоящую БД; без Map/fallback и без PREP-истории. |
| Порядок и повторы | Последовательности выдаются транзакционно, owner-level lock; уникальные request IDs и проверка совпадения содержимого. Один активный ответ пользователя, повтор HTTP не запускает новую модель. |
| Ответ AI | Существующая модель PREP `gpt-5.6-sol`, Responses API, потоковые дельты, без tools, автоматических повторов и provider-side хранения ответов. PREP-сценарии и их состояния не изменены. |
| Контекст | Только текущий разговор: до 24 завершённых сообщений и 18 000 символов истории. Незавершённые ответы исключены. Никакой фоновой памяти из других чатов/профилей. |
| Поток на iPhone | Чтение сохранённых частичных ответов с интервалом около секунды, пока ответ активен. Это не SSE: сервер сохраняет дельты с интервалом около 150 мс. |
| Восстановление | Потеря HTTP-соединения не отменяет уже принятый ответ. После потери процесса lease истекает, ответ становится interrupted; автоматической повторной генерации нет. |
| Вложения | Приватное App Storage, owner-bound metadata и скачивание через авторизованный API. TXT UTF-8, PNG, JPEG, PDF до 2 MiB, до трёх файлов на сообщение. Проверка формата/сигнатур, не выполнение содержимого. |
| Голос | Существующий STT preparation API; расшифровка возвращается в редактируемое поле и не отправляется автоматически. Работа микрофона изолируется от телефонного аудио. |
| Локализация | en/ru/es/kk/uk по системному языку iPhone; не по профессии или языку подсказок. |

### Что не внедрялось

Этапы 1B/1C/1D, подтверждаемая общая память, карточки как предметные операции,
вызовы Hint/Секретаря, Gmail, поиск, геолокация, календарные события и задачи.
Существующие маршруты звонков и Retell, голос, модели и правила Кати не менялись.
Нет нового телефонного движка. Production не опубликован.

Новый чат не даёт модели ни собственных credentials, ни возможности вызвать
внешнюю функцию. Запрос клиента не может задать userId, роль или инструменты.

## API

Префикс: `/api/chat-v1`; существующий `/api/chat` не используется.
Авторизация — существующая app session/Bearer; scoped credentials внешних
интеграций не расширяют доступ. Изменяющий запрос браузера дополнительно
требует совпадения Origin и `X-TalkHint-Chat: 1`; чужой Origin отклоняется.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/capabilities` | Готовность модели/STT и приватного хранилища, типы и предел размера файлов |
| GET / POST | `/conversations` | Список / идемпотентное создание |
| GET | `/conversations/:id/messages` | Последняя страница, более ранние через beforeSequence |
| POST | `/conversations/:id/messages` | Сохранить пользовательский ход и одну заготовку ответа |
| GET | `/conversations/:id/messages/:messageId` | Состояние существующего ответа, без новой генерации |
| POST | `/attachments` | Проверить и сохранить файл |
| GET | `/attachments/:id/info` | Собственные метаданные |
| GET | `/attachments/:id` | Собственное скачивание, attachment + nosniff + no-store |

Conversation/message/attachment IDs и clientRequestId — UUID. Входные UUID
нормализуются для совместимости с iOS. Изменение содержимого под уже
использованным requestId даёт IDEMPOTENCY_CONFLICT, не перезаписывает историю.

Новая файловая библиотека не внедрена. Удаление вложения из черновика не
является удалением объекта из хранилища или из уже отправленных сообщений.
Политику удаления/сроки хранения нужно утвердить отдельно.

## Реальные проверки

- **25 новых автоматических проверок прошли**, 4 файла тестов. Включая
  настоящую Dev PostgreSQL: параллельный дубликат, порядок, повторное чтение
  новым экземпляром repository, оборванная генерация, чужие сообщения/файлы,
  HTTP → сохранение → поток тестовой модели → повторное открытие.
- **37 существующих проверок прошли**: native wiring профилей, подготовленные
  Hint-планы, Translator, каналы push, аудиограницы Секретаря.
- Дополнительно предыдущий прогон фильтра `server/chat` включил
  **208 проверок** вместе с соседними ChatGPT-модулями, без ошибок.
  Эти числа частично перекрываются; их нельзя суммировать.
- `npm run check` — TypeScript без ошибок.
- Приватное App Storage: реальная запись и чтение маленького синтетического
  файла, совпадение байтов подтверждено. Удалён только созданный для этой
  проверки тестовый объект; пользовательские файлы не читались и не удалялись.
- **Один реальный текстовый запрос** к модели на синтетическом сообщении:
  ответ `CHAT_1A_OK`, завершён, 165 входных + 9 выходных = 174 токена.
  Повторов не было. Request ID: `req_6a38b587a2ea49cb841e33147e1f0078`.
  Это проверка доступности модели/потока, не оценка качества диалога.
- После перезапуска Dev-сервера новый API без авторизации вернул **401**.
- Новая схема применена **только в Dev**, только CREATE TABLE/INDEX.
- Предпросмотр прошёл отдельные TypeScript/build-проверки и просмотр
  в размере 402×874: главный экран и все пять нижних вкладок видны,
  ошибок браузера при загрузке нет. Это визуальная, не native-проверка.
- В пяти языках совпадают 44 ключа Chat; отсутствующих строковых ключей
  в новых native-файлах не найдено.

Платные звонки, репетиции, письма, календарные записи и production-операции
не запускались. Запрос настоящей текстовой модели указан отдельно выше.

### Что этим НЕ доказано

- Xcode-компиляция, XCTest и поведение микрофона/клавиатуры/QuickLook на
  настоящем iPhone. Linux не имеет Xcode/UIKit; native-тесты добавлены,
  но их нельзя объявлять прошедшими.
- Реальное чтение изображений/PDF этой моделью не проверялось отдельными
  платными запросами. Файловые ограничения, хранение, приватность, HTTP и
  структура модельного запроса проверены отдельно.
- Это не полный серверный набор проекта и не нагрузочный аудит.
- Не проверялся production и не менялась версия установленного на iPhone приложения.

## Предпросмотр и согласование

Интерактивный preview `ChatFoundation` воспроизводит интерфейс и состояния.
Его сообщения — демонстрационные; он явно это обозначает и не выполняет
запросы к модели или настоящим пользовательским чатам. Он нужен для
визуального согласования и не заменяет функциональную проверку iPhone.

Реальный защищённый API подключён в native-коде. Техническое принятие iOS
требует Mac-проверки по `MAC_HANDOFF.md`, затем ручной проверки владельца
в Dev, не на production-сервере.

## Изоляция и ограничения

Частичные ответы сохраняются не на каждый токен; при аварии процесса
последние примерно 150 мс текста могут не сохраниться, такой ответ помечается
незавершённым. Сервер не сообщает о полноценном ответе до его сохранения.

Технические защиты 1A: до 60 новых пользовательских ходов в час; один
активный ответ на пользователя; до 200 файлов/100 MiB приватных вложений на
пользователя. Это не настройки телефонных звонков и не бюджет отдела.

Статусы ready/available — проверка конфигурации/хранилища, не обещание
безотказности внешнего поставщика. Ошибки возвращаются явно; другой моделью
они не подменяются. Истечение или неизвестный исход не вызывает повтор.
