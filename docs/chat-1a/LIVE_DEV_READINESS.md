# Chat 1A — перенос Mac → Dev и реальное подключение

Внешний вид принят владельцем. Четыре исправления Mac перенесены:
crash/constraints, scroll layout, initial draft, readiness-aware XCTest.
Их исходники сверены с blob IDs патчей:
`665bf85` (контроллер без добавленного live factory) и `45971f5` (тесты).

## Проверено на настоящем Dev-сервере

`npx tsx scripts/probe-chat-dev.ts` (без `--model`):

- неавторизованный запрос → 401;
- нормальная регистрация и Bearer auth синтетических Dev-пользователей;
- capabilities: AI/STT доступны по наличию ключа; App Storage доступен;
- создание разговора и повтор с тем же clientRequestId → один ID;
- HTTP readback + отдельное чтение PostgreSQL;
- другой пользователь → 404 для чужого разговора/файла;
- загрузка/скачивание реального txt-файла из App Storage;
- удалены только созданные smoke-тестом аккаунты, записи и файл.

`CHAT_DB_TESTS=1 npx vitest run server/chat --maxWorkers=1`:
20 файлов / 209 тестов прошли, включая opt-in PostgreSQL integration.
36 Python source-contract checks прошли. Native gate helper checks: 28 passed.

## Один реальный AI-запрос — проверен с разрешения владельца

После отдельного разрешения «Да, максимум $0.50» выполнен один вызов через
настоящий Dev API (не напрямую к SDK): запрос с синтетическим txt-вложением,
ответ `green-42`, статус `complete`. Модель `gpt-5.6-sol`,
166 input / 7 output tokens, reasoning 0. Usage и provider request ID
получены и проверены в БД до удаления тестовых данных.
Повтор HTTP с тем же clientRequestId вернул тот же reply ID; в истории
ровно два сообщения. Дополнительной генерации не было.
Точную сумму счёта провайдера эти токены сами по себе не подтверждают.

## Не выдавать за проверенное

Доступность STT в capabilities — проверка конфигурации, не успешная
расшифровка. STT не вызывался. Разрешён только один AI-запрос, не серия.
Новая схема `TalkHintChatLiveDev` подготовлена, но её native build, запуск
в Xcode/на iPhone, настоящий микрофон и UX на сервере ещё требуют Mac-проверки.
259/259 в полученном архиве — доказательство старого Mac HEAD, не новой схемы.

Схема отдельно устанавливается, требует Dev HTTPS origin, не стартует push
и телефонные провайдеры, использует принятый внешний вид без изменения меню.
Новая авторизация остаётся реальной: нет встроенных токенов или auth bypass.

Production, Retell, Катя, голос, модели звонков и рабочая навигация не менялись.
Публикации и звонков не было. Модель Chat — существующая `gpt-5.6-sol`,
транспорт Responses, без инструментов и полномочий на внешние действия.

После уточнения владельца подготовлен привычный Google/Replit-вход:
отдельный callback `talkhint-chatdev://auth`, без регистрации рабочего
`talkhint://` в Dev-сборке. Дельта и инструкция —
`docs/chat-1a/GOOGLE_DEV_MAC.md`. Реальный вход владельца на Mac ещё не проверен.

## Proposed-урок для проверяющего / Фомы

**Было:** native offline preview выглядел рабочим, но файлы и ответ модели
в нём симулировались; сервер не был виден в отдельной GitHub-ветке.
**Узнали:** утверждение UI и наличие API-кода не доказывают рабочую цепочку.
**Действовать:** отдельно фиксировать (1) source transfer, (2) native gate,
(3) Dev HTTP/auth/DB/storage, (4) реальный AI/STT, (5) ручной iPhone UX.
Статус proposed; не принято автоматически и не записано в production-книжку.
