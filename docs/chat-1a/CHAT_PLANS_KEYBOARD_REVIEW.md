# Dev: клавиатура и подготовка звонков из Chat

## Реализовано

| Путь | Поведение |
|---|---|
| Клавиатура | Тап по переписке или Done скрывает клавиатуру; черновик не очищается. Кнопки и вложения не перехватываются. |
| AI | Та же модель/Responses transport; единственный tool предлагает структурированные данные, без исполнительных полномочий. |
| Карточка | Цель, короткий чек-лист, факты, неизвестное, ожидаемые вопросы/ответы, разрешённое/запрещённое, язык, телефон, voicemail. |
| Hint | После отдельного подтверждения план сохраняется существующим CallPlanStore. Подключение к следующему подходящему исходящему Hint-звонку остаётся прежним. |
| Катя | После отдельного подтверждения открывается существующий нативный review. Для настоящего звонка всё ещё нужна отдельная кнопка Start. |
| Исправления | Новый полный план получает другой hash; старую карточку после нового сообщения подтвердить нельзя. |
| Повтор | Message ID — стабильный ключ downstream-сохранения. Конкурирующие подтверждения сериализованы; повтор не сохраняет второй Hint-план. |
| Безопасность | Владелец только из аутентификации. Body принимает только hash. Токен review краткоживущий, не попадает в историю/outbox/модель. |
| История | Полный plan action хранится в БД и восстанавливается при повторном открытии. Старые сообщения без action совместимы. |

Переиспользованы `shared/callPlan`, `CallPlanStore`, существующая подпись
подтверждения Секретаря и существующий `SecretaryTaskReviewViewController`.
Новый телефонный движок, Retell, голос, тарифы и лимиты звонков не менялись.
Новое 180-секундное ограничение для живых звонков не добавлено.

## Границы

- Это подготовка и подтверждение двух действий, не весь roadmap 1C.
- Автоматическая доставка результатов завершённых звонков в чат пока не
  добавлялась. Это отдельная следующая часть, не выдаётся за готовую.
- Нет Gmail, поиска, геолокации, календаря, долговременной памяти или Voice Orb.
- Существующий лимит Secretary-инструкции 2000 символов сохранён. Слишком
  большой план явно отклоняется, а не урезается с потерей условий.
- Смена бюджета через сообщение требует подтверждения новой карточки.
  Уже сохранённый старый план не изменяется моделью автоматически.
- Текстовое «да» не заменяет кнопку подтверждения карточки.

## Проверки и выпуск

Неплатный целевой проход: 25 тестов provider/service/plans/реальной Dev БД
прошли. В том числе гонка трёх подтверждений, повтор из нового экземпляра
репозитория, чужой владелец, неверный hash, последующая коррекция, rollback
неуспешной записи, transient-only token и отсутствие автоматических действий.

Кодовые проверки iOS и локализаций пройдены. Новые XCTest добавлены, но
Xcode/Simulator/iPhone здесь недоступны. Исходниковый тест не доказывает
фактическую работу клавиатуры или навигации на iPhone.

Общий Vitest: **3994 passed / 0 failed / 52 skipped** (4046 тестов).
Все **409/409** тестовых файлов включены ровно по одному разу в четыре
последовательных шарда. Opt-in проход реальной Dev БД выполнен отдельно:
8/8 DB-тестов прошли в целевом проходе 25/25.
TypeScript: `npm run check` — PASS.
Серверная кандидатная сборка `build:prepare` — PASS; собранный production
сервер локально не запускался. Dev workflow перезапущен, схема без drift.
Логи: `generated-artifacts/chat-plans-keyboard-20261109`.
Нативные Python source contracts: 49 проверок; четыре новых XCTest
переданы на Mac, а не выданы за запущенные в Linux.

Schema diff проверен отдельно: только
`ALTER TABLE "chat_messages" ADD COLUMN "action" jsonb;`.
Нет удаления таблиц/данных/колонок, destructive warnings отсутствуют.
Поле добавлено только в Dev. Production — отдельным Publish владельца;
никакого startup DDL или ручных production-записей.

Нативная передача: [задание Claude](https://github.com/Sergalmazfas/Talk-Hint-VM/blob/xcode-chat-plans-keyboard-2026-11-09/docs/claude-mac-chat-plans-keyboard-handoff.md).

коммит `4e55d54` поверх `160181a`,
без merge в main/clean-main. Publish сервера **не обновляет iPhone-приложение**:
Mac должен пройти полный gate и собрать обновление обычного TalkHint.

Платные запросы AI/STT, звонки и репетиции не запускались. Реальная модель
с новой proposal-схемой в этом проходе не оплачивалась и не проверялась —
только её mocked Responses-протокол. Первый платный ручной проход владельца
