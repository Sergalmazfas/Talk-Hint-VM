# Swift Secretary: личность → номер → Retell + Engine

24 октября 2026. Только Dev; публикации, GitHub Push и реальных звонков не было.

## Пользовательский путь

В обновлённых исходниках Swift:

**Settings → Secretary → Личность и исходящий номер**

1. Выбрать принадлежащую пользователю личную или рабочую линию.
2. Открыть каталог и выбрать Катю. На экране показаны описание, подробные правила,
   примеры, рекомендации для личного/рабочего общения и версия.
3. Отдельно отметить карточки, которые разрешено использовать в исходящих
   разговорах с этой линии. По умолчанию дополнительные карточки не разрешены.
4. Нажать «Применить связку Retell». Сервер атомарно сохраняет назначение
   личности и разрешения карточек. Клиент явно выбирает Retell + Engine.
5. Подготовить/надиктовать поручение, подтвердить, ввести номер получателя и
   нажать вызов. Эта операция уже является реальным звонком; автоматическая
   проверка её НЕ выполняла.

Личность — не голос. Сохраняется существующий голос Merritt и Engine
`gpt-6.1-sol / medium`. Новые голоса, клонирование и отдельный мозг Retell
не добавлялись. Полномочия реальных календарных/платёжных действий не расширены.

## Как запустить Dev-сборку на Mac

AppConfig уже поддерживает Debug-переопределение. В Xcode:

**Product → Scheme → Edit Scheme → Run → Arguments → Environment Variables**

```text
TALKHINT_API_BASE_URL=https://e62acc35-f5e5-43be-91ea-c3ad7b36be85-00-3l7jbsd7n4zci.janeway.replit.dev
```

Собрать свежие исходники и запустить из Xcode на iPhone. Эта переменная действует
при таком запуске; она не превращает обычную установленную production-сборку
в постоянную Dev-сборку. Адрес сервера виден на новом экране.
Release и запуск без переопределения по-прежнему используют рабочий сервер.
Каталог/новая связка на нём пока недоступны.

Swift-файлы под `ios/TalkHint` и тесты под `ios/TalkHintTests` включаются через
существующие XcodeGen source globs; новый отдельный мобильный проект не создавался.

## Сервер и сохранение

- Назначение личности: прежний каталог и прежняя таблица назначений.
- Разрешения исходящих карточек: отдельные настройки владельца + номера, не
  поля персонажа и не автоматическое наследование разрешений входящего Work.
- API: GET/PUT `/api/secretary-personalities/numbers/:numberId/outgoing`.
- В `secretary_tasks.outgoing_context` сервер фиксирует выбранную линию,
  профиль, версию личности, ID и тексты разрешённых карточек. Клиент не присылает
  готовый prompt или произвольный снимок карточек.
- Dialer использует именно сохранённую принадлежащую владельцу линию. Если
  она недоступна, звонок не подменяется звонком с личного номера.
- До набора и регистрации Retell повторно проверяются принадлежность линии,
  профиль, существование/содержимое карточек и сохранённые разрешения.
- Модель получает выбранные карточки как фактические данные, не инструкции.
  Приоритет безопасности, полномочий, проверенной идентичности владельца и
  выбранной личности остаётся выше текста карточек и реплик собеседника.
- Уже начатая сессия использует свой снимок. Изменение настроек не переписывает
  отправленное поручение; это не механизм удаления уже услышанных сведений.

## Повторный запрос и прежние режимы

Нативный черновик сохраняет ID линии и origin сервера вместе с прежним UUID
запроса. После первой попытки они не подменяются текущими настройками.
Повтор того же request ID возвращает старую задачу; попытка сменить её линию
отклоняется без нового вызова. Черновик другого backend не отправляется.

Выбор GPT очищает локальный выбор новой исходящей связки для будущих поручений,
но не удаляет серверные назначения. Старые задачи без outgoing_context сохраняют
прежний выбор линии и не получают новые карточки.

Выбор персонального номера не включает несуществующий личный входящий маршрут.
Существующая маршрутизация входящих и рабочий номер не перенастраивались.

## Проверки

- TypeScript и регрессионные проверки Secretary/Engine/Lab/incoming.
- Настоящая Dev-база: личный/рабочий профиль, чужие карточки и номера,
  атомарное сохранение, повторное чтение, отзыв/изменение карточек,
  закреплённая версия личности и сериализация снимка в строку поручения.
  Тестовая строка поручения была в откатываемой транзакции и не видна worker.
- Mock Twilio: выбранный Work From, отсутствие fallback при потере линии,
  сохранение старого поведения без нового контекста. Реальной телефонии нет.
- Пять локализаций; добавлены XCTest для моделей, старого черновика,
  восстановления UUID/линии/origin и постраничного каталога.

**Ограничение:** в Replit нет Xcode/Swift toolchain. Нативная сборка,
выполнение новых XCTest и экран на iPhone не подтверждены. Следующая
проверка — на Mac с существующим `ios/scripts/validate-native.sh`,
затем UI-проход на iPhone. Живой звонок с Катей требует отдельной проверки
владельцем; успешность такого звонка этим отчётом не заявляется.
