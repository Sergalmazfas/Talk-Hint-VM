## 3. Обновить прежний checkout, не потеряв работу

Используй существующую папку **Talk-Hint-VM** на Mac, а не TalkHint-Clean и не
отдельный Expo-клиент `apps/secretary-mobile`.

1. Проверь текущую ветку, полный HEAD, `git status --short`.
2. Проверь fetch/push remote без вывода credentials. Ожидается
   `Sergalmazfas/Talk-Hint-VM` на github.com; в Replit использован внутренний
   `https://github.replit.internal/Sergalmazfas/Talk-Hint-VM.git`.
   Другой владелец/репозиторий — остановиться и сообщить.
3. Если есть локальные изменения или свои коммиты, остановиться и перечислить
   только пути/коммиты. Не делать автоматический stash, reset, clean или rebase.
4. В чистом checkout:

```bash
git fetch --no-tags origin refs/heads/xcode-secretary-2026-10-24
git switch xcode-secretary-2026-10-24
git pull --ff-only origin xcode-secretary-2026-10-24
git rev-parse HEAD
git merge-base --is-ancestor c1c289d96c764e804e65678b8528ca4a5911d813 HEAD
git diff --exit-code c1c289d96c764e804e65678b8528ca4a5911d813 HEAD -- \
  . ':(exclude)docs/claude-mac-secretary-handoff.md'
```

Последние две команды должны завершиться с кодом 0: потомок нужного кода,
без непроверенных отличий за исключением задания. Если ветка локально отсутствует,
создать tracking checkout именно `origin/xcode-secretary-2026-10-24`, но только
после проверки чистоты. При non-fast-forward остановиться, не исправлять историю.

## 4. Прежняя native validation — выполнить до запуска на iPhone

Существующие файлы:

- `ios/project.yml` → `ios/TalkHint.xcodeproj`;
- схема приложения **TalkHint**, Debug;
- изолированная тестовая схема **TalkHintValidation / NativeValidation**;
- инструкция `ios/README.md`;
- `ios/scripts/validate-native.sh`, `verify-project-sources.py`,
  `verify-native-entitlements.py`, `verify-xcresult.py`.

Из корня репозитория:

```bash
DEVELOPER_DIR=/Applications/Xcode_16.4.app/Contents/Developer \
  bash ios/scripts/validate-native.sh
```

Если согласованный Xcode установлен по другому пути — указать его и записать
фактические версии Xcode/XcodeGen/симулятора в отчёт. Отсутствующий инструмент или
runtime — блокер среды, не повод отключить gate.

Скрипт должен заново сгенерировать проект, проверить членство исходников,
собрать тестовый host, проверить runtime entitlements **главного Mach-O**, запустить
XCTest и разобрать .xcresult. Недостаточно одного `BUILD SUCCEEDED`.
NativeValidation использует `.invalid` backend и фикстуры; не перенаправлять её
на Dev/production.

Обязательно проверить:

- старые audio router / Hint stream / captions / Prepare appearance tests;
- реальный Keychain write/read/delete, без обхода ошибки `-34018`;
- catalog/personality API decoding, selection/save/readback и owner/number scope;
- SessionStore: pending request scope по owner + backend-origin;
- Retell default и сохранённый явный GPT, ограничения альтернатив;
- подтверждение поручения и повторное открытие без повторного POST/dial;
- первые live-реплики и восстановленный snapshot, включая
  `testLiveUpdateAfterRecoveryReusesTheExistingCard`;
- карточка добавлена в общий родитель **до** width constraint activation;
- source-connected/source-missing metadata, read-only переподписка и отсутствие
  ложного обещания восстановить Twilio-источник;
- синхронность ключей/placeholder всех пяти Localizable.strings.

Не исправлять тест только потому, что он упал: отделить ошибку теста от регрессии
приложения и привести доказательства.

## 5. Сборка настоящего приложения, без публикации и звонков

После успешной validation:

```bash
cd ios
xcodegen generate
open TalkHint.xcodeproj
```

В Xcode выбрать **TalkHint / Debug**, существующую команду Signing и iPhone
владельца. При доступной подписи можно проверить build:

```bash
xcodebuild -project TalkHint.xcodeproj -scheme TalkHint \
  -configuration Debug -destination 'generic/platform=iOS' build
```

Не отключать phone signing ради зелёного build. Подготовить Build & Run на iPhone;
установку/запуск согласовать с владельцем. Самостоятельно не нажимать Call/Start.

## 7. План телефонного теста владельца — сейчас НЕ выполнять

Только после отчёта и отдельного согласия владелец сам запускает согласованный
вызов. Браузерный успех не является доказательством PSTN/iPhone.

- Один Start → один вызов через наш Twilio → SIP → Retell Custom LLM → наш Engine.
  Двойной тап/повтор callback/повторное открытие задачи не создают второй вызов.
- Катя: виртуальный секретарь, правильное подтверждённое имя владельца, характер
  v2, RU/EN/ES и переключение языка. Без выдуманных действий и TEST-сведений.
- При первых репликах и Resume monitoring нет constraint crash.
- Владелец **слышит ОБОИХ участников**, в наушниках и на динамике, в том числе
  одновременную речь. Twilio both_tracks → guest/secretary → два Swift playback-узла.
  Приход аудиопакетов и локальный playback callback не равны слышимости человеком.
  Микрофон владельца через мониторинг собеседнику не передаётся.
- Перебивания в начале/середине/конце. Устаревшая речь и прощание отменяются;
  уже выполненные действия не повторяются.
- Конец по подтверждённому итогу/прощанию, End, завершению собеседником и лимиту
  300 секунд; timeout ответа 30 секунд. Не заканчивать за простую паузу/ожидание.
- Retell `end_call` — после произнесения актуального прощания; перебивание
  отменяет сигнал. HTTP 404 stop не считать успехом без состояния того же call ID.
- Свернуть/вернуться, потерять сеть, открыть старую задачу: без нового набора.
  Read-only обновление feed не создаёт потерянный Twilio-источник.
  После рестарта сервера восстановление Custom LLM/источника не гарантируется;
  не маскировать это статусом connected.
- После End освобождены playback/audio session; Hint/Translator/Copilot не
  регрессировали. Повторное открытие завершённой задачи показывает итог/transcript.

## 8. Отчёт Claude и цикл исправлений

Верни:

1. Sanitized remote owner/repository, ветку, полный фактический HEAD, коммит
   кода выше; чистота до проверки и изменённые пути после.
2. Версии Xcode/XcodeGen, симулятор, отдельно сборка iPhone.
3. Команды, exit codes, число passed/failed/skipped. Сборка ≠ выполненные тесты.
4. Для каждой ошибки: test/file/line, точный безопасный текст, воспроизведение,
   приложение/тест/среда, предполагаемое минимальное исправление.
5. Путь `generated-artifacts/ios-native.…/`, логи и .xcresult.
   Не коммитить DerivedData, логи, секреты или персональные данные разговоров.
6. Таблица UI-проверок: подтверждено / не проверено / блокер.
   Физический звук и реальные звонки обозначить **не проверено**.
7. Что осталось до установки/ручного теста владельца. Не заявлять, что звонок
   прошёл или оба голоса слышны, если был только XCTest/build.

После согласованных исправлений получить новую версию задания/коммита, обновить
ту же ветку только fast-forward и повторить весь native gate. Тесты не выключать.
Ни успешная сборка, ни этот документ не разрешают публикацию или реальный набор.
