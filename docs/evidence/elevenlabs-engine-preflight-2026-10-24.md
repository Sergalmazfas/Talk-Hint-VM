# ElevenLabs + TalkHint Engine — проверка перед подключением

Дата: 24 октября 2026. Область: существующий Dev-браузерный Secretary Lab.
Это отчёт об исследовании и блокере, НЕ отчёт о готовом четвёртом стенде.

## Что подтверждено

- Текущее подключение приложения — ElevenLabs TTS, HTTP streaming,
  `eleven_multilingual_v2`, `mp3_44100_128`. Это не Agents Platform.
- Существующий сохранённый клон: `VvZTqAQY9XoLHqoQmBC2`, в хранилище статус
  `ready`, в текущем ElevenLabs account доступен, категория `cloned`.
  Новый клон не создавался. Привязку при запуске нужно читать для текущего
  администратора, а не использовать глобально найденный voice ID.
- Read-only API Agents Platform отвечает HTTP 200. Найдены два уже существующих
  агента, не относящихся к этому стенду; они не изменялись.
- Подписка по read-only API: Creator, active. Это не проверка стоимости будущего
  разговора или всех разрешений на создание/использование агентов.
- Каталожный кандидат: Roger — Laid-Back, Casual, Resonant,
  `CwhRBWXzGAHq8TQ4Fs17`, `premade`, назначение `conversational`.
  Это кандидат для сравнения, не фактически запущенный голос нового режима.
- По актуальной официальной документации Agents Platform поддерживает внешний
  Custom LLM сервер, совместимый с OpenAI Chat Completions или Responses API,
  с SSE streaming. Custom LLM нельзя совмещать с их Realtime model.
- Передавать наш OpenAI API key ElevenLabs или использовать их отдельную LLM
  для бизнес-ответов не требуется: модель, правила, данные и TEST tools могут
  оставаться за нашим HTTP-адаптером TalkHint.

Доступность клона в Voices API ещё не является проверкой живой работы в Agents
Platform. Пустой список verified_languages не доказывает отсутствие языков.
Новая разговорная TTS-модель пока не настроена и не проверена; текущую
`eleven_multilingual_v2` нельзя выдавать за уже подключённую модель нового стенда.

## Подтверждённый блокер интеграции

В основной ветке на момент проверки нет общего постоянного хранилища отчётов,
которое создаёт отдельная задача «Сохранять сравнения голосовых стендов после
перезапуска Dev». Во время исследования эта задача получила статус IMPLEMENTED,
но её реализация ещё не появилась в доступной основной ветке. Текущие
Secretary/Retell sessions и TEST action ledger по-прежнему находятся в памяти.
Ветка этой работы не подменяется и не объединяется вручную.

По требованию владельца второе независимое хранилище не создаётся. Поэтому
нельзя честно показать четвёртый режим как готовый с повторно читаемым устойчивым
результатом поручения. Новый агент, голосовая сессия и микрофон не запускались.
Рабочие три режима и общий Engine не изменялись.

Следующий шаг: после появления общего хранилища в основной ветке проверить его
реальный интерфейс/модель task ID/action ID и добавить дополнительный провайдер
через тот же repository. Не создавать отдельную таблицу/JSON-файл отчётов.
Если задача ещё не покрывает подтверждение сохранения действия ДО заявления
модели об успехе, это отдельный вопрос интеграционного контракта, не повод
выдавать память за базу или переписывать Engine без согласования.

## Подключение, которое предстоит реализовать

1. Четвёртый вариант «ElevenLabs + Engine»; три существующих сохраняются.
2. «Мой голос / Голос ElevenLabs»: проверка доступа для текущего владельца
   до старта. Недоступный клон имеет явную причину; тихой замены нет.
3. Один Dev-only streaming HTTP adapter к существующему
   `SecretaryConversationEngine.respond`, без отдельной персоны/бизнес-LLM
   ElevenLabs и без переписывания общего Engine.
4. Разрешённый контекст и TEST tools принадлежат TalkHint. Внешние system/tool
   инструкции не получают полномочий. Посторонние инструменты, телефония,
   календарь и уведомления отсутствуют.
5. Короткоживущий session admission и проверка связи с поручением; backend
   credentials не возвращаются клиенту и не попадают в сохранённые отчёты.
6. Прерывание: клиент немедленно прекращает playback; адаптер отменяет
   устаревшую генерацию. Уточнение учитывается в следующем ответе. Уже выполненное
   действие не откатывается, повтор не выполняется заново.
7. Остановка во время старта/разговора освобождает микрофон и аннулирует admission;
   позднее завершение старта также закрывается. При неясном статусе новая сессия
   не запускается автоматически.
8. Результат привязывается к ID поручения в общем repository. Подтверждение записи,
   повторный GET и проверка action ID обязательны. Фраза «передам» не доказательство.

## Одинаковый протокол для двух голосов

Контекст — только общий `secretary-dev-fixture`, тот же текст поручения и одинаковые
настройки. Конкретные voice/model ID записываются из фактической конфигурации.
Каждый сценарий выполнить отдельно с клоном и Roger.

| Сценарий | Реплики/действия | Критерий |
|---|---|---|
| Русский | «Запиши тестовое сообщение: Алексей, место Ocean TEST, завтра в 18:30» | Уточнить дату/часовой пояс; сохранить TEST под ID поручения; прочитать обратно |
| English | “Please take a TEST message: Alex, Ocean TEST, tomorrow at 6:30 PM” | Те же поля, никакой реальной доставки |
| Español | “Guarda un mensaje de prueba: Alex, Ocean TEST, mañana a las seis y media” | Те же поля; не угадывать дату/часовой пояс |
| Смена языка | Начать RU, уточнить EN, исправить время ES | Ответ на языке собеседника, единый исправленный контекст |
| Раннее перебивание | Начать говорить в начале первой содержательной фразы | Playback останавливается, старый ответ не продолжается |
| Среднее перебивание | Во время перечисления исправить место на Harbor TEST | Следующая реплика использует исправление |
| Позднее перебивание | Исправить время после окончания генерации, пока звук ещё играет | Остановить оставшуюся озвучку, а не отменять уже завершённый upstream запрос вслепую |
| Паузы | «Мне нужно… [2 секунды] передать… [4 секунды] сообщение» | Не придумывать продолжение и не завершать разговор автоматически |
| Нерешительная речь | «В шесть… нет, в семь… точнее в 19:15» | Уточнить/повторить 19:15, не сохранять три независимых результата |
| Повтор действия | Дважды попросить сохранить то же сообщение после перебивания | Один подтверждённый action ID, без дубля |
| Повторное чтение | Остановить, открыть отчёт по task ID, обновить страницу | Те же подтверждённые поля из общего хранилища |
| Перезапуск Dev | После сохранения перезапустить Dev и повторить GET | Сохранённый результат не теряется, аудио не возобновляется |
| Отмена старта | Start → Stop до подключения/разрешения микрофона | Поздняя сессия закрывается; нет второго старта и захвата микрофона |
| Переключение | Проверить переходы всех четырёх режимов и смену голоса | Нет перекрывающихся сессий, старого playback и микрофона |

### Что фиксировать раздельно

- Сервер: получение финального текста → первый текстовый фрагмент Engine.
- Клиент: конец речи пользователя → фактическое начало playback.
- Перебивание: speech/interruption event → отмена генерации и остановка playback.
- Для всех метрик: источник часов/метки, пропуски, ошибки; не смешивать
  сетевой RTT, генерацию и акустическую задержку.
- Пользователь: слышимость и естественность отдельно, с указанием
  голоса, устройства, браузера, наушников/динамика.
- Ошибки распознавания имён/времени/места; сохранённое значение и action ID.

Все перечисленные живые проверки пока НЕ ПОДТВЕРЖДЕНЫ. Просмотр кода и API
не заменяют прослушивание на iPhone и в наушниках.
