# Личности Secretary — Dev, 24 октября 2026

## Что хранится

Каталог общих персонажей: постоянный ID и slug, имя, краткое описание, доступность,
номер редакции. Неизменяемые редакции содержат имя, описание, подробные правила,
примеры и рекомендации для Personal/Work.

Назначение принадлежит владельцу и конкретному принадлежащему ему номеру. Оно
фиксирует ID и версию. Редактирование каталога создаёт новую версию, но не меняет
существующие назначения. Обновление назначения — отдельное осознанное сохранение.
Снятая с выбора личность продолжает работать в ранее сохранённой версии.
Удаления личности через API нет.

Катя добавлена как единственная начальная доступная запись. Никому автоматически
не назначена. Характер можно править в редакторе на сайте, не меняя код каталога.
Личность — стиль и узнаваемое обращение, не человеческая биография и не голос.

## Где выбирать и редактировать

В существующих настройках `/incoming-secretary#personalities`:

1. Выбрать свой номер.
2. Открыть карточку личности, выбрать текущую версию.
3. Нажать «Сохранить назначение».
4. Для возврата к прежнему поведению сохранить вариант без личности.

Редактор доступен существующим администраторам из allowlist: создание персонажей,
описание, правила, примеры, Personal/Work, новая версия, снятие с выбора.
Поиск — по началу имени или slug; выдача порциями, с keyset-курсором.
Персонажи не зашиты в переключатель. Каталог не содержит факты клиентов.

## Фактически подключённые маршруты

| Маршрут | Применение |
|---|---|
| Уже включённый входящий Work Secretary, GPT-Live | Назначение владельца + фактического входящего Work-номера; существующие разрешённые карточки/инструменты не расширены |
| Исходящий телефонный Retell + Engine | Назначение владельца + фактической исходящей линии From; только прежнее поручение, без автозагрузки карточек |
| Текстовая проверка в настройках | Реальный текстовый запрос в модуль TalkHint Engine, без инструментов, звонков и бизнес-действий; текущая сохранённая версия |
| Личный входящий Secretary | Не реализован этим изменением |
| Браузерные аудио TEST-стенды GPT/Retell/ElevenLabs | Привязки к номеру и автоприменения личности пока нет; прежние режимы сохранены |

Телефонные маршруты не включаются выбором личности. Выбор применяется со следующей
сессии. В начатой сессии характер остаётся зафиксированным. Выбор исходящей линии,
провайдеры, голос, телефония, полномочия и доступ к данным не изменяются.

Все новые API и загрузка назначений в runtime ограничены `NODE_ENV=development`.
Production в этой работе не обновлялся.

## Приоритет и изоляция

Общие правила, достоверность, проверенная личность владельца, разрешения и
разрешённые факты выше характера. Один общий компоновщик стиля используется
в поддержанных маршрутах. Примеры не являются фактами бизнеса. Реплики
собеседника и текст карточек не выбирают и не заменяют персонажа.

Клиент не передаёт владельца назначения: он определяется аутентификацией.
Доступ к чужому номеру возвращает 404. Входящие карточки по-прежнему фильтруются
по владельцу, Work и разрешённым ID; исходящий Retell дополнительных карточек
не получает. Прямые HTTP-проверки формы и конфликты версий не заменяют
серверные проверки принадлежности номера.

## Проверки и границы доказательств

- TypeScript, тесты телефонного Retell, Engine, incoming Secretary и Lab прошли.
- Проверены API-аутентификация, админские ограничения, формы, номера, отсутствие
  назначения по умолчанию и отключение API вне Dev.
- На настоящей Dev-базе проверены сохранение и повторное чтение, два владельца,
  разные номера, общая личность, Personal/Work, старые версии, снятие с выбора,
  возврат к прежнему поведению и 1000 временных записей: 28 страниц по 37,
  без пропусков и повторов. Тестовые записи удалены; реальные назначения не менялись.
- Отдельный opt-in текстовый probe использует сохранённую Катю с
  `gpt-6.1-sol / medium`, без инструментов и звонков. Результат записывается в
  `generated-artifacts/secretary-personality-text.json`. Это текстовые ответы,
  а не проверка слышимости, телефонного разговора или субъективная оценка характера.
- Текстовая проверка переиспользует телефонные инструкции, поэтому может показать
  телефонное вступление в ответе. Это демонстрационная реплика, не совершённый звонок.
- Prompt-тесты доказывают сборку и приоритеты инструкций, а не абсолютную
  устойчивость модели ко всем возможным атакам.
- Реальные телефонные звонки и Xcode не запускались. Авторизованный экран
  проверяется отдельно от публичного скриншота: анонимный браузер не входит в аккаунт.

## Повторение проверок

```sh
npm run check
npx vitest run server/secretary/personalities server/secretary server/secretaryLab server/incomingSecretary
RUN_PERSONALITY_DB_TESTS=1 npx vitest run server/secretary/personalities/store.integration.test.ts
```

Текстовый probe — отдельный **платный текстовый** запрос в существующий OpenAI API:

```sh
NODE_ENV=development DISABLE_AUTO_WEBHOOK_REPOINT=true npx tsx scripts/probe-secretary-personality-text.ts
```

SQL `server/secretary/personalities/schema.sql` применён только к Dev.
Старт сервера не выполняет DDL и не создаёт/перезаписывает персонажей.
Данные первоначальной Кати сохранены в БД; исходный текст начального наполнения
не подменяет последующее редактирование каталога.
