# Прослушивание Кати: исправления в Dev

## Статус

Изменён только исходный код приложения iOS и локальные проверки.
Production, сервер звонка, Retell, модель, голос и права не изменены.
Новых звонков, писем и платных запросов не было.
Обновление сервера само по себе не обновит установленное приложение iPhone.

## Что исправлено

- Переподключение текстовой ленты больше не стирает ошибку местного плеера.
- Запуск движка и получение пакетов не считаются восстановлением воспроизведения.
  Ошибка снимается только после callback `.dataPlayedBack` при наличии текущего
  принятого аудио, на видимом экране, без прерывания или чужой телефонной аудиосессии.
  Это техническое свидетельство воспроизведения буфера, не доказательство слышимости.
- Готовность проверяется по работающему движку и обоим узлам проигрывания,
  а не по одному запомненному флагу.
- При остановленном плеере и зависшем воспроизведении добавлено местное восстановление:
  максимум три автоматические попытки, минимум две секунды между ними.
  Запуск движка без callback воспроизведения не обнуляет этот предел.
- Автоматическое восстановление не создаёт звонок, не переподключает сетевую ленту
  и не восстанавливает отсутствующий Twilio-источник.
- При уходе с экрана, завершении звонка, прерывании iOS или занятой CallKit
  аудиосессии восстановление запрещено.
  Если iOS не разрешила автоматическое возобновление после прерывания,
  требуется явная кнопка повторного подключения. Во время самого прерывания она
  не запускает звук.
- Некорректные роли, Base64 и чрезмерные пакеты отвергаются до постановки в плеер.

## Диагностика на экране

При ошибке показываются стадия и безопасный системный код:
`session_category`, `session_activation`, `output_route`, `engine_start`,
`player_not_ready`, `buffer_allocation`, `playback_stalled`,
`invalid_audio_frame`, `phone_audio_busy`, `interruption_resume_denied`.

Рядом: количество повторов, принятых пакетов и callback проигрывания,
версия/номер сборки приложения, версия iOS, тип аудиовыхода, частота и громкость.
Адреса устройств, телефон, текст разговора, аудио, токены и URL не включаются.
Неизвестный домен NSError заменяется на `Other`; описание и userInfo ошибки
не выводятся. Никакая новая диагностика автоматически на сервер не отправляется.

## Проверки, фактически выполненные в этой среде

| Проверка | Результат |

| Python source-contract для восстановления и защит | 7 проверок прошли |
| Vitest: Retell monitor и streamAuth на заглушках | 6 тестов прошли |
| `git diff --check` | Прошёл |
| `ios/scripts/validate-native.sh` | Заблокирован: требуется macOS/Xcode; сборка и XCTest не запускались |

Source-contract проверяет устройство исходников и наличие защит.
Он не исполняет Swift и не заменяет XCTest.

## Добавленные native-тесты, пока НЕ выполненные

11 новых XCTest проверяют:

- ограничение частоты и количества восстановления;
- сброс лимита только по свидетельству проигрывания;
- ручной повтор без ложного объявления исправления;
- отсутствие приватных данных в безопасном системном коде;
- сохранение ошибки при сбросе текстовой ленты;
- сохранение диагностики и кнопки завершения при потере источника;
- отсутствие ложного успеха от пакетов и старого callback после сброса ленты;
- отказ некорректным пакетам и событиям скрытого экрана;
- местную попытку без повторной подписки;
- запрет автоматического старта без разрешения iOS на возобновление.
- реальный запуск AVAudioEngine/аудиосессии и callback обоих синтетических
  звуковых буферов без сети, микрофона и звонка; это не тест слышимости человеком.

Все добавлены в обязательную проверку `.xcresult`. Для этой iOS-дельты действует
короткий путь из `replit.md`: целевые SecretaryMonitorAudioTests,
SecretaryTranscriptRenderingTests, CallAudioDeviceRouterTests и
NativeSessionStorageTests на изолированном NativeValidation-контуре,
затем одна обычная сборка TalkHint. Полный gate не требуется только из-за этой
дельты; `bash ios/scripts/validate-native.sh` оставлен для случаев, определённых
общими правилами проекта. Единственное актуальное задание для этой дельты:
`docs/claude-mac-secretary-monitor-recovery-handoff.md`.

## Что ещё требуется

1. Выполнить целевые native-проверки на Mac с Xcode. Пока они не выполнены,
   native-исправление нельзя считать проверенным или готовым к выпуску.
2. После успешных проверок отдельно согласовать установку новой Dev-сборки.
3. На iPhone проверить реальную слышимость обоих участников, переключение
   разговорного динамика/громкой связи/Bluetooth и восстановление после прерывания.
   Новый платный звонок не разрешён этим пакетом.

Причина конкретного старого отказа по скриншоту по-прежнему не доказана:
технический код с того телефона не был сохранён в доступных серверных журналах.
