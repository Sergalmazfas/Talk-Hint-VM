## Получение без потери локальной работы

Использовать существующий репозиторий Talk-Hint-VM, не TalkHint-Clean.
Проверить remote, ветку, HEAD и `git status --short`.
При локальных изменениях или собственных неопубликованных коммитах остановиться
и сообщить владельцу; не применять stash/reset/clean/rebase/force автоматически.

В чистом checkout:

```bash
git fetch --no-tags origin refs/heads/xcode-hint-lab-v3-2026-10-26
git switch --track -c xcode-hint-lab-v3-2026-10-26 origin/xcode-hint-lab-v3-2026-10-26
git rev-parse HEAD
```

Если tracking ref не создан fetch-настройками:
`git switch -c xcode-hint-lab-v3-2026-10-26 FETCH_HEAD`.
Если локальная ветка уже существует, не пересоздавать и не сбрасывать её.
Сопоставить фактический HEAD с SHA поставки, который Replit сообщил владельцу.

## Проверка на Mac

Использовать существующие `ios/project.yml`, схему TalkHint и native validation
из `ios/README.md` / `ios/scripts/validate-native.sh`. Сначала изучить реальные
аргументы скрипта и наличие Xcode/симулятора; не выдавать Linux-проверки за XCTest.
Не отключать тесты и не менять Apple Team/signing для сокрытия ошибки.

Для открытия существующего приложения:

```bash
cd ios
xcodegen generate
open TalkHint.xcodeproj
```

Не менять сохранённую серверную конфигурацию наугад. Вывести только безопасный
адрес назначения приложения и конфигурацию, без токенов.

После native gate вернуть: репозиторий/ветку/HEAD, версии Xcode/XcodeGen,
точные команды и exit codes, результат XCTest, путь к xcresult, ошибки и
список локально изменённых файлов. Исправления сначала показать diff владельцу.

Сборку Archive/загрузку TestFlight выполняет владелец либо Claude только по его
явному поручению с существующей подписью. Не запускать звонки, публикацию сервера,
backend, БД, миграции или платные сервисы. Не переносить серверные секреты на Mac.
