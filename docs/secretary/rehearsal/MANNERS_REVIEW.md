# Манера Кати — только «Новая (Dev)»

> Исторический пакет. По следующему решению владельца удержание полного
> ответа отменено. Текущее поведение и замеры: [STREAMING_REVIEW.md](STREAMING_REVIEW.md).

## Граница
Только dev-C на `/admin/rehearsal`. Флаг задаёт внутренний binding выбранной
версии, не HTTP-body владельца. «Как в бою (C)», обычный стенд C, прежняя A и
телефонный runtime не получают новую инструкцию/фильтр. Голос, язык,
приветствие, план, IVR, безопасность, модель и её лимит 300 не меняются.
Ни звонков, ни платных запросов, ни Publish, ни production-записей не было.

## Что меняется
1. Существующее одно подтверждение перед ожиданием сохранено. В новом варианте
   известная продолжающаяся речь микрофона блокирует подтверждение, даже если
   Retell уже прислал `response_required`. Повтор ASR не даёт второе подтверждение.
2. Существующие короткие обращения и формы имени сохранены. Короткая фраза
   освобождает ожидание только после измеренной паузы ≥1,2 с. Явная команда
   коллеге («John, check…») не освобождает ожидание даже после паузы.
3. Только новый Dev-фильтр держит текст до завершения короткой генерации.
   Прерванная генерация не отдаёт свой незавершённый префикс в TTS. Финальные
   обрывки вроде `New,`, `New tires,`, `Okay. What` подавляются без повторного
   платного запроса. Retell по-прежнему сам останавливает звук при перебивании.
4. Инструкция: об отсутствующем факте сказать один раз и уточнить полезное;
   оба варианта спрашивать только если собеседник действительно предложил два,
   не выдумывать ни варианты, ни сведения владельца. История передаётся модели.
   Защитный фильтр убирает повторный самостоятельный префикс «I don't know» /
   «He didn't mention», не вырезая числа или произвольный смысл предложения.
5. Инструкция: одно прощание, без повторного Thank you. Фильтр убирает
   повторную чистую благодарность в одном ответе и повторное прощание,
   если оно уже есть в услышанной расшифровке. Перед ответом на вопрос
   удаляется стартовое «Got it»; для вопросов в новом варианте не включается
   отдельная отложенная bridge-фраза буфера.
   Для остальных фраз сырой первый токен отменяет bridge через 600 мс,
   даже пока текст ещё удерживается новым фильтром. Лимит связок не расширен.

## Компромисс скорости
Завершение генерации перед отправкой текста может увеличить задержку речи.
Это намеренно ограниченный Dev-опыт против обрывков, **не доказательство
ускорения**. Фактическую прибавку на голосе не измеряли. Метрика `speed` TTFT
остаётся провайдерской; `cInterruption.first_token` в этой ветке помечен причиной
`dev_complete_reply_ready_for_tts` и видит уже отфильтрованный готовый текст,
не первый сырой токен модели. Их нельзя сравнивать
как один и тот же замер.

## Replay и ожидания
Офлайн WebSocket-replay воспроизводит сохранённые в прежнем регрессионном
тесте фрагменты с временными якорями:

| Фрагмент | Ожидается | Проверка |
|---|---|---|
| 1:17,720 — «Секунду… посмотрю на складе…» | 1 подтверждение, затем молчание | есть |
| 1:20 — команда коллеге | 0 запросов модели | есть |
| 1:26,690 — «Кать, ты меня слышишь?» | 1 ответ | есть |
| 1:38,630 — новое ожидание | 1 подтверждение | есть |
| 1:50,860 — «Здесь?» | 1 ответ | есть |

Цель регрессии: 2/2 обращения получают ответ, 0 запросов по явной команде
коллеге, 0 отправленных обрывков из незавершённой генерации, 0 двойных
подтверждений в одном ожидании.

Replay использует реальный локальный registry/буфер и фикстурную модель:
это проверка маршрута событий, не новый разговор и не воспроизведение аудио
в Retell. Полный оригинальный звук и семантическая точность живой модели здесь
не проверены. Не гарантируем распознавание любого скрытого адресата по ASR.
Независимое прослушивание/реальный TTFA потребуют отдельной проверки владельца.
