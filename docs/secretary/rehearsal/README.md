# Репетиция Кати — Dev, на сверку Клавдию

## Границы
- Страница `/admin/rehearsal`, только вход владельца/администратора лаборатории.
- API `/api/admin/rehearsal`: только development, не Replit deployment.
- Мутации: Bearer владельца, точный Origin Dev, отдельный CSRF; перед платным
  стартом сверяются хэши выбранных поручения и версии.
- Только Retell **web_call**. Нет покупки номеров, набора телефона, Twilio-вызовов,
  уведомлений, изменения действующих агентов или настроек Кати.
- Создаётся отдельный агент Retell `TalkHint Rehearsal DEV · <hash>`.
  Голос Merritt, языки и настройки Retell берутся из существующей связки.
- Агентов AI Crew и глобальные переключатели не включаем. Разбор репетиции —
  изолированная Dev-цепочка Лёва → Тома, авторизованная кнопкой старта.

## Сценки и версии
Главный экран — только Секретарь: одно поле «Вставь поручение», маленькие
кнопки «Шины / Парковка / Мойка», две версии «Как в бою (C) / Новая (Dev)»,
одна основная кнопка «Позвонить». История, сравнение, подробные поля и бюджет —
в «Ещё»; существующие данные не удаляются.

Перед первым запуском владелец один раз разрешает запись и разбор в настройках
«Ещё». Согласие сохраняется в существующем Dev-архиве для его учётной записи;
после перезагрузки сервера/страницы и смены версии не сбрасывается. Можно
отозвать для следующих запусков. Сам флаг в запросе сессии без сохранённого
согласия не разрешает запись. Origin, CSRF и вход владельца остаются обязательными.

Свободный текст сервер детерминированно раскладывает тем же помощником, что
старый `prepare_call`, без модели и без оплаты. JSON ChatGPT, JSON в Markdown
и `Owner-approved call plan` читаются как структурированный план: пункты,
факты, неизвестное и запреты остаются целиком. Телефон из вставленного
телефонного плана убирается только для web-репетиции: внешнего звонка нет.
Неверный JSON и executor=hint отклоняются, не превращаются незаметно в другое
поручение. Длинная законченная мысль не режется ради лимита. Разбор свободного
текста не угадывает ответы, язык звонка или отсутствующие факты; язык по
умолчанию en, как у `prepare_call`, структурный план сохраняет свой язык.

Три первоначальные сценки: новая шина 295/75R22.5 до $400, ночная парковка,
мойка грузовика. Можно сохранить новый план; структурные пункты не склеиваются
и не делятся по запятым/`;`. Старый структурный endpoint по-прежнему не принимает
телефон и executor=hint; вставка текстом убирает только проверенный телефонный
targetPhone, не меняя остальной план.
Рабочий лимит текстового задания существующего web-стенда — 4000 символов:
превышение отклоняется **до платного запуска**, факты не обрезаются.

Версии: снимок боевого профиля C, текущий Dev C с ожиданием,
сохранённый полный вариант A. На главном экране только C и Dev; данные A остаются
в архиве/подробностях и серверном каталоге. Каждая сессия хранит свой неизменяемый снимок
параметров/сценки, хэши, инструкцию и хэш фактического промпта.
Отдельный `dev-source-sha256` вычисляется по исходникам движка, лаборатории,
репетиции и shared (без тестов): это не SHA git и не отпечаток удалённого production.
Катя берётся из существующего каталога v2, не создаётся заново.
При неоднозначной/отсутствующей личности старт запрещён.

**Ограничение слова «боевая»:** это изолированная репетиция профиля C из кода,
а не подключение к действующему телефонному агенту. Совпадение опубликованного
исходного кода с рабочей копией не доказано и явно отмечено в интерфейсе.
В этой версии используются телефонные правила движка с изолированным
измеряемым stream; реальные телефонные инструменты не передаются.
Репетиция не доказывает поведение PSTN, DTMF или качество телефонного канала.

Только чтением 2026-11-05 проверено:
- production control: вариант C, revision 16018;
- Retell C: agent version 0, custom-llm, `retell-Merritt`,
  en-US/ru-RU/es-ES, responsiveness=1, interruption=0.85,
  backchannel=false, dynamic responsiveness=true, STT fast;
- SHA256 проверенного набора настроек:
  `346c91363346cc709ee126640acb647a89ccd34376a3ffcdf1632357db63d771`.
Ни один телефонный агент при проверке не изменялся, голосовые сессии не создавались.

## Запись и хранение
- Начало разговора — после первой реплики владельца в роли продавца.
  Пустое начало и call_details не запускают модель и не произносят вступление.
- Согласие: владелец один играет собеседника, обе стороны записываются.
- Результаты, планы, тайминги и JSON разбора — существующая Dev-таблица
  `secretary_lab_dev_reports`. Новых таблиц и миграций нет.
- Двухканальный файл Retell копируется в закрытый App Storage, только после
  проверки call_id/web_call и разрешённого HTTPS-хоста.
- В БД — закрытый object key, размер и SHA256; в выдаче — защищённый owner-only
  URL. Внешний recording URL и SDK access_token в результат не сохраняются.
- При задержке записи проверяем её готовность ограниченным числом безопасных
  чтений; pending/failed не выдаются за готовое аудио.
- Результаты доступны владельцу и Replit через тот же защищённый Dev API/БД.
  Скачивание JSON не требуется для последующего чтения Replit.
- Перезагрузка страницы не возобновляет микрофон/аудио автоматически.
  Незавершённую сессию можно остановить с серверным подтверждением.

## Разбор и бюджет
- После подтверждённого конца запускаются архивирование и разбор.
- Лёва Sonnet 5.5 → Тома Opus 5.5, по 6000 выходных токенов,
  штатная схема и правила разбора Секретаря.
- Тома получает исходные обезличенные данные и отдельно недоверенный вывод
  Лёвы; совпадение с автором не является доказательством.
- Проверяются полный список пунктов, индексы и цитаты из исходных реплик.
  Обрезанный JSON допускает одну дозапись только при явном `max_tokens`.
  Ошибка/unknown не повторяется автоматически.
- Это анализ расшифровки, **не прослушивание аудио моделями**.
  Факт VAD→первый звук не выдумывается: ASR-тайминги, модельный TTFT и
  акустическая задержка — разные величины.
- Используется один существующий `speed-series` ledger, без пополнения,
  обнуления и пересчёта истории. Лимит серии не менялся.
- Резерв голосовой сессии прежний ($3). Для изолированного разбора отдельно
  резервируется до $3 из **того же остатка**, затем списывается известный
  расход моделей. Неизвестный расход учитывается по полному резерву.
- Если денег на разбор нет — явный failed, ни одного модельного запроса.
- Стоимость платформы по прежним правилам стенда — оценка/верхняя граница,
  не выписка Retell. Токены моделей фиксируются отдельно.

## Как проверить владельцу
1. Открыть Dev `/admin/rehearsal`, войти своим обычным входом.
2. Выбрать поручение и стрелками версию. Прочитать ограничение снимка C.
3. Подтвердить согласие, нажать «Начать разговор», разрешить микрофон.
4. Первым сказать приветствие продавца; Катя должна представиться.
5. Завершить, дождаться статусов записи и разбора.
6. Повторить ту же сценку на другой версии; выбрать два результата для сравнения.
7. Аудио и JSON доступны в сохранённом результате.
