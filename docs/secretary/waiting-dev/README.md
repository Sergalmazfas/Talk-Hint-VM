# Правила ожидания — только Dev C

Решение владельца: сначала стенд, без включения в боевую Катю.
Боевые промпты, голос, языки, IVR, телефония, сотрудники и полномочия не изменены.
Звонки и платные запросы при подготовке пакета не запускались.

## Стенд

Открыть **/admin/secretary-lab?stand=retell-engine&speedVariant=C** на Dev-домене
проекта под владельцем. Выбрать C, дать согласие на платный стендовый разговор,
нажать существующую кнопку запуска. Сам этот пакет сессии не запускает.
Production-страница не является Dev-стендом.

Используется новый отдельно именованный Dev-агент `speed C · waiting-dev`,
который создаётся только при разрешённом владельцем старте.
Прежние Dev A/B/C-агенты и боевой агент не переписываются.
Голос, модель C, языки и приветствие остаются прежними.
Сессия C длится максимум 10 минут, чтобы пятиминутное ожидание можно было
проверить не только сразу после подключения. A/B остаются пятиминутными.
Старый общий бюджет и резерв $3 на C ($2 модель + $1 голос) не сбрасываются,
не пополняются и не увеличиваются. Unknown по-прежнему не повторяется.

## Правила

| Ситуация | Действие |
|---|---|
| Необъяснимая тишина после завершения речи Кати | В 20 с один `Hello?`, только при свежем подтверждении отсутствия звука |
| `one sec`, `give me a minute` | 60 с молчания, затем одна проверка `Still there?`, только при отсутствии звука |
| `let me check`, склад, вторая линия, `I'll be right back` | До 300 с молча, без проверок |
| Музыка / работа / разговор с коллегой | Не проверять и не перебивать; максимум 300 с |
| Явное возвращение с ответом / обращение к Кате | Дождаться завершения реплики, свежий ответ модели |
| Сомнение в адресате | Молчать |
| Максимум истёк | Одна фраза `I'll let him know and call back later`, затем `end_call` |

**Уточнение реализации стенда:** после единственной проверки при коротком
ожидании оставлено ещё 20 с на ответ. Итоговые пределы: 40 с для внезапной
тишины, 80 с для `one sec`; длинное ожидание — 300 с без добавочного окна.
Это не изменение боевой Кати.

Во время ожидания блокируются и `response_required`, и `reminder_required`,
и незавершённый ответ/таймер связки буфера C. Новые ASR-версии одной фразы
не продлевают ожидание. Новый ответ возможен только после явного возвращения
или обращения; неясная фоновая речь не передаётся модели.

## Звук и честность измерения

Custom LLM Retell передаёт текст, а не входной звук. Поэтому на браузерном
стенде локально анализируется энергия входного микрофона; сервер получает
только два boolean, не аудио и не содержимое разговора.
Для наблюдающего микрофона C отключены шумоподавление/автоусиление, чтобы
не скрывать фоновую музыку. Выход Кати не подаётся в анализатор; остаётся
включённым эхоподавление. Фактический захват Retell не перенастраивается.

Это **не** классификатор музыки, не разделение говорящих и не доказательство,
что речь адресована Кате. Любой устойчивый звук трактуется консервативно
как фон/удержание. Текстовые метки `[music]` тоже поддерживаются, но наличие
таких меток у Retell не предполагается. Устаревший/отсутствующий сигнал
не считается тишиной и не разрешает `Hello?` / `Still there?`.
Порог энергии необходимо проверить живым голосом/музыкой на устройстве:
по unit-тесту нельзя доказать чувствительность реального микрофона.

Второй локальный микрофонный поток нужен только браузерному C;
совместимость двух потоков с SDK и эхоподавления на iPhone не подтверждена.
При отказе AudioContext/микрофона платная сессия ещё не создаётся.
После остановки потоки/анализатор закрываются.

## Проверка владельцем — играть продавца

1. После вопроса Кати сказать `one sec`, молчать: до 60 с проверок нет,
   затем одна; ответить `I'm back, we have one`.
2. Сказать `let me check in the warehouse`, поговорить с «коллегой»,
   шуметь: проверок нет. Вернуться `I'm back, the price is $150`.
3. Сказать `I'm on the other line`, включить музыку: Катя ждёт молча;
   максимум 5 минут, затем одна фраза и завершение.
4. Внезапно замолчать после ответа Кати в тихом помещении:
   один `Hello?` в 20 с, без повторов.
5. Во время генерации попросить подождать: старый текст и связка не должны
   просочиться. Возвращение с исправленной суммой вызывает свежий ответ.

Сохранённый отчёт C содержит `engine.waiting`: тип/длительность,
события/число отправленных проверок и пакет разбора Лёва → Тома.
Команды TTS не называются доказанными звуковыми репликами.
Проверка перебиваний/музыки по аудио — `не проверено` до голосового испытания.
Агенты для этого не включаются.

## Команда и паспорт норм

`norms-append.json` — proposed append-only дополнение к паспорту норм:
«держать: 0 лишних проверок; 0 перебиваний во время ожидания».
`proposed-lessons.json` — уроки после ручной работы Replit.
Оба файла — **подготовлены, в production не записаны**. Старый паспорт,
книжки, обязанности, промпты Лёвы/Томы и история не заменяются.
Для принятия правила в боевой разбор требуется отдельное решение владельца;
в данном пакете применяется только стендовый пакет проверки.

## Что не проверено

- Ни одного нового звонка / платного разговора не сделано.
- Реальный Retell/TTS, громкость музыки, коллеге адресованная речь,
  два потока микрофона на iPhone — требуют разговора владельца на стенде.
- Лёва и Тома не запускались: подготовлены факты и инструкция проверки,
  не выдаётся их работа или приёмка за выполненную.
- Нет production-записей, миграций, обновления Retell-агентов, Publish.
