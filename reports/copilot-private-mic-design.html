Copilot V1: приватный RU → EN, без Brain

Вывод: существующий Realtime-переводчик умеет выдавать только текст. Недостающая часть — безопасное переключение микрофона iPhone, отдельный приватный транспорт и завершение фразы по отпусканию. Это не новая модель и не перенос Hint.

1. Где физически перекрывается голос

Один захват микрофона под управлением CallKit
                    ↓
        локальный переключатель PCM-кадров
           ┌────────┴─────────┐
NORMAL     │                  │ PRIVATE
кадры → Twilio Voice          кадры → приватный WSS → Realtime
      → Guest                 Twilio получает только тишину
                                     ↓
                              EN text → Copilot UI

Guest → Twilio playback → Owner: остаётся включённым в обоих состояниях.

Переключатель нужен перед передачей captured samples в Twilio SDK. Не после доставки на сервер, не в UI mute и не в режиме Translator. Private audio не должно попадать в обычный телефонный media stream, transcript или CRM.

Twilio документирует custom AudioDevice с собственными capture/render paths. Но сейчас приложение использует DefaultAudioDevice; готового tap/divert нет. Установка собственного audio device — до звонка/использования SDK, не при каждом нажатии. Во время звонка переключается только destination кадров внутри него.

Важное ограничение изоляции: audioDevice — общий объект SDK. Нельзя честно обещать «не затронем ни одной общей строки». Для реализации потребуется либо безопасная установка Copilot device до инициализации соответствующего SDK lifecycle, либо общий pass-through device с приватным gate, доступным только Copilot. Предпочтение — один device с pass-through для остальных режимов, но это требует явного согласования общего аудиослоя и регрессионных проверок Hint/Translator. Их prompts и телефонная семантика не меняются.

Не предлагается запускать второй независимый AVAudioEngine рядом с Twilio или переделывать телефонный bridge на удержании. При старте Copilot нужен отдельный mode flag: обычный двусторонний звонок без запуска Hint/Translator pipeline. Это отдельная ветка при создании звонка, не перестройка текущего звонка по нажатию.

Порядок нажатия

  1. Нажатие переводит gate в PREPARING_PRIVATE: реальные PCM-кадры перестают уходить в Twilio; необходимые SDK capture callbacks продолжают получать корректную тишину.
  2. Audio callback подтверждает переход с новым generation ID. До подтверждения UI не показывает «Говоришь только Copilot». Ранее отправленные normal frames нельзя отозвать; пользователь начинает приватную речь только после сигнала готовности.
  3. Приватный translator session также должен подтвердить применённую конфигурацию text-only. Одного WebSocket open недостаточно. Подключение желательно подготовить заранее в пределах активного Copilot call.
  4. Только когда обе стороны готовы, UI показывает PRIVATE; captured PCM идёт по отдельному приватному каналу. Guest audio продолжает воспроизводиться; эхо требует проверки.

Порядок отпускания

  1. На границе audio callback закрыть private capture и зафиксировать последний sequence/sample index. Уже захваченный приватный хвост отправляется только в private transport; он не теряется и не попадает в Twilio.
  2. Отделить/очистить локальные resampler и capture buffers, исключить перенос приватного хвоста в новый normal frame. Не полагаться на произвольную задержку таймером.
  3. Восстановить normal uplink для новых кадров и подтвердить NORMAL в UI. Не ждать завершения модели для восстановления разговора.
  4. Перевод оставшегося private input завершается асинхронно. Новые normal samples туда не направляются.

Ошибка перевода ≠ разрешение раскрыть речь. Пока кнопка удерживается или граница выхода не подтверждена, при ошибке остаёмся в закрытом для Guest состоянии и показываем ошибку. Нельзя неожиданно открыть линию, пока Owner продолжает говорить приватно. Телефонный звонок и приём Guest не разрываются. Release/явный безопасный выход восстанавливает линию; при непроверенном состоянии — видимый mute, а не утечка.

2. Что действительно переиспользуем

  • server/translation/openaiRealtimeTranslator.ts: текущий OpenAI Realtime transport, strict interpreter instructions, PCM append, text deltas/done, error/cancel correlation. Default модели в коде — gpt-realtime, не Terra и не отдельный text Brain. Runtime override/deploy здесь не проверены.
  • server/translation/provider.ts: PCM16/24 kHz input, fixed RU source → EN output, outputMode:"text". В существующем adapter этот режим уже исключает audio-output config и рассматривает неожиданное audio как ошибку.
  • server/translation/iosTranslator.ts: образец authenticated binary-PCM WebSocket, но не готовый endpoint V1. Нужен отдельный Copilot endpoint с text-only и press/release.
  • CallManager/CallKit — существующий звонок и lifecycle. Новая вкладка/экран отдельно, не переименование TranslatorViewController.

Не переиспользуем wholesale: twilioBridge.ts — он не пропускает оригинальный голос Owner к Guest и сохраняет переводческие turns. TranslatorPhoneFeedStream.swift — receive-only feed, без microphone uplink и нужных клиентских идентификаторов. /translator — текущий audio-producing контракт, не переключать его глобально на text.

Не добавляются GoalEngine, StrategyMemory, cards, retrieval, SAY/CHOOSE reasoning, переформулирование, TTS или автоответ Guest. Фраза «скажи ему…» в V1 не является командой: переводится сказанный текст. Owner диктует непосредственно желаемую реплику.

3. Что делать с концом фразы

Текущий Translator использует server VAD: 500 ms silence, автоматический commit/response. В интерфейсе provider нет операции «закончи именно это нажатие». Прекращение отправки audio не равно отправленной тишине; stop/cancel не следует использовать как надёжное завершение последней фразы.

Основной кандидат под запрошенный UX: сохранить native server VAD и автоматический перевод. EN text появляется по готовности сегментов ещё во время удержания, после пауз; мы не обещаем перевод до завершения произнесённой мысли. Все provider segments внутри одного hold объединяются в одну карточку в source-item порядке, а не смешиваются с другим нажатием.

Недостающий протокол — release без обрезания последнего сегмента. Кандидат для проверки: после последнего реального private PCM frame отправить в тот же private stream ограниченный хвост синтетической тишины, достаточный для настроенного VAD, затем дождаться его commit/response completion. Не добавлять параллельно manual commit/response.create: это создаёт риск двойного ответа. При пустом hold не инициировать перевод. Ограничить ожидание; при timeout показывать ошибку, не выдавать частичный результат за законченный. Не принимать следующий hold в ту же незавершённую provider operation: сначала завершить либо явно отменить её. Тишина не берётся с микрофона и никогда не направляется Guest.

Этот release-протокол ещё не проверен. Нельзя объявлять готовый безопасный V1 только по наличию text mode. Нужно доказать на isolated transport test, что tail вызывает ровно нужный VAD boundary, не порождает лишний turn и не теряет последние слова. Это остаётся условием реализации основного варианта, а не скрытым обещанием.

Документированная альтернатива: отключить auto VAD только в Copilot session; press → clear + audio, release → один input_audio_buffer.commit и один response.create с text-only. Это тот же перевод, не второй Brain. Но текст начинает приходить после отпускания. Такой UX отличается от запрошенного; не выбираем его молча, требуется отдельное согласование.

При manual mode общий adapter нельзя переключить одной настройкой: его duration guard считает данные через VAD events и потребует отдельного учёта samples. При любом варианте существующий 700-ms noise gate нельзя бездумно переносить: короткий ответ может исчезнуть. Нужны проверки короткой речи, пустого hold, repeated release, нескольких пауз внутри hold и быстрых повторных нажатий. Изменения делаются с неизменным default для старого Translator.

Сессия — максимум на активный Copilot call, без общего контекста с Hint/V2. Одна текущая операция и ограниченный буфер; при новой фразе старый UI output не подменяет её. Приватные provider conversation items очищаются по завершении операции, либо сессия пересоздаётся, если cleanup не подтверждён. Поведение cleanup и повторного использования требует контрактной проверки; обещание zero retention у провайдера этим не даётся.

4. Минимальный приватный контракт

Authenticated /copilot-private (предлагаемый новый endpoint)
bind: user owner + active callId + connection epoch
press: utteranceId + generation
audio: sequence-numbered PCM frames, только PRIVATE
release: utteranceId + lastSequence (один раз)
result: text_delta / text_done / error
        callId + epoch + utteranceId + responseId

Server проверяет ownership, актуальный call, размеры и последовательность кадров; duplicate release не вызывает второй перевод. В UI результат связан с конкретным hold. Stop/cancel/disconnect освобождают ресурсы, поздние responses закрытого hold игнорируются. Voice normal restore не зависит от server ACK перевода.

Текст показывается крупно, новая private phrase заменяет предыдущую. Нельзя считать display, release, ACK или произнесённую приватно фразу частью телефонного разговора.

Приватные raw audio/transcripts — только необходимые оперативные buffers. Не сохранять в БД, recordings, call metadata, CRM, analytics, long-term memory или debug logs. Ошибки логировать без content. Закрытие/замена очищает локальное состояние; buffers ограничены, фон/разрыв/смена call отменяет операцию. Перед любым расширением хранения — отдельное разрешение. Аудио передаётся внешнему Realtime provider; его политика обработки/retention требует отдельной проверки, это не локальная офлайн-функция.

5. V2 — только направление, не реализация

OWNER_SPOKEN ─┐
GUEST_SPOKEN ─┼→ один role-aware Brain → SAY / CHOOSE / NO_ACTION
OWNER_PRIVATE┘
V1 private translation остаётся независимым быстрым путём.

Heard/Private/Suggested/Spoken различаются. Новая реплика Guest сама по себе не отменяет private intent Owner и не стирает V1 перевод. Защита от старого asynchronous response — техническая, а не разрешение AI менять решение Owner. Во V2 передача private context в Brain будет отдельной возможностью; в V1 Brain не подключается.

6. Что подтверждено и что пока нет

По исходникам: CallManager использует DefaultAudioDevice; mute устанавливает Twilio call.isMuted; Translator text mode реализован; готовых private gate/PTT endpoints нет. ios/project.yml задаёт Twilio from:6.11.0 — это нижняя граница зависимости, не доказательство точной установленной версии.

По официальной документации: custom AudioDevice поддерживается; нельзя менять его при активном звонке. OpenAI описывает manual PTT commit/create. Это доказывает наличие механизмов, но не работу нашей будущей реализации.

Перед признанием V1 готовым: проверка реальных SDK headers/build; audio-buffer boundary tests; устройство iPhone с receiver/speaker/Bluetooth; быстрый press/release, cancel gesture, lock/background, interruptions, CallKit mute, смена route и сетевой обрыв. На стороне Guest проверить отсутствие private speech в полученном аудио. Любые звонки/записи для проверки — только после отдельного разрешения; Simulator и UI-флаг не доказательство отсутствия утечки.

Нужны регрессионные тесты обычного Hint и Translator, поскольку custom device — общая инфраструктура. Метрики: press→private-ready, release→first text→final text, release→normal audio. Числа из прежнего mic-spike не являются SLA этой функции.
