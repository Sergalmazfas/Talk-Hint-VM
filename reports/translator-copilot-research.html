Translator → отдельный Copilot V1

Фактический live phone Translator, причины его скорости и минимальная архитектура Copilot. Без изменений Hint/Translator, звонков, моделей, production или данных.

Executive summary

  • Факт Phone Translator изолирован от Hint/Deepgram; Owner и Guest имеют независимые Realtime sessions.
  • Ограничение ~0,3 с — не SLA: есть только dev-mic first-audio data, без phone/iOS/render ACK/head-to-head.
  • Рекомендация V1 = role-labeled STT ears → один text Brain → strict SAY/CHOOSE/NO_ACTION; новый pipeline, не migration Hint.
  • Копировать Translator нельзя: две sessions не имеют общего context; audio merge теряет roles. Copilot требует role-aware state, private input и stale control.
  • Нет TTS/private mic/Secretary; conventional bidirectional voice переживает assistant outage.

Решение для отдельного согласования

Рекомендуемый baseline B: исходящий англоязычный звонок, media copy → два role-labeled Flux EN ears → один per-call gpt-5.6-terra Brain → complete validated action → отдельный iOS Copilot UI.

Альтернатива A: direct role-preserving audio→text Realtime Brain. Оставить кандидатом, пока не доказаны двухсторонняя маркировка ролей, private-input protocol, strict schema и cancel semantics.

Статус: это рекомендация архитектуры, а не разрешение реализации. Все Copilot contracts/gates ниже — proposed.

Audio, STT, model, trigger

  • Audio: Twilio μ-law mono 8 kHz → PCM16 mono 24 kHz; output обратно в μ-law один раз. twilioBridge.ts:141–154,263–275

Source transcript приходит асинхронно, иногда после перевода; interim source captions этот adapter не выдаёт. История сохраняется в provider session каждой роли: приложение не задаёт «последние N turns», не отправляет общий диалог и не управляет здесь truncation. Earlier turns по prompt разрешены только для disambiguation. openaiRealtimeTranslator.ts:65–67,155–197,309–313,474–549; twilioBridge.ts:297–315

Guards, queue, fan-out

  • Committed ids — FIFO; нарушения: response без source, multiple responses, output-after-done. openaiRealtimeTranslator.ts:414–471,551–650
  • Captured audio <700 ms и empty transcript отменяются; late output suppressed-response отбрасывается. Длительность вычисляется по байтам с VAD prefix, это не точная длительность произнесённого слова. Empty-transcript gate срабатывает только пока соответствующий response ещё активен; уже выданный результат он не отзывает. Короткий текст отдельно не фильтруется. openaiRealtimeTranslator.ts:23–29,343–379,395–425,474–520
  • Playback marks блокируют Owner re-entry; Guest original имеет ~300-ms pre-roll. twilioBridge.ts:276–295,369–388
  • Guest original→Owner; Owner original→никто; Owner translation→Guest+Owner; Guest translation→Owner. Один output fan-out. :35–45,254–275
  • Single finalization: cancel/close/hangup/persist. :165–206,394–400

Последовательно: Owner provider connect → создание Guest leg → Guest provider connect. Затем две sessions работают независимо; внутри каждой аудио/перевод и input transcription не образуют последовательную HTTP-цепочку. Persistence вызывается без ожидания на пути выдачи. FIFO — атрибуция committed items, не очередь отдельного Brain. Здесь нет Hint cooldown/debounce/semantic dedup; вместо них lifecycle/suppression/playback guards. Не все provider errors завершают звонок: bridge завершает его при fatal error или invariant violation, nonfatal errors отправляет в feed. Неожиданное Guest audio в text mode — fatal. twilioBridge.ts:165–174,251–352; openaiRealtimeTranslator.ts:652–661

Voice/text config: Owner всегда получает audio-output session; Guest при preference=text — настоящий text-output без синтеза, иначе audio. Default female: Owner marin, Guest cedar; male меняет их местами. Настройки фиксируются на звонок. twilioBridge.ts:23–34,104–113,235–243

2. Why it is fast

Ключевые числа: 1 persistent WS на leg; 0 Goal/retrieval/classifier model calls; 500 ms configured VAD silence (не total latency).

  1. Узкая задача: prompt разрешает только один точный перевод и запрещает участие/советы/fillers.
  2. Native streaming: persistent audio session без отдельной цепочки STT-final → HTTP model → TTS.
  3. Нет orchestration: GoalEngine, strategy, profile/cards, retrieval и application prompt history отсутствуют.
  4. First delta сразу: playback может начаться до response.done.
  5. Одна synthesis: один output конвертируется и fan-out.
  6. Детерминированные guards: FIFO/suppression не делают AI calls.

3. Proposed Copilot V1

Отдельный tab/mode и новый contract. Copilot слушает обычный разговор, но Owner сам произносит suggested SAY; Guest никогда не слышит private selection.

Architecture choice

A — direct audio→text Realtime Brain: потенциально ниже latency, но нужен доказанный role-preserving multiplex, private channel, strict schema и cancel; смешивать audio нельзя. кандидат

B — role STT→text Brain: явные roles/private input и контролируемые revisions/schema; потенциально медленнее из-за STT-final и complete validation. V1 baseline

Baseline B

Normal bidirectional call → separate media copy → 2 Flux EN role ears → shared state → 1 Brain → Owner-only action UI. Assistant outage не рвёт voice.

  • Scope: минимально только outgoing English conversation. Existing Flux EN обосновывает только EN; inbound/RU требуют отдельного scope.
  • Brain: independently configured per call gpt-5.6-terra, profile reasoning_effort=none. Это grounded-behavior baseline, не измеренное утверждение о скорости; не использовать global Hint setting.
  • No silent fallback: timeout/error/invalid JSON → explicit error status, не mini и не semantic NO_ACTION.
  • Triggers: Guest final и private Owner tap/type вызывают ровно один Brain. Owner final обновляет context, но по умолчанию не вызывает второй hint.
  • No extra AI: нет goal classifier, summarizer, retrieval, translation, sentiment или strategy model calls.

Reuse boundary

  • Reuse patterns: Twilio/CallManager/auth/role mapping, existing STT transports как ears, authenticated owner feed.
  • Не копировать: twilioBridge pairing/playback/asymmetry, Translator prompt/cards.
  • New boundary: CopilotBrainProvider, не force-fit interpreter RealtimeTranslationProvider.
  • Не переносить Hint: GoalEngine, Strategy, wait/library/cards. My Context — только optional relevant confirmed profile; profile ≠ disclosure permission.

Selected ≠ Suggested ≠ Spoken

  • Selected: private tap/type; не transcript/CRM/spoken.
  • Suggested: Brain SAY; accepted/rendered всё ещё совет.
  • Spoken: только фактический Owner STT final.

Tap/type всегда запускает один Brain на свежем state. В V1 нет prefabricated local SAY shortcut.

Иллюстрации, не результаты модели: Guest: “Tuesday or Thursday?” → CHOOSE Tuesday / Thursday / Neither–Other → private Tuesday → SAY “Tuesday works for me. What times are available?”; Guest: “9 AM or 2:30 PM?” → private 2:30 → SAY “2:30 works for me.” При уже установленном намерении записаться допустимо “Let's book it.” Other/type “after 3 PM” → SAY “Do you have anything after 3 PM?” Известный и уместный подтверждённый ответ сразу даёт SAY; пауза без полезного действия — NO_ACTION, UI остаётся в listening без старой карточки.

Minimal context

  1. Optional initial Reason: контекст звонка, не script; incoming может не иметь reason.
  2. Role-labeled live finals обеих сторон; fresh speech выше old profile.
  3. Confirmed private selections, явно private/not_spoken, пока релевантны.
  4. Optional bounded relevant Owner Profile facts.

Retain reason + selections + explicit constraints/relevant confirmed facts + последние, например, 12 turns. При cap ставить olderContextUnavailable=true; явные constraints нельзя терять молча. No auto-summary.

Источник профиля можно переиспользовать без новой таблицы: users.userContext, authenticated GET/POST /api/user/context; загрузка один раз в call snapshot. Новый редактор/импорт резюме не является условием V1. CONTACT_CONTEXT, TUTOR_MEMORY и B2B cards автоматически не подключать к новому режиму; существующий Hint продолжает использовать их как раньше. При ограничении контекста неизвестное остаётся неизвестным — не восстанавливать факты догадкой. shared/schema.ts:12; server/routes.ts:2089–2113; server/storage.ts:510–518; server/contactMemory.ts:115–124

Consent boundary. Tuesday означает предпочтение Tuesday, но не согласие book appointment. 2:30 также не authorizes binding booking, если исходный intent этого не установил. Other: after 3 PM — private preference, не spoken fact.

Proposed server contracts

Новый Copilot namespace. Server authoritative ownership берётся из session auth. После auth каждый event связан с callId, epoch, revisions и ids.

client → server
{"type":"session","callId":"…","epoch":3,"requestId":"…"}
{"type":"subscribe","callId":"…","epoch":3,"requestId":"…"}

server → client
{"type":"snapshot","callId":"…","epoch":3,"audioRevision":18,
 "conversationRevision":12,"currentAction":{…},"status":"listening"}

session attaches only owner-scoped call state. subscribe returns snapshot then live events. New processing lifetime uses new epoch; old epoch is rejected.

Mutually exclusive strict schema: SAY — bounded say; CHOOSE — bounded question + 2–4 stable options; NO_ACTION — kind + optional machine reason enum. Prose, unknown fields, bad bounds/semantics → error. NO_ACTION — valid Brain decision, не timeout/error.

Общий пример выше — схема вариантов, не валидный экземпляр всех типов сразу. Предлагаемые начальные пределы: SAY до 25 слов/300 символов, question до 200, label до 80, typed input до 500 Unicode code points; TTL карточки 30 секунд. Это настройки на согласование, не измеренные оптимумы. Envelope каждого server event также несёт callId/epoch; в сокращённых примерах ниже они опущены. Generation token включает audioRevision, conversationRevision и selectedRevision; action revision — отдельный монотонный номер карточки.

New provider boundary

interface CopilotBrainProvider {
  generateAction(input: {
    callId: string; epoch: number; requestId: string;
    conversationRevision: number; reason?: string;
    ownerProfile?: BoundedFact[]; explicitConstraints: BoundedFact[];
    selections: PrivateSelection[]; turns: RoleLabeledTurn[];

Publish только complete validated action, не partial JSON/text delta.

Stale, races, reconnect

  1. На Guest speech start или actual Owner speech start немедленно increment audioRevision, invalidate current action, cancel/drop in-flight generation — не ждать final.
  2. STT final добавляет role-labeled turn и increment conversationRevision.
  3. Response принимается только при совпадении user/call/epoch/request/base revisions.
  4. Late role/order/STT correction increment revision и может invalidate/regenerate latest trigger.
  5. Не более one current generation + one latest pending. New pending replaces old; no unbounded queue.

iOS V1

iOS: отдельный tab/mode/screen; reuse CallManager call controls; новый authenticated feed; одна SAY/CHOOSE card (Other→bounded type), keyed actionId+revision; invalidate removes, reconnect replaces state by snapshot. Не settings «hide transcript».

Телефония V1: conventional Twilio bridge между Owner и Guest передаёт оригинальную речь в обе стороны; копия обоих tracks идёт в новый authenticated/bound /copilot-stream, не в Hint handler. Новый /copilot-feed принимает только private control и отдаёт карточки. Mapping caller-leg/owner-leg брать из проверенного role helper, а не угадывать по inbound/outbound. Подсистема Brain не владеет завершением телефонного звонка: отказ assistant выключает карточки, но не voice. Это новый routing branch, а не изменение текущего Translator bridge.

Future latency telemetry

Stages: speech start/invalidate → speech end → STT EOT/final → Brain queued/start → complete JSON validated → WS sent/received → render ACK.

Owner-input path отдельно: tap accepted → Brain start → complete → send → render ACK. Нужны request/action/revision ids, invalidation/drop/error. Не смешивать с Hint latency. Никаких latency promises до измерения.

Common strict rules — обе роли
Strict rules:
1. Output ONLY the translation of what was just said. Nothing else.
2. NEVER answer questions, give advice, add opinions, or continue the conversation yourself. If the speaker asks "what time is it?", you translate the question — you do not answer it.
3. NEVER add filler words or acknowledgements (no "yeah", "okay", "mm-hmm", "sure", "got it") that the speaker did not say.
4. NEVER explain, comment, apologize, or mention that you are translating.
5. Preserve meaning exactly. Do not soften, embellish, summarize, or "improve" facts.
6. Numbers, dates, times, prices, addresses, phone numbers and proper names must be carried over EXACTLY. Spell out phone numbers digit by digit in the target language.
7. Keep the speaker's tone and register (formal/informal).
8. If the speaker corrects themselves mid-sentence, translate only the corrected final meaning.
9. If the audio is unintelligible or silent, say NOTHING. Never invent content.
10. Keep translations as short as the original — do not pad.
11. Produce EXACTLY ONE rendition per speaker utterance, then STOP and stay silent until the speaker talks again. Never add a second sentence that was not spoken. Never respond to, acknowledge, or react to your own previous translation.
12. You are NEVER a participant in the conversation. You never accept or decline invitations, never congratulate, never thank, never agree or disagree, never express emotion, and never speak on anyone's behalf. If the speaker says "come with us tonight", you translate the invitation — you NEVER say anything like "Sure" or "I'm coming".
13. Earlier turns may be used ONLY to disambiguate pronouns, names, terms, or an unfinished thought. NEVER carry facts, intentions, or replies from earlier turns into the current translation. Each translation must contain only what was said in the current utterance.
